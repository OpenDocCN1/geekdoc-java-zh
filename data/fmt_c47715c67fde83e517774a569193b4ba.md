### 9.4.4 使用保护实例变量的 CommissionEmployee-BasePlusCommissionEmployee 继承

为了使 `BasePlusCommissionEmployee` 类能够直接访问实例变量 `firstName`、`lastName`、`securityNumber`、`grossSales` 和 `commissionRate`，我们在父类将它们声明为 `protected`。正如我们在 9.3 节中所讨论的，父类的保护成员被该类的所有子类访问。在新的 `CommissionEmployee` 类中，我们仅修改了图 9.4 的第 6–10 行，使用 `protected` 访问修饰符声明变量如下：

```java
protected final String firstName;
protected final String lastName;
protected final String securityNumber;
protected double grossSales; // weekly sales
protected double commissionRate; // commission percentage
```

声明的其余部分（此处未显示）与图 9.4 相同。我们可以将 `CommissionEmployee` 的实例变量声明为 `public`，以便子类 `BasePlusCommissionEmployee` 访问它们。然而，将实例变量声明为公共是糟糕的软件工程，因为它允许任何类对变量进行无限制访问，增加了错误的概率。使用保护实例变量，子类可以访问这些实例变量，但不是子类且不在同一包中的类无法直接访问这些变量——记住，保护成员对同一包中的其他类也是可见的。

## 父类与子类之间的关系

### 子类对象包含其所有父类的实例变量

当你创建一个 `BasePlusCommissionEmployee` 时，它包含了在类层次中声明的所有实例变量——即来自 `Object`（它没有实例变量）、`CommissionEmployee` 和 `BasePlusCommissionEmployee`。`BasePlusCommissionEmployee` 不继承 `CommissionEmployee` 的五参数构造函数，而是显式地调用了它（第 14–15 行），以初始化 `BasePlusCommissionEmployee` 从 `CommissionEmployee` 继承的实例变量。同样，`CommissionEmployee` 的构造函数必须显式调用 `Object` 的构造函数。`BasePlusCommissionEmployee` 的构造函数必须显式调用 `CommissionEmployee` 的构造函数，因为 `CommissionEmployee` 没有可以调用的无参数构造函数。

## 使用保护变量的注意事项

使用保护变量会带来几个问题。首先，子类可以为变量分配无效值。其次，如果我们决定更改实例变量的名称，我们可能需要修改所有的子类。第三个问题是，类的保护成员对该类所在包中的所有类都可见——这并不总是所想要的。

> 软件工程观察 9.7：当父类应该仅向其子类和同一包中的其他类提供方法，而不向其他类提供时，使用 `protected` 访问修饰符。

> 软件工程观察 9.8：声明实例变量为 `private`（而不是 `protected`）允许父类对这些变量的实现发生变化。

> 错误预防技巧 9.2：可能的情况下，不要在父类中包含实例变量。相反，应包含访问实例变量的非私有方法。这将有助于类的对象维持状态。
