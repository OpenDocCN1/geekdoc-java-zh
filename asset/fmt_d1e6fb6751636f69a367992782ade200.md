## 目标

在本附录中你将学习：
- 设置断点以调试应用程序。
- 使用 `run` 命令通过调试器运行应用程序。
- 使用 `stop` 命令设置断点。
- 使用 `cont` 命令继续执行。
- 使用 `print` 命令评估表达式。
- 使用 `set` 命令在执行期间更改变量值。
- 使用 `step` 和 `next` 命令控制执行。
- 使用 `watch` 命令查看字段在执行期间如何被修改。
- 使用 `clear` 命令列出或移除断点。

在第 2 章中，你学习了有两种类型的错误——语法错误和逻辑错误，并学习了如何从代码中消除语法错误。逻辑错误不会阻止应用程序成功编译，但它们会导致应用程序在运行时产生错误结果。JDK 包含一个调试器，用于监控应用程序的执行，以便你可以定位并移除逻辑错误。调试器将是你最重要的应用程序开发工具之一。许多 IDE 提供与 JDK 包含的调试器类似的调试器，或为 JDK 调试器提供图形界面。

本附录使用不接收用户输入的命令行应用程序演示 JDK 调试器的关键功能。这里讨论的相同调试器也可以用于调试接收输入的应用程序，但调试此类应用程序需要稍微多的设置。为了专注于调试器功能，我们选择使用不涉及用户输入的简单命令行应用程序来演示调试器。有关 Java 调试器的更多信息，请访问 http://docs.oracle.com/javase/7/docs/tools/windows/jdb.html。

## E.2 断点以及 `run`、`stop`、`cont` 和 `print` 命令

编译 `AccountTest.java` 和 `Account.java`。命令 `javac -g *.java` 会编译当前工作目录下所有的 `.java` 文件以供调试。

1.  **启动调试器**。在命令提示符中，输入 `jdb`（图 E.2）。此命令将启动 Java 调试器并允许你使用它的功能。[注：为了可读性，我们更改了命令提示符窗口的颜色。]

```
C:\examples\debugger>javac -g AccountTest.java Account.java

C:\examples\debugger>jdb

Initializing jdb ...
```

**图 E.2** | 启动 Java 调试器。

2.  **在调试器中运行应用程序**。通过输入 `run AccountTest`（图 E.3）通过调试器运行 `AccountTest` 应用程序。如果你在调试器中运行应用程序之前没有设置断点，应用程序的运行方式将与使用 `java` 命令一样。

```
C:\examples\debugger>jdb

Initializing jdb ...

> run AccountTest

run AccountTest

Set uncaught java.lang.Throwable

Set deferred java.lang.Throwable

>
VM Started: initial account balance: $50.00
```

**图 E.3** | 通过调试器运行 `AccountTest` 应用程序。

3.  **重启调试器**。为了正确使用调试器，你必须在运行应用程序之前设置至少一个断点。通过输入 `jdb` 重启调试器。

4.  **在 Java 中插入断点**。你可以在应用程序的特定代码行设置断点。这些步骤中使用的行号来自图 E.1 中的源代码。通过输入 `stop at AccountTest:12`（图 E.4）在源代码的第 12 行设置断点。`stop at` 命令在该命令后的行号处插入断点。你可以根据需要设置任意数量的断点。通过输入 `stop at AccountTest:19`（图 E.4）在第 19 行设置另一个断点。当应用程序运行时，它会在任何包含断点的行处暂停执行。当调试器暂停应用程序的执行时，该应用程序处于断点模式。在调试过程开始后也可以设置断点。调试器命令 `stop in` 后跟类名、点和方法名（例如 `stop in Account.credit`），会指示调试器在指定方法的第一个可执行语句处设置断点。当程序控制进入该方法时，调试器将执行。

```
C:\examples\debugger>jdb

Initializing jdb .

> stop at AccountTest:12

Deferring breakpoint AccountTest:12.
It will be set after the class is loaded.

> stop at AccountTest:19

Deferring breakpoint AccountTest:19.
It will be set after the class is loaded.

>
```

**图 E.4** | 在第 12 行和第 19 行设置断点。

5.  **运行应用程序并开始调试过程**。输入 `run AccountTest` 执行应用程序并开始调试过程（图 E.5）。调试器打印文本表示在第 12 行和第 19 行设置了断点。它将每个断点称为“延迟断点”，因为每个断点都是在调试器运行应用程序之前设置的。当执行到达第 12 行的断点时，应用程序暂停。此时，调试器通知你已到达断点，并显示第 12 行的源代码。该行代码是即将执行的下一条语句。

```
It will be set after the class is loaded.

run AccountTest

run AccountTest

Set uncaught java.lang.Throwable

Set deferred uncaught java.lang.Throwable

>

VM Started: Set deferred breakpoint AccountTest:19

Set deferred breakpoint AccountTest:12

Breakpoint hit: "thread-main", AccountTest.main(), line=12 bci=13

12: System.out.printf("initial account balance: $%.2f%n",
main[1]
```

**图 E.5** | 重启 `AccountTest` 应用程序。

6.  **使用 `cont` 命令恢复执行**。输入 `cont`。该命令导致应用程序继续运行，直到遇到下一个断点（第 19 行），此时调试器会通知你（图 E.6）。`AccountTest` 的正常输出出现在来自调试器的消息之间。

```
main[1] cont

> initial account balance: $50.00

adding 25.00 to account balance

Breakpoint hit: "thread-main", AccountTest.main(), line=19 bci=60

19: account.deposit(depositAmount); // add to account balance

main[1]
```

**图 E.6** | 执行到达第二个断点。

7.  **检查变量的值**。输入 `print depositAmount` 显示存储在 `depositAmount` 变量中的当前值（图 E.7）。`print` 命令允许你查看计算机内部某个变量的值。此命令将帮助你发现并消除代码中的逻辑错误。显示的值为 25.0——这是图 E.1 中第 15 行赋值给 `depositAmount` 的值。

```
main[1] print depositAmount

depositAmount = 25.0

main[1]
```

**图 E.7** | 检查变量 `depositAmount` 的值。

8.  **继续执行应用程序**。输入 `cont` 继续运行。由于没有更多断点，应用程序将继续并最终终止（图 E.8）。

```
main[1] cont

> new account balance: $75.00

The application exited
```

**图 E.8** | 继续执行应用程序。

## E.3 `print` 和 `set` 命令

在上一节中，你学习了如何使用调试器的 `print` 命令来检查变量的值。在本节中，你将学习如何使用 `print` 命令来检查复杂的表达式。你还将学习 `set` 命令，它允许程序员为变量分配新值。对于本节，我们假设你已经按照 E.2 节中的步骤打开了命令提示符、切换到目录 (`C:\examples\debugger`) 并编译了 `AccountTest` 应用程序（以及 `Account`）。

1.  启动调试器并设置断点（参考 E.2 节步骤 1-4）。
2.  运行应用程序至第一个断点。
3.  **检查表达式的值**。输入 `print depositAmount - 2.0` 检查算术表达式的值（图 E.10）。输入 `print depositAmount == 23.0` 检查布尔表达式的值。

```
main[1] print depositAmount - 2.0

depositAmount - 2.0 = 23.0

main[1] print depositAmount == 23.0

depositAmount == 23.0 = false

main[1]
```

**图 E.10** | 检查算术表达式和布尔表达式的值。

4.  **修改值**。调试器允许您在应用程序执行期间更改变量的值。这对于尝试不同的值以及定位应用程序中的逻辑错误非常有价值。您可以使用调试器的 `set` 命令来更改变量的值。输入 `set depositAmount = 75.0`。调试器会更改 `depositAmount` 的值并显示其新值（图 E.11）。

```
main[1] set depositAmount = 75.0

depositAmount = 75.0 = 75.0

main[1]
```

**图 E.11** | 修改值。

5.  **查看应用程序结果**。输入 `cont` 继续应用程序的执行。`AccountTest`（图 E.1）的第 19 行执行，将 `depositAmount` 传递给 `Account` 方法 `deposit`。该方法随后显示新余额。结果为 $125.00（图 E.12）。这表明上一步将 `depositAmount` 的值从其初始值（25.0）更改为 75.0。

```
main[1] cont

> new account balance: $125.00

The application exited

C:\examples\debugger>
```

**图 E.12** | 查看修改变量值后的应用程序结果。
