
# 第 6 章 方法：深层观察

```java
// 玩一场骰子游戏
public static void main(String[] args) {
    int myPoint = 0; // 如果第一次投掷没有胜负，则点数(point)
    Status gameStatus; // 可以包含 CONTINUE, WON 或 LOST
    int sumOfDice = rollDice(); // 第一次投掷

    // 根据第一次投掷确定游戏状态和点数
    switch (sumOfDice) {
        case SEVEN: // 第一次投掷 7 则胜
        case YO_LEVEN: // 第一次投掷 11 则胜
            gameStatus = Status.WON;
            break;
        case SNAKE_EYES: // 第一次投掷 2 则输
        case TREY: // 第一次投掷 3 则输
        case BOX_CARS: // 第一次投掷 12 则输
            gameStatus = Status.LOST;
            break;
        default: // 没胜也没输，所以记住点
            gameStatus = Status.CONTINUE; // 游戏未结束
            myPoint = sumOfDice; // 记住点
            System.out.printf("Point is %d\n", myPoint);
            break;
    }

    // while 循环未完成
    while (gameStatus == Status.CONTINUE) { // 未胜或输
        sumOfDice = rollDice(); // 再次投掷骰子
        // 确定游戏状态
        if (sumOfDice == myPoint) // 通过掷出点数胜
            gameStatus = Status.WON;
        else {
            if (sumOfDice == SEVEN) // 在点点数前掷出 7 则输
                gameStatus = Status.LOST;
        }
    }

    // 显示胜或负信息
    if (gameStatus == Status.WON)
        System.out.println("Player wins");
    else
        System.out.println("Player loses");
}

// 投掷骰子，计算和并显示结果
public static int rollDice() {
    // 骰子值
    int die1 = 1 + randomNumbers.nextInt(6); // 第一次投掷
    int die2 = 1 + randomNumbers.nextInt(6); // 第二次投掷
    int sum = die1 + die2; // 骰子值之和
    // 显示本次投掷的结果
    System.out.printf("Player rolled %d + %d = %d%n", die1, die2, sum);
    return sum;
}
```

## 方法 rollDice

在游戏规则中，玩家在第一次以及所有后续投掷中必须投掷两个骰子。我们声明方法 `rollDice`（第 68–81 行）来投掷骰子并计算及打印它们的和。`rollDice` 方法声明了一次，但在 `main()` 中的两个地方（第 26 行和 50 行）被调用，`main()` 包含了一个完整游戏的逻辑。`rollDice` 方法没有参数，它有一个空的参数列表。每当调用它时，`rollDice` 都会返回骰子的和，返回类型 `int` 在方法头（第 68 行）中指定。尽管第 71 行和 72 行看起来相同（除骰子名称外），但它们并不一定产生相同的结果。这些语句都会产生一个 1–6 范围内的随机值。变量 `randomNumbers`（在第 71–72 行中使用）没有在方法中声明。相反，它被声明为类的 `static final` 变量并在第 8 行中初始化。这使得我们能够创建一个 `SecureRandom` 对象，并在每次调用 `rollDice` 时重用它；它们共享这个 `SecureRandom` 对象。

## main 的局部变量

游戏逻辑相当复杂。玩家可能在第一次投掷时胜或输，也可能在任何后续投掷中输。`main` 方法（第 21–65 行）使用局部变量 `myPoint`（第 23 行）在玩家第一次投掷未胜未输时存储“点数”，使用局部变量 `gameStatus`（第 24 行）来跟踪整个游戏状态，以及使用局部变量 `sumOfDice`（第 25 行）。

## 为什么某些常量没有定义为 enum

你可能会奇怪为什么我们将骰子之和声明为 `static final int` 而不是 `enum` 常量。原因是程序必须将 `int` 变量 `sumOfDice`（第 26 行）与这些常量比较，以确定每次投掷的结果。假设我们声明 `enum Sum` 包含游戏中使用的五个和（例如 `Sum.SNAKE_EYES`），并在 `switch` 语句（第 29–45 行）中表示它们。这将阻止 `switch` 语句的控制表达式，因为 Java 不允许 `int` 成为枚举常量。为了实现与当前程序相同的功能，我们必须使用 `Sum` 类型的变量 `currentType` 作为 `switch` 的控制表达式。Java 未提供将 `int` 值转换为特定 `enum` 常量的简单方法。这将通过单独的 `switch` 语句来实现。

## 6.11 声明的作用域

你见过各种 Java 实体的声明，例如类、方法、变量和参数。声明引入了供 Java 实体引用的名称。声明的作用域是可以通过该名称引用该实体的程序部分。该实体在该部分程序中被称为“在作用域内”。本节引入了重要的作用域问题。

### 基本的作用域规则

基本的作用域规则如下：

1. 参数声明的作用域是出现该声明的方法体。
2. 局部变量声明的作用域是从声明出现的位置到该代码块的结束。
3. 出现在 `for` 语句头部初始化部分中的局部变量声明，其作用域是 `for` 语句体以及该头部中的其他表达式。
4. 方法或字段的作用域是整个类的体。这使得类的实例可以使用该类的字段和其他方法。

任何代码块都可以包含变量声明。如果方法中的局部变量或参数与类的字段同名，则该字段会被隐藏，直到该代码块执行结束——访问代码块中被遮蔽的变量的方法如下：

- 如果该字段是实例变量，在它的名称前加上 `this` 关键字和一个点（`.`），例如 `this.x`。
- 如果该字段是静态类变量，在它的名称前加上类名和一个点（`.`），例如 `ClassName.x`。

图 6.9 展示了字段和局部变量的作用域问题。第 7 行声明并初始化字段 `x` 为 1。在任何声明了局部变量 `x` 的代码块（或方法）中，该字段都会被遮蔽。`main` 调用两次方法（第 11–23 行），声明了一个局部变量 `x`（第 13 行）并将其初始化为 5。输出该局部变量的值是为了显示 `main` 中的字段（其值为 5）被遮蔽了。程序执行其他方法——`useLocalVariable`（第 26–35 行）和 `useField`（第 38–44 行），它们不接受参数也没有返回值。`main` 调用两次方法（第 20 行）。方法 `useLocalVariable` 声明了局部 `x`（第 28 行）。当第一次调用 `useLocalVariable` 时（第 17 行），它创建了 `x` 并将其初始化为 25（第 28 行），输出 `x` 的值（第 30–31 行），递增 `x`（第 32 行）并再次输出 `x` 的值（第 33–34 行）。当第二次调用 `useLocalVariable` 时（第 19 行），它重新创建了局部变量 `x` 并将其重新初始化为 5，每次调用 `useLocalVariable` 的输出都是相同的。

```java
// Fig. 6.9: Scope.java
// Scope 展示了字段和局部变量的范围。
public class Scope {
    // 类所有方法都可以访问的字段
    private static int x = 1;

    // main 方法创建并初始化局部变量 x
    // 并调用方法 useLocalVariable 和 useField
    public static void main(String[] args) {
        int x = 5; // main 的局部变量 x 遮蔽了字段
        System.out.printf("local x in main is %d%n", x);
        useLocalVariable(); // useLocalVariable 有局部 x
        useField(); // useField 使用 Scope 类的字段 x
        useLocalVariable(); // useLocalVariable 重新初始化局部 x
        useField(); // Scope 类的字段 x 保留其值
        System.out.printf("local x in main is %d%n", x);
    }

    // 在每次调用期间创建并初始化局部变量 x
    public static void useLocalVariable() {
        int x = 25; // 每次调用 useLocalVariable 时初始化
        System.out.printf("%nlocal x on entering method useLocalVariable is %d%n", x);
        x++; // 修改此方法的局部变量 x
        System.out.printf("local x before exiting method useLocalVariable is %d%n", x);
    }

    // 在每次调用期间修改 Scope 类的字段
    public static void useField() {
        System.out.printf("%nfield on entering method useField is %d%n", x);
        x = 10; // 修改 Scope 类的字段 x
        System.out.printf("field before exiting method useField is %d%n", x);
    }
}
```

```
local x on entering method useLocalVariable is 25
local x before exiting method useLocalVariable is 26
field on entering method useField is 1
field before exiting method useField is 10
local x on entering method useLocalVariable is 25
local x before exiting method useLocalVariable is 26
field on entering method useField is 10
field before exiting method useField is 100
local x in main is 5
```

图 6.9 Scope 类展示了字段和局部变量的范围。（2 部分中的第 2 部分）

`useField` 没有声明任何局部变量。当它引用 `x` 时，使用的是类的字段（第 7 行）。当第一次调用 `useField` 时（第 18 行），它输出字段（第 40–41 行）的值（1），将字段乘以 10（第 42 行），并在返回之前再次输出字段 `x` 的值（10）（第 43–44 行）。下次调用方法 `useField` 时（第 20 行），该字段已经有了被修改后的值（10），方法输出 10，然后是 100。最后，程序在 `main` 中输出局部变量 `x` 的值（第 25 行）。

## 重载方法

方法重载允许多个方法具有相同的名称但不同的参数列表。这在你想要对不同类型的数据执行相同操作时非常有用。例如，你可能有一个针对整数的 `add` 方法和另一个针对双精度浮点数的方法。编译器根据所提供的参数决定调用哪个方法。

**方法的签名由其名称和参数列表组成。返回类型不是签名的一部分。这意味着你不能仅通过更改返回类型来重载方法。**

例如，在图 6.10 所示，编译器可能会（在内部）使用逻辑名称 "square of int" 来指定带有 `int` 参数的 `square` 方法，并使用 "square of double" 来指定带有 `double` 参数的 `square` 方法（这些是编译器向用户暴露的实际名称）。如果方法的声明如下：

```java
void method1(int a, float b)
```

那么编译器可能会使用逻辑名称 "method1 of int and float"。如果参数指定为：

```java
void method1(float a, int b)
```

那么编译器可能会使用逻辑名称 "method1 of float and int"。参数类型的顺序非常重要——编译器认为上述两个方法头是不同的。

### 重载方法的返回类型

在讨论编译器使用的方法逻辑名称时，我们并没有提到方法的返回类型。方法调用不能仅通过返回类型来区分。如果你有仅在返回类型上不同的重载方法，并且在语句中调用了其中一个方法：

```java
square(2);
```

编译器将无法确定调用哪个版本的方法，因为返回值被忽略了。当两个方法具有相同的签名和不同的返回类型时，编译器会发出错误信息，指示该方法在类中已定义。如果方法的参数列表不同，重载方法可以具有不同的返回类型。重载方法的参数数量可以不同。

> **编程错误 6.8**
> 无论返回类型是否不同，声明参数列表相同的重载方法都是编译错误。

## 6.13（可选）GUI 与图形案例研究：颜色与填充形状

虽然你可以用线条基础形状创建有趣的设计，但 `Graphics` 提供了更多功能。我们介绍的接下来两个功能是颜色和填充形状。添加颜色丰富了我们在计算机屏幕上看到的图形。形状可以用实色填充。

显示在计算机屏幕上的颜色由红、绿、蓝分量（RGB 值）定义，这些值是从 0 到 255 的整数。组件颜色的值越高，颜色就越丰富。我们使用 `Color` 类（位于 `java.awt` 包）使用 RGB 值表示颜色。为了方便起见，`Color` 类包含了各种预定义的静态 `Color` 对象——`BLACK`、`CYAN`、`DARK_GRAY`、`GRAY`、`LIGHT_GRAY`、`WHITE` 和 `YELLOW`。可以通过类名和点（.）访问每个对象，如 `Color.YELLOW`。你可以通过将红、绿、蓝分量值传递给 `Color` 类的构造函数来创建自定义颜色：

```java
public Color(int r, int g, int b)
```

`Graphics` 方法 `fillRect` 和 `fillOval` 分别绘制填充的矩形和椭圆。这些参数与 `drawRect` 和 `drawOval` 相同；前两个参数是形状左上角的坐标，接下来的两个决定宽度和高度。图 6.11 中的示例通过在脸上绘制并涂画一个黄色笑脸演示了颜色和填充形状。

```java
// 图 6.11: DrawSmiley.java
// 使用颜色和填充形状绘制一个笑脸。
import java.awt.Color;
import java.awt.Graphics;
import javax.swing.JPanel;

public class DrawSmiley extends JPanel {
    public void paintComponent(Graphics g) {
        // 绘制脸部
        g.setColor(Color.YELLOW);
        g.fillOval(10, 10, 200, 200);

        // 绘制眼睛
        g.setColor(Color.BLACK);
        g.fillOval(55, 65, 30, 30);
        g.fillOval(135, 65, 30, 30);

        // 将嘴部调整成微笑
        g.setColor(Color.YELLOW);
        g.fillRect(50, 110, 120, 30);
        g.fillOval(50, 120, 120, 40);
    }
 // 结束 DrawSmiley
}
```
