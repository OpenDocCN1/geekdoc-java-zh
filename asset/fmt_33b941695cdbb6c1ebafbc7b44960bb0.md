## 19.2 线性查找

查询电话号码、通过搜索引擎查找网站以及在字典中检查单词定义涉及搜索大量数据。本节和第 19.4 节讨论了两种常见的搜索算法——一种容易编写但效率相对较低（线性查找），另一种相对有效但编写更复杂（二分查找）。

### 线性查找算法

该搜索算法按顺序搜索数组中的每个元素。如果搜索键与数组中的元素不匹配，算法将测试每个元素，当到达数组末尾时，通知用户搜索键不存在。如果搜索键在数组中，算法将测试每个元素，直到找到匹配项并返回其索引。

例如，考虑一个包含以下值的数组：`34 | 56 | 2 | 10 | 77 | 51 | 93 | 30`，以及一个搜索 51 的程序。使用线性查找，程序首先检查 34 是否匹配搜索键。如果不匹配，算法检查 56 是否匹配。程序继续遍历数组，测试 2、10、77。当程序测试 51 时匹配了搜索键，程序返回该元素的索引 5。在检查每个元素后，程序确定搜索键不匹配任何元素，返回一个哨兵值（例如 -1）。

### 线性查找实现

`LinearTest` 类（图 19.2）包含了用于 `int` 数组的静态方法 `linearSearch` 以及测试 `linearSearch` 的 `main`。

```java
// 图 19.2: LinearTest.java
// 按顺序搜索数组中的项

import java.security.SecureRandom;
import java.util.Arrays;
import java.util.Scanner;

public class LinearTest {

    // 在数据上执行线性查找
    public static int linearSearch(int[] data, int searchKey) {
        // 遍历数组
        for (int index = 0; index < data.length; index++) {
            if (data[index] == searchKey)
                return index; // 返回索引
        }
        return -1; // 未找到整数
    }

    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        SecureRandom generator = new SecureRandom();
        int[] data = new int[10]; // 创建数组
        for (int i = 0; i < data.length; i++) // 填充数组
            data[i] = 10 + generator.nextInt(90);

        System.out.printf("%s%n", Arrays.toString(data)); // 显示数组

        // 获取用户输入
        System.out.printf("请输入整数（-1 退出）：%n");
        int searchInt = input.nextInt();

        // 重复输入整数；-1 终止程序
        while (searchInt != -1) {
            int position = linearSearch(data, searchInt); // 执行搜索
            if (position == -1) // 未找到
                System.out.printf("%d 未找到%n", searchInt);
            else // 找到
                System.out.printf("%d 位于位置 %d%n", searchInt, position);

            // 获取用户输入
            System.out.printf("请输入整数（-1 退出）：%n");
            searchInt = input.nextInt();
        }
    } // 结束 main
} // 结束类 LinearTest
```

## 19.3 大 O 表示法

搜索算法都实现了同一个目标——如果确实存在这样的元素，则找到与给定键匹配的元素（或元素）。然而，有很多因素可以将算法区分开来。主要区别在于它们完成搜索所需的精力。描述这种精力的一种方式是使用大 O 表示法，它指示了算法解决问题可能需要多大的工作。对于搜索和排序算法，这特别取决于数据元素的数量。在本章中，我们使用大 O 来描述各种搜索和排序算法的最坏情况运行时间。

### 19.3.1 O(1) 算法

假设有一种算法用于测试数组的第一个元素是否等于第二个元素。如果数组有 10 个元素，该算法只需要一次比较。事实上，该算法完全独立于元素的数量。这种算法被认为具有常数运行时间，在大 O 表示法中表示为 `O(1)`，读作 "order one"。一个 `O(1)` 的算法并不一定意味着只需要一次比较。`O(1)` 仅意味着比较次数是常数——它不会随着数组大小的增加而增长。一个测试数组第一个元素是否为后续三个元素之一的算法，即使需要三次比较，仍然是 `O(1)`。

### 19.3.3 O(n²) 算法

现在假设你有一个算法，测试数组中的元素是否在数组的其他地方重复。第一个元素必须与数组中的每个其他元素比较。第二个元素必须与除第一个元素以外的所有其他元素比较（它已经和第一个元素比较过了）。第三个元素必须与除第二个元素以外的所有其他元素比较。最后，该算法将进行 $(n-1) + (n-2) + \dots + 2 + 1$ 或 $n^2/2$ 次比较。随着 $n$ 的增大，$n^2$ 项占主导地位，大 O 表示法强调 $n^2$ 项并留下了 $n/2$。正如我们很快看到的，大 O 表示法中省略了常数因子。

大 O 关注的是算法运行时间相对于处理的项目数量的增长。假设一个算法需要 $n^2$ 次比较。对于四个元素，算法需要 16 次比较；对于八个元素，需要 64 次比较。元素数量翻倍，比较次数变为四倍。考虑一个需要 $n^2/2$ 次比较的算法。对于八个元素，元素数量翻倍，比较次数变为四倍。这类算法随 $n$ 的平方增长，因此大 O 忽略了常数，且这些算法被认为是 `O(n²)`，这被称为二次时间，读作 "on the order of n-squared" 或简单称为 "order n-squared"。

当 $n$ 较小时，`O(n²)` 算法对性能的影响不会十分显著。但随着 $n$ 的增大，你会开始注意到性能下降。在包含百万个元素的数组上运行 `O(n²)` 将需要一万亿次“操作”（每次操作可能需要几条机器指令来执行）。这可能花费几个小时。一个十亿元素的数组将需要数万亿次操作，因为算法可能花费数十年！遗憾的是，`O(n²)` 算法很容易编写，正如你在本节中看到的。你还会看到具有更优大 O 指标的算法。创建这些高效算法通常需要更多的技巧和努力，但它们卓越的性能值得额外的付出，特别是当 $n$ 变得很大以及算法被组合成更大的程序时。

### 19.3.4 线性查找的大 O 复杂度

线性查找算法的运行时间为 `O(n)`。该算法的最坏情况是必须检查每个元素，以确定搜索项是否存在于数组中。如果数组大小翻倍，算法必须执行的比较次数也会翻倍。如果匹配搜索键的元素恰好位于数组的前部，线性查找可以提供最佳性能。我们还寻求在所有搜索中平均表现良好的算法，包括那些匹配搜索键的元素位于数组末尾的情况。

线性查找很容易编写，但与其他算法相比可能很慢。如果程序需要在大型数组上执行多次搜索，最好实现更高效的算法，例如我们接下来要介绍的二分查找。

> **性能提示 19.1**
> 有时最简单的算法性能表现最好。它们的优点是易于编程、测试和调试。有时需要更复杂的算法来最大化性能。

## 19.4 二分查找

二分查找比线性查找更高效，但它要求数组必须经过排序。该算法的第一次迭代测试数组中的中间元素。如果该元素匹配搜索键，算法结束。假设数组是按升序排列的，那么如果搜索键小于中间元素，它就不可能匹配数组后半部分的任何元素，算法继续仅处理数组的前半部分（即包含中间元素在内的元素）。如果搜索键大于中间元素，它就无法匹配数组前半部分的任何元素，算法继续仅处理后半部分（即中间元素之后到最后一个元素的元素）。每次迭代都会测试数组剩余部分的中间值。如果搜索键不匹配，算法将排除一半剩余元素。算法通过找到匹配搜索键的元素或将子数组大小减为零来结束。

### 示例

例如，考虑一个排序好的 15 元素数组：

| 2 | 3 | 5 | 10 | 27 | 30 | 34 | 51 | 56 | 65 | 77 | 81 | 82 | 93 | 99 |

以及一个搜索键 65。实现二分查找算法的程序将首先检查 51 是否为搜索键（因为 51 是数组的中间元素）。搜索键 (65) 大于 51，因此忽略数组的前半部分（所有小于 51 的元素），留下：

| 56 | 65 | 77 | 81 | 82 | 93 | 99 |

接下来，算法检查新子数组的中间元素 81。搜索键 (65) 小于 81，因此忽略后半部分，留下：

| 56 | 65 | 77 |

最后，算法检查中间元素 65，匹配搜索键，算法结束。
