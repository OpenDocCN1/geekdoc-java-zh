## 24.4 WHERE 子句

在大多数情况下，有必要在数据库中定位满足某些选择标准的结果。只有满足选择标准（以前称为谓词）的行会被选中。SQL 在查询中使用可选的 `WHERE` 子句来指定查询的选择标准。带有选择标准的查询的 Basic 形式为：

```sql
SELECT columnName1, columnName2 FROM tableName WHERE criteria
```

例如，从 `Titles` 表中选择 `Title`、`EditionNumber` 和 `Copyright` 列，其 `Copyright` 日期大于 2013，使用查询：

```sql
SELECT Title, EditionNumber, Copyright
FROM Titles
WHERE Copyright > '2013'
```

SQL 中的字符串用单引号 (`''`) 而不是双引号 (`""`) 括起来。图 24.12 显示了上述查询的结果。

| Title | EditionNumber | Copyright |
|---|---|---|
| n Java How to Program | 10 | 2015 |
| Java How to Program, Late Objects Version | 10 | 2015 |
| Visual Basic 2012 How to Program | 6 | 2014 |
| Visual C# 2012 How to Program | 5 | 2014 |
| C++ How to Program | 9 | 2014 |
| Android How to Program | 2 | 2015 |
| Android for Programmers: An App-Driven Approach, Volume 1 | 2 | 2014 |

### 模式匹配：零或多个字符

`WHERE` 子句的标准可以包含运算符 `<`、`>`、`>=`、`=` 和 `LIKE`。`LIKE` 用于带有通配符百分比 (`%`) 和下划线 (`_`) 的模式匹配。模式匹配允许 SQL 搜索匹配给定模式的字符串。

包含百分比字符 (`%`) 的模式搜索在模式中百分比字符位置有零或多个字符的字符串。例如，该查询定位所有姓以字母 D 开头的作者行：

```sql
SELECT AuthorID, FirstName, LastName
FROM Authors
WHERE LastName LIKE '%D%'
```

该查询选取了图 24.13 所示的两行——三位作者的姓以字母 D 开头（后面跟着零或多个字符）。`WHERE` 子句 `LIKE` 模式中的 `%` 符号表示 `LastName` 中的字母 D 之后可以出现任意数量的字符。模式字符串被单引号包围。

| AuthorID | FirstName | LastName |
|---|---|---|
| 1 | Paul | Deitel |
| 2 | Harvey | Deitel |
| 3 | Abbey | Deitel |

### 模式匹配：任意字符

模式字符串中的下划线 (`_`) 表示模式中该位置的单个通配符字符。例如，该查询定位所有姓以任意字符（由 `_` 指定）开头，其后是字母 o，再后面是任意数量的额外字符（由 `%` 指定）的作者行：

```sql
SELECT AuthorID, FirstName, LastName
FROM Authors
WHERE LastName LIKE '_o%'
```

前一个查询产生了图 24.14 所示的行，因为我们数据库中只有一位作者的姓中 o 是第二个字母。

|---|---|---|

## 24.4.3 ORDER BY 子句

查询结果中的行可以使用可选的 `ORDER BY` 子句按升序或降序排序。带有 `ORDER BY` 子句的查询的基本形式为：

```sql
SELECT columnName1, columnName2, ... FROM tableName ORDER BY column ASC
SELECT columnName1, columnName2, ... FROM tableName ORDER BY column DESC
```

其中 `ASC` 指定升序（从低到高），`DESC` 指定降序（从高到低），`column` 指定用于排序基准的列。例如，要按升序获取作者列表（图 24.15），使用查询：

```sql
SELECT AuthorID, FirstName, LastName
FROM Authors
ORDER BY LastName ASC
```

| AuthorID | FirstName | LastName |
|---|---|---|
| 1 | Paul | Deitel |
| 2 | Harvey | Deitel |
| 3 | Abbey | Deitel |
| 5 | Michael | Morgana |
| 4 | Dan | Quirk |

**图 24.15** | 表中的升序示例数据。

### 降序排序

默认排序是升序，因此 `ASC` 是可选的。要按名称降序获取相同的列表（图 24.16），使用查询：

```sql
SELECT AuthorID, FirstName, LastName
FROM Authors
ORDER BY LastName DESC
```

| AuthorID | FirstName | LastName |
|---|---|---|
| 4 | Dan | Quirk |
| 5 | Michael | Morgana |
| 1 | Paul | Deitel |
| 2 | Harvey | Deitel |
| 3 | Abbey | Deitel |

**图 24.16** | 表中的降序示例数据。

### 多列排序

可以使用以下形式的 `ORDER BY` 子句多列排序：

```sql
ORDER BY column1, column2, ...
```

其中每列指定 `ASC` 或 `DESC`。

### 结合 WHERE 和 ORDER 子句

`WHERE` 和 `ORDER BY` 子句可以在查询中结合，例如：

```sql
SELECT ISBN, Title, EditionNumber, Copyright
FROM Titles
WHERE Title LIKE '%How to Program'
ORDER BY Title ASC
```

## 24.4.4 从多个表映射数据：INNER JOIN

数据库设计人员通常将相关数据拆分为单独的表，以确保数据库不存储冗余数据。例如，在书籍数据库中，我们使用 `AuthorISBN` 表来存储作者与其标题之间的关系。如果我们不将这些信息拆分到单独表中，我们就需要在 `Titles` 表的每个条目中包含作者信息。这将导致数据库存储重复的作者信息。

通常，有必要将多个表的数据合并到一个结果中。这被称为连接表，通过 `INNER JOIN` 算符指定，它通过匹配两个表中共同的列的值来合并两个表的行。`INNER JOIN` 的基本形式是：

```sql
SELECT columnName1, columnName2, ...
FROM table1
INNER JOIN table2
ON table1.columnName = table2.columnName
```

`INNER JOIN` 的 `ON` 子句指定了每个表中用于确定哪些行被合并的共同列——这些字段几乎对应于被连接表中的外键字段。例如，查询根据每个作者书籍的 ISBN 生成了作者列表：

```sql
SELECT FirstName, LastName, ISBN
FROM Authors
INNER JOIN AuthorISBN
ON Authors.AuthorID = AuthorISBN.AuthorID
ORDER BY LastName
```

该查询将 `Authors` 表中的 `FirstName` 和 `LastName` 列与 `AuthorISBN` 表中的 `ISBN` 列合并，并按 `LastName` 和 `FirstName` 升序排序结果。注意在 `ON` 子句中使用 `table.columnName` 语法。这种语法称为限定名，它指定了从每个表中应连接到其他表的列。如果表中的列具有相同的名称，则需要使用 `"TableName."` 语法。相同的语法可以用于任何 SQL 语句，用以区分不同表中具有同名的列。在某些系统中，可以使用限定数据库名的表名来执行跨数据库查询。像一常一样，查询可以包含一个 `ORDER BY` 子句。图 24.19 显示了上述查询的结果，按 `LastName` 和 `FirstName` 排序。[注：为了节省空间，我们将查询结果分为两列，包含 `FirstName`、`LastName` 和 `ISBN`。]

## 24.4.5 INSERT 语句

`INSERT` 语句向表中插入一行。该语句的基本形式是：

```sql
INSERT INTO table (columnName1, columnName2, ..., columnNameN)
VALUES (value1, value2, ..., valueN)
```

其中 `table` 是要插入行的表名。`INSERT` 语句后面跟着括号内用逗号分隔的列名列表（如果 `INSERT` 操作按正确顺序为表的每个列都指定了值，则不需要此列表）。值必须与表名后指定的列相匹配（例如，如果 `columnName` 预想是 `FirstName`，那么 `value` 就是一个用单引号括起来表示名称的字符串）。在插入行时，始终列出列。如果表发生了变化或添加了新列，仅使用 `VALUES` 可能会导致错误。该语句为 `FirstName` 和 `LastName` 提供了值。对应的值为 'Sue' 和 'Smith'。在这个示例中，我们没有指定 `AuthorID`，因为 `AuthorID` 是表中的一个自增列。对于添加到此表中的每行，DBMS 都会分配一个唯一的 `AuthorID`，该值是自增序列中的下一个值（例如 1、2 等等）。在这种情况下，Sue 被分配了编号为 6 的 `AuthorID`。图 24.20 显示了 `INSERT` 操作后的表。[注：并不是每个数据库系统都支持自增列。]

带有单引号 (`''`) 的 SQL 字符串。包含单引号的字符串（如 `O'Malley`）必须进行转义处理，具体方法请参考数据库文档。
