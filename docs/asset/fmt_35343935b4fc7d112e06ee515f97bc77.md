        try {

            throw new Exception(); // 生成异常

        } catch (Exception exception) { // 捕获 try 中抛出的异常

        } finally { // 无论 try...catch 发生什么，都会执行

        }

    }

    // 演示在未发生异常时的 finally

    public static void doesNotThrowException() {

        try { // try 块没有抛出异常

            System.out.println("Method doesNotThrowException");

        } catch (Exception exception) { // 不执行

            System.err.println(exception);

        } finally { // 无论 try...catch 发生什么，都会执行

            System.err.println("Finally executed in doesNotThrowException");

        }

    }

`System.out` 和 `System.err` 是流——字节序列。`System.out`（称为标准输出）显示程序的输出，`System.err`（称为标准错误）显示程序的错误。这些流的输出可以被重定向（即发送到命令提示符的其他地方，例如文件）。使用两个流允许你将错误消息与其他输出分离开。例如，来自 `System.err` 的数据输出可以发送到日志文件，而来自 `System.out` 的数据输出可以显示在屏幕上。为了简单起见，本章将不会重定向 `System.err` 的输出，而是将向命令提示符显示消息。你将在第 15 章学习更多关于流的知识。

### 使用 throw 语句抛出异常

方法 `main`（图 11.5）开始，进入其 `try` 块并立即调用方法 `throwException`（第 10 行）。该方法抛出一个 `Exception`。第 26 行的语句不是 `throw` 语句——它的执行是为了表示发生了异常。到目前为止，你只捕获了由调用方法抛出的异常。你可以通过使用 `throw` 语句来自己抛出异常。与 Java API 方法抛出的异常一样，这向客户端应用程序表明发生了错误。`throw` 语句指定一个要抛出的对象。该对象可以是任何继承自 `Throwable` 的类的实例。

### 重新抛出异常

图 11.5 的第 32 行抛出了异常。当 `catch` 块在接收到异常后，决定无法处理该异常或只能部分处理它时，异常会被重新抛出。重新抛出异常会将异常处理（或其部分）推迟到与外部 `try` 语句相关的另一个 `catch` 块。使用 `throw` 关键字重新抛出异常，随后是对刚刚捕获的异常对象的引用。异常无法在 `finally` 块中重新抛出，因为 `catch` 块中的异常参数（局部变量）已不再存在。

当发生 `throw` 时，外层的 `try` 块会检测到重新抛出的异常，并在 `main` 方法的第 8–11 行找到下一个对应的 `catch` 块。然而，在处理异常之前，`finally` 块会执行。

## 11.8 异常链

### 从异常对象获取数据

所有异常都继承自 `Throwable`，它拥有一个 `printStackTrace` 方法，该方法向标准错误流输出堆栈轨迹（在第 11.2 节讨论）。这在测试和调试中非常有用。`Throwable` 类还提供了一个 `getStackTrace` 方法，用于检索可能被 `printStackTrace` 打印的堆栈轨迹信息。`Throwable` 的 `getMessage` 返回存储在异常中的描述性字符串。

> **错误预防提示 11.7**
> 如果异常没有被捕获，Java 默认异常处理程序将运行。这会显示异常的类名、一个指示发生问题的描述性消息以及完整的执行堆栈轨迹。在单线程执行的应用程序中，异常将终止程序。在多线程的应用程序中，导致异常的线程将终止。我们在第 23 章讨论多线程。

> **错误预防提示 11.8**
> `Throwable` 的 `toString`（被所有 `Throwable` 子类继承）返回一个包含异常类名和描述性消息的字符串。

第 11.6 行（第 12–31 行）演示了 `getMessage`、`printStackTrace` 和 `getStackTrace`。如果我们想将堆栈轨迹信息输出到标准错误以外的流，可以使用 `getStackTrace` 获取的信息并将其输出到另一个流或 `printStackTrace` 方法的重载版本之一。将数据发送到其他流将在第 15 章中讨论。

第 14 行调用异常的 `getMessage` 方法获取异常描述。第 15 行调用异常的 `printStackTrace` 方法输出指示异常发生位置的堆栈轨迹。第 18 行调用异常的 `getStackTrace` 方法以 `StackTraceElement` 对象数组的形式获取堆栈轨迹。第 24–30 行获取数组中的每个 `StackTraceElement` 并调用其方法 `getClassName`、`getFileName`、`getLineNumber` 和 `getMethodName` 分别获取类名、文件名、行号和方法名。每个 `StackTraceElement` 代表方法调用栈上的一个方法。

程序的输出显示 `printStackTrace` 的输出遵循以下模式：`className.methodName(fileName:lineNumber)`，其中 `className` 和 `methodName` 分别表示异常发生的类名和方法名，`fileName` 和 `lineNumber` 表示异常发生的文件名和行号。你在图 11.2 的输出中见过这一点。`getStackTrace` 方法允许对异常信息进行自定义处理。比较 `printStackTrace` 的输出与通过它创建的输出，它们都包含相同的堆栈轨迹信息。

> **软件工程观察 11.11**
> 偶尔，你可能想通过编写一个空身体的 `catch` 处理程序来忽略异常。在这样做之前，确保该异常没有指示堆栈高处可能需要知道或恢复的状况。

## 11.8 异常链

有时，方法会通过抛出一个特定于当前应用程序的不同异常类型来响应异常。如果 `catch` 块抛出一个新异常，原始异常的信息和堆栈轨迹将会丢失。早期的版本没有提供包装带有完整堆栈轨迹的异常的机制以显示问题发生的地方。图 11.7 展示了异常链。

```java
public class UsingExceptions {

    public static void main(String[] args) {

        try {

            method1();

        } catch (Exception e) {

            e.printStackTrace();

        }

    }

    public static void method1() throws Exception {

        try {

            method2();

        } catch (Exception e) {

            throw new Exception("Exception in method1", e);

        }

    }

    public static void method2() throws Exception {

        try {

            method3();

        } catch (Exception e) {

            throw new Exception("Exception in method2", e);

        }

    }

    public static void method3() throws Exception {

        throw new Exception("Exception in method3");

    }

}
```
