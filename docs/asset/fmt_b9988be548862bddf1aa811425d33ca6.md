# 23.4 线程同步

当线程调用 `PrintTask` 的 `run` 方法时，`PrintTask` 开始执行。第 25–26 行显示一条消息，表示当前任务将睡眠 `sleepTime` 毫秒。第 27 行调用 `Thread` 类的静态 `sleep` 方法，将线程放入指定时间的定时等待状态。此时，线程失去了处理器，系统允许另一个线程执行。当线程唤醒时，它进入可运行状态。当 `PrintTask` 再次分配给处理器时，第 36 行输出一条表示任务已完成的消息，然后方法返回。第 29–33 行的 `catch` 块是必须的，因为如果调用了睡眠线程的方法，`sleep` 可能会抛出 `InterruptedException` 类型的检查异常。

在这些情况下，程序的行为是不可靠的——有时程序会产生正确的结果，有时则不会，而且没有任何迹象表明共享对象被错误地操作了。

这个问题可以通过一次只允许一个线程对访问共享对象的代码进行排他性访问来解决。在此期间，其他想要访问该对象的线程将保持等待状态。当允许等待线程中的某一个线程继续执行时，这种过程被称为**线程同步**（thread synchronization），它负责协调多个并发线程之间的数据。通过以这种方式同步线程，你可以确保每个访问共享对象的线程都排除了其他线程同时进行操作——这被称为**互斥**（mutual exclusion）。

## 23.4.1 不变数据

实际上，线程同步仅对于**可变数据**（mutable data）是必要的，即在生命周期内可能会改变的数据。对于不会改变的不可变数据，线程不可能因为另一个线程对数据的操作而看到旧值或错误值。

当你跨线程共享不可变数据时，请将相应的字段声明为 `final`，以确保变量在初始化后不发生改变。这可以防止对共享数据的意外修改，从而损害线程安全。将引用标记为 `final` 不会改变引用本身，但它不能保证所引的对象是不可变的——这完全取决于对象的属性。然而，将不会改变的引用标记为 `final` 仍然是一个良好的做法。

## 23.4.2 监视器

执行同步的一种常用方法是使用 Java 内置的监视器（monitors）。每个对象都有一个监视器和一个监视锁（内在锁）。监视器确保在任何时候只有一个线程持有该对象的监视器锁。监视器和监视锁可用于强制互斥。如果某个操作要求在执行操作时持有锁，则线程在继续操作之前必须获取锁。其他尝试执行需要相同锁的操作的线程将被阻塞，直到第一个线程释放锁，此时，被阻塞的线程可能会获取锁并继续操作。

为了指定线程必须监视某个锁以执行代码块，该代码被认为受**监视器锁保护**（guarded by the monitor lock）——线程必须获取该锁才能执行受保护的语句。监视器允许一次只有一个线程执行锁定相同对象的 `synchronized` 语句中的语句，因为同一时间只有一个线程可以持有监视器锁。`synchronized` 语句使用 `synchronized` 关键字声明：

```java
synchronized (object)
{
  statements
}
```

其中 `object` 是将获取监视器锁的对象；如果 `synchronized` 语句出现在该对象内部，`object` 通常就是该对象（即 `this`）。如果不同线程中的多个 `synchronized` 语句尝试同时在一个对象上执行，只有其中一个会在该对象上活跃——所有其他尝试进入同一对象的 `synchronized` 语句的线程都将置于阻塞状态。

当 `synchronized` 语句执行完毕后，该对象的监视器锁将释放，一个尝试进入 `synchronized` 语句的阻塞线程即可继续执行。Java 还允许使用 `synchronized` 方法。在执行之前，`synchronized` 实例方法必须获取用于调用该方法的对象的锁。同样，静态 `synchronized` 方法必须获取调用该方法的类的锁。
