
# 第 17 章 Java SE 8 Lambdas 和 Streams

## 17.2.3 流

- 流实现接口（来自 `java.util.stream` 包）的对象，并允许你执行函数式编程任务。还有用于处理 `int`、`long` 或 `double` 值的专用流接口。
- 流将元素通过一系列处理步骤（被称为**流流水线**）进行移动——该流水线从数据源开始，对数据源执行各种操作，并以终端操作结束。流流水线通过链式方法调用形成。
- 与集合不同，流没有自己的存储——一旦流被处理，它就无法重用，因为它不维护原始数据源的副本。
- **中间操作**指定在流元素上执行的任务，并返回一个新流。
- 中间操作是**惰性的**——在调用终端操作之前不会执行。
- 终端操作触发流的处理。

## 17.3 操作

### 17.3.1 创建 IntStream 并显示其值

- 让库决定如何遍历元素集合被称为**内部迭代**。内部迭代更易进行并行化。

### 17.3.2 终端操作

- `IntStream` 提供的 `count`、`min`、`max` 和 `sum` 操作返回 `OptionalDouble` 对象。

### 17.3.3 终端操作 reduce

- 你可以通过调用其 `reduce` 方法在 `IntStream` 上定义自己的二元操作。第一个参数是标识值，第二个参数是实现 `IntBinaryOperator` 的对象。

### 17.3.4 操作：过滤和排序 IntStream 值

- 你过滤元素以产生符合谓词的流。`filter` 接收一个实现 `IntPredicate` 接口（`java.util.function`）的对象。
- `sorted` 将流元素按升序排列。在执行该方法之前，流流水线中的所有先前操作必须完成。

### 17.3.5 中间操作：映射

- 映射是将流的元素转换为新值并产生包含这些（可能不同的）元素的流中间操作。
- `map`（无状态中间操作）接收一个实现 `IntUnaryOperator` 接口（`java.util.function`）的对象。

### 17.3.6 使用 IntStream 方法和 rangeClosed 创建 int 流

- `IntStream` 方法和 `rangeClosed` 产生有序的 int 值序列。这两个方法都接受两个 int 参数表示范围。

## 17.4 Stream<Integer> 操作

- `Arrays.stream` 方法用于从对象数组创建 `Stream`。

### 17.4.1 创建 Stream<Integer>

- `Stream`（package `java.util.stream`）是一个用于对对象执行流操作的泛型接口。所处理的对象类型由 `Stream` 的源决定。
- `Arrays` 类提供了重载的 `stream` 方法，可以从 `int`、`long` 和 `double` 数组或数组中的元素范围创建 `IntStream`、`LongStream` 和 `DoubleStream`。

### 17.4.2 对流进行排序并收集结果

- 方法 `sorted` 默认按升序对流的元素进行排序。
- 要创建一个包含流流水线结果的集合，可以使用 `collect` 方法（一种终端操作）。随着流流水线的处理，`collect` 执行一个可变归约操作，将结果放入对象中，例如 `List`、`Map` 或 `Set`。
- 带有一个参数的 `collect` 方法接收实现 `Collector` 接口（package `java.util.stream`）的对象，该接口指定了如何执行可变归约。
- `Collectors` 类（package `java.util.stream`）提供了返回预定义 `Collector` 实现的静态方法。
- 方法 `toList` 将 `Stream<T>` 转换为 `List<T>`。

### 17.4.3 过滤流并存储结果供以后使用

- 方法 `filter` 接收一个 `Predicate` 并返回匹配该 `Predicate` 的对象流。`Predicate` 方法根据参数是否满足某个条件返回布尔值。`Predicate` 接口还拥有 `negate` 和 `or` 方法。

### 17.4.5 对之前已收集的结果进行排序

- 一旦你将流流水线放入集合中，就可以从该集合创建一个新的流，以便对先前的结果执行额外的流操作。

## 17.5 进阶流操作

### 17.5.1 对流进行映射：使用方法引用转换为大写字母

- 方法 `map` 将每个元素映射到一个新值，并产生一个与原始流元素数量相同的新流。
- 方法引用是实例方法的简写形式。
- `ClassName::instanceMethod` 代表类实例方法的方法引用。它创建一个单参数的 lambda 表达式，该表达式调用其 lambda 参数的实例方法并返回方法的结果。
- `objectName::instanceMethod` 代表应在特定对象上调用的实例方法的方法引用。它创建一个单参数的 lambda 表达式，该表达式在指定对象上调用实例方法——传递 lambda 参数——并返回方法的结果。
- `ClassName::staticMethod` 代表类静态方法的方法引用。它创建一个单参数的 lambda 表达式，其中 lambda 参数被传递给静态方法，lambda 返回方法的结果。
- `ClassName::new` 代表构造函数引用。它创建一个 lambda 表达式，调用指定类的无参数构造函数来创建并初始化该类的新对象。

### 17.5.2 过滤流后按不区分大小的升序排序

- 方法 `sorted` 可以接收一个比较器作为参数，以指定如何比较流元素进行排序。
- 默认情况下，`sorted` 方法使用流元素类型的自然顺序。

### 17.5.3 过滤字符串后按不区分大小的降序排序

- 函数式接口 `Comparator` 的默认方法 `reversed` 反转现有的比较器排序顺序。

## 17.6 Employee 流操作示例

### 17.6.1 创建并显示 List<Employee>

- 当将实例引用 `System.out::println` 传递给 `Stream` 的 `forEach` 时，编译器将其转换为一个实现 `Consumer` 接口的对象。该接口的 `accept` 方法接收一个参数并返回 `void`。在这种情况下，`accept` 方法将参数传递给 `System.out.println` 方法。

### 17.6.2 过滤工资在指定范围内的员工

- 要重用 lambda，可以将其赋值给相应接口类型的变量。
- `Comparator` 的静态方法 `comparing` 返回一个 `Function`，该 `Function` 用于从流中的对象中提取值以进行比较，并返回一个 `Comparator`。
- **延迟求值**的性能优势是能够执行**短路求值**——即一旦获得结果立即停止流流水线的处理。
- `Stream` 方法 `findFirst` 是一种短路终端操作，它处理流流水线，并在找到流流水线中的第一个对象时立即终止处理。该方法返回一个包含找到的对象的 `Optional` 对象（如果有）。

### 17.6.3 按多个字段对员工排序

- 要按字段对对象进行排序，你需要创建一个使用两个 `Function` 的 `Comparator`。首先，你调用 `Comparator` 方法 `comparing` 来创建一个带有第一个 `Function` 的 `Comparator`。在生成的 `Comparator` 上，你使用第二个 `Function` 调用 `thenComparing`。最终生成的 `Comparator` 使用第一个 `Function` 比较对象，如果对象相等，则通过第二个 `Function` 对它们进行比较。

### 17.6.4 将员工映射为唯一的姓氏字符串

- 你可以将对象映射到不同类型，以产生另一个与原始流具有相同元素的流。
- `Stream` 方法 `distinct` 消除流中的重复对象。

### 17.6.5 按部门分组员工

- `Collectors` 方法 `groupingBy` 接收一个分类器、一个 `Map` 厂和一个下游 `Collector`。分类器是一个返回对象作为键的 `Function`。`Map` 厂是一个实现 `Supplier` 的对象并返回一个新的 `Map`。下游 `Collector` 决定如何收集每个组的元素。
- `Map` 方法 `entrySet` 返回包含 `Map` 键值对的 `Set`。
- `Set` 方法 `stream` 返回一个用于处理 `Set` 元素的流。

### 17.6.6 统计每个部门的人数

- 带有两个参数的 `Collectors` 方法 `groupingBy` 返回一个统计对象的 `Map`。
- `Collectors` 方法 `counting` 返回一个计算元素的 `Collector`。

### 17.6.7 求和与平均值

- `Stream` 方法 `mapToDouble` 将对象映射为双精度数值并返回一个 `DoubleStream`。该方法接收实现 `ToDoubleFunction`（package `java.util.function`）的对象并返回一个值。

## 17.7 从文件创建 Stream<String>

- `Files` 方法 `lines` 创建用于读取文件行的流。
- `Stream` 方法 `flatMap` 接收一个将对象映射为流的 `Function`。`Pattern` 方法 `splitAsStream` 使用正则表达式对字符串进行分词。

## 17.8 生成随机值流

- `SecureRandom` 的方法 `ints`、`longs` 和 `doubles`（继承自 `Random`）分别返回用于随机数的 `IntStream`、`LongStream` 和 `DoubleStream`。
- 无参数的 `ints` 方法创建一个用于随机值的无限流 `IntStream`。无限流是一个元素数量未知的流——你使用短路终端操作来完成无限流的处理。
- 带有一个 `long` 参数的 `ints` 创建具有指定数量随机值的 `IntStream`。
- 带有两个 `long` 参数的 `ints` 创建一个从第一个参数开始到但不包含第二个参数的范围内的无限随机值 `IntStream`。
- 带有一个 `long` 参数和两个 `int` 参数的 `ints` 创建具有指定数量随机值的 `IntStream`，其范围从第一个参数开始到但不包含第二个参数。
- 要将 `IntStream` 转换为 `Stream<Integer>`，调用 `IntStream.boxed`。
- `Function` 静态方法 `identity` 创建一个直接返回其参数的 `Function`。

## 17.9 Lambda 事件处理器

- 某些事件监听器是函数式接口。对于此类接口，你可以使用 lambda 实现事件处理器。

## 17.10 关于 Java 8 接口的补充说明

- 函数式接口必须包含一个抽象方法，但也可以包含在接口声明中完全实现的默认方法和静态方法。
- 当类实现一个带有默认方法的接口且没有重写它们时，该类继承默认方法的实现。接口的设计者可以通过添加新的默认和静态方法来演进接口，而不会破坏实现接口的现有代码。

## 自测习题

- 如果一个类从两个接口继承了相同的默认方法，则该类必须重写该方法；否则编译器将产生编译错误。
- 你可以通过确保每个接口只包含一个抽象方法且零或多个默认方法或静态方法，来创建自己的函数式接口。
- 你可以通过在接口前加上 `@FunctionalInterface` 注解来声明该接口为函数式接口。编译器将确保该接口只包含一个抽象方法；否则它将产生编译错误。

### 17.1 填空

a) Lambda 表达式实现了 **函数式接口**。
b) 函数式程序更容易进行 **并行化**（即：同时执行多个操作），这样你就可以利用多核架构来增强性能。
c) 通过 **内部迭代**，库决定了如何访问集合中的所有元素以执行任务。
d) 函数式接口 **BinaryOperator<T>** 包含一个接收两个参数、对这些参数执行操作（例如计算）并返回类型为 T 的返回值的方法。
e) 函数式接口 **Predicate<T>** 包含一个接收 T 参数并返回布尔值的方法，并用于测试 T 是否满足某个条件。
f) 一个 **lambda 表达式** 代表一个匿名方法——它是提及函数式接口的简写。
g) 中间流操作是 **惰性的**——在调用终端操作之前，它们不会被执行。
h) 终端流操作 **forEach** 对流中的每个元素执行操作。
i) **捕获** 使用了封闭作用域中的局部变量。
j) 惰性求值的性能特性是能够执行 **短路求值**——即一旦获得所需的结果，立即停止流流水线。
k) 对于 `Map` 来说，`BiConsumer` 的第一个参数代表 **键**，第二个参数代表 **值**。

### 17.2 判断正误

a) **正确**。Lambda 表达式可以用任何期望函数式接口的地方。
b) **错误**。终端操作是急切的——它们在调用时执行操作。
c) **错误**。求元素之和时，恒等值是 0；求元素乘积时，恒等值是 1。
d) **正确**。`findFirst` 方法是一个短路终端操作，它处理流流水线，但一旦找到对象就会终止。
e) **错误**。流方法 `flatMap` 返回一个流。
f) **错误**。当一个类实现带有默认方法的接口且**没有重写**它们时，该类继承了默认方法的实现。
