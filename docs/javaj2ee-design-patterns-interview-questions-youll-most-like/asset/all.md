[Introduction to Design Patterns](#tmp_f353b6c4930e82b6df695a2b6a8bbd14_uEhiwq.ch.fixed.fc.tidied.stylehacked.xfixed_split_003.html_TOC)

1: What are Design Patterns?

Answer:

Design Patterns are patterns, in an extent a way to pursue and intent, that use classes and their Methods in object oriented languages. In simple words, a Design Pattern is a general reusable solution to a commonly occurring problem in software design. A Design Pattern is not a finished design that can be transformed directly into code. It is a description or template for how to solve a problem that can be used in many different situations.

2: What is a Class Interface in Design Patterns?

Answer:

A Class Interface represents the collection of Methods and fields of a class that allow objects of other classes to access.

3: What is a Class Implementation in Design Patterns?

Answer:

A Class Implementation is designed to be the code that lies within its own code, with instructions on how an object is to fulfill a certain commitment.

4: What is the Java Interface Construct?

Answer:

The Java Interface Construct is a tool, powerful in its own right, used for adaptation of class interfaces and for applying patterns to collection of classes.

5: What is a Stub in Design Patterns?

Answer:

A Stub is a class used to implement the interface with Methods that do absolutely nothing; developers use this as a way to override Methods in the interface that are important to their own applications.

6: What is a Constant in Design Patterns?

Answer:

A Constant is a field that is static and final and it is defined by interfaces and classes that are cooperating with each other when it comes to the process of defining it.

7: What is the purpose of Design Patterns?

Answer:

Design Patterns are used mainly for solving problems that occur in a context, with interface oriented patterns addressing the context in which developers need to define or redefine access to the Methods of a class or group of classes.

8: What is an Adapter in Design Patterns?

Answer:

An Adapter is used for implementing expected interfaces, by having the developer provide the interface that a client needs, using the services of a class with a different interface.

9: What are measures and dimensions in Design Patterns?

Answer:

a. Measures are a combination of magnitude and dimension,

b. Dimensions are an aggregation of a measure’s length, mass and time exponents.

10: What does the times() Method do in Design Patterns?

Answer:

The times() Method is a standard measure, part of a unit, that instantiates whichever class of Measure reflects the dimension of any given unit.

11: When is Abstract Class used in Design Patterns?

Answer:

An Abstract Class is used when a Java interface is unusable and it can be deployed by having an object adapter that uses delegation as a Method rather than subclassing.

12: What does JDK stand?

Answer:

JDK stands for Java Development Kit. It is used to supply an Abstract Class that provides default implementation to most of the domain specific Methods.

13: What does the JTable class do in Design Patterns?

Answer:

The JTable class is used to handle almost every aspect of displaying a table, but cannot know in advance what data the developer wishes to present; it is a main setter for the use of the Adapter.

14: What is a Façade in Design Patterns?

Answer:

A Façade is a class with a level of functionality that lies between a toolkit and a complete application, thus offering a vanilla usage of the classes in a package or even in a subsystem. It is mainly used to provide an interface that makes a subsystem easy to use, if it is deployed as a pattern.

15: What is a Demo in Design Patterns?

Answer:

A Demo is an example that provides the same value as a Façade and shows the use of a class or a subsystem. It is mainly a stand alone, non-reusable application that shows on way to apply a subsystem.

16: What is a Composite in Design Patterns?

Answer:

A Composite is a group of objects in which objects may contain other objects, such as one object may represent groups and another object may represent an individual item.

17: What is the purpose of a Composite Pattern?

Answer:

A Composite Pattern is used to let clients treat individual objects and compositions of objects in a tight, uniform way, by defining a common type for groups and items and by modeling groups as containing a collection of

objects of a certain type.

18: What are Directed Graphs in Design Patterns?

Answer:

A Directed Graph is an object reference that has a direction with the tree term applied to undirected graphs. For a directed graph to be considered a tree it has to have a root node that has no references to it and it also has to have one edge to all other nodes.

19: What does the getStepCount() Method do in Design Patterns?

Answer:

This Method is used as an operation in the ProcessComponent class to count the number of steps needed in a process flow; it has to count each step only once and to not enter an infinite loop when a process contains a cycle.

20: What is the danger of Modeling Composites in Design Patterns?

Answer:

Because Modeling Composites usually leads to recursive definition of Methods on composite nodes, a danger exists of writing code that may produce an infinite loop.

21: What is an Abstraction in Design Patterns?

Answer:

Abstraction represents a class that relies on a set of purely abstract operations, where several implementations of the set of abstractions are possible.

22: How can we create a Bridge in Design Patterns?

Answer:

A Bridge can be created by moving the set of abstract operations to an interface so that an abstraction will depend on an implementation of the interface; its intent is mainly to decouple an abstraction from the implement-tations of its abstract operations.

23: What is a Driver in Design Patterns?

Answer:

A Driver is an instance of the adapter Pattern and it’s an object that operates on a computer system or an external device according to a well specified interface.

24: Why is UML used for Design Patterns?

Answer:

UML is an application modeling specification from OMG that simplifies the complex software engineering process.

25: How many diagrams does UML offer for classification in Design Patterns?

Answer:

UML offers 12 diagrams that represent an application’s requirements analysis and solution design.

26: How many structure diagrams does UML provide?

Answer:

UML provides 4 structure diagrams that are used to represent a static structure of an application. They are:

a. Class,

b. Object,

c. Component and

d. Deployment Diagrams.

27: How many Behavior Diagrams does UML provide?

Answer:

UML provides 5 Behavior Diagrams used to represent the dynamic behavioral aspects of an application. They are:

a. Use case,

b. Sequence,

c. Activity,

d. Collaboration and

e. Statechart.

28: How many Model Management diagrams does UML provide?

Answer:

UML provide 3 Management Diagrams which can be used to represent how different application modules are organized and managed. They are:

a. Packages,

b. Subsystems and

c. Models diagrams.

29: What are Class Diagrams?

Answer:

Class Diagrams are used to describe a static structure of any given system, where the structure and behavior of classes and their association with other classes are depicted inside of a class diagram.

30: What is an Inner Class?

Answer:

An Inner Class is a class that is simply defined inside another class with the concept of an inner class existing in object oriented languages like Java, C++and C#.

31: What is the Generalization Method used for in Design Patterns?

Answer:

Generalization is mainly used to depict the Object Oriented Concept of Inheritance when there is a base class with common behavior and each of its derived classes contains specific details.

32: What is an Interface in Design Patterns?

Answer:

An Interface is used to specify the externally visible operations of a class and not the actual implementations of those operations; it also most of the times specifies only a part of the behavior of an actual implementer class.

33: What is Realization in Design Patterns?

Answer:

Realization is used to show the relationship between an interface and a class that provides the actual implementation and it can be drawn in two ways depending on how the interface is depicted.

34: What is Dependency in Design Patterns?

Answer:

Dependency is used to show the relationship between a source and a target component when there is a dependency between relations between the two.

35: What is Multiplicity in Design Patterns?

Answer:

Multiplicity is used to indicate the number of instances of one class linked to one instance of the other class, with

different values used to indicate the Multiplicity.

36: What is a Message in Design Patterns?

Answer:

A Message simply puts communication between two objects with the horizontal line indicating a message that can be labeled with the name of the operation along with its argument values.

37: Why are Private Methods used for in Design Patterns?

Answer:

Private Methods are used to provide means of designing class behaviors so that external objects are not permitted to access the behavior that is meant only for an internal use.

38: Why is Accessor Method used in Design Patterns?

Answer:

Accessor Methods provide means of accessing an object’s state using specific Methods by discouraging different client objects from directly accessing the attributes of an object.

39: What is an Immutable Object used for in Design Patterns?

Answer:

An Immutable Object is mainly used to ensure that the state of an object cannot be changed and that the concurrent access to a data object by several client objects does not result in race conditions.

40: What does the Monitor Function do in Design Patterns?

Answer:

The Monitor Function is a way of designing an application object so that it does not produce unpredictable results when more than one thread tries to access the object at the same time.

41: What is a Singleton in Design Patterns?

Answer:

A Singleton represents the way of finding the responsible object needed for a particular responsibility on which other objects rely such as coordinating work or modulation of the overall state of a system

42: What does the getFactory() Method do?

Answer:

The getFactory() Method is used to ensure that if a second thread begins to lazy initialize the singleton after another thread has begun the same initialization, the second thread will wait to obtain the class lock object’s monitor.

43: What is the use of the Observer Pattern?

Answer:

The Observer Pattern is used to define a one-to-many dependency between objects. For example, when one object results in a state change, then all the dependents are notified and also automatically updated.

44: What does MVC stand for and what does it refer to?

Answer:

MVC stands for Model/View/Controller and it refers to separating an interesting object, which is the model, from GUI elements that are portraying it, which are the view and the controller.

45: What is a Layer in Design Patterns?

Answer:

A Layer is a group of classes that have similar response-bilities and are most of the times collected in a single unified Java package; higher layers depend only on classes in equal or lower layers.

46: How can a class observe a subclass in Design Patterns?

Answer:

A Class can be maintained by providing the class that the developer chooses with an observable object and have the class forward key Methods call it.

47: What does the PropertyChangeSupport class do?

Answer:

This class is similar to the Observer class but it is also part of the java.beans package. It is used to allow interested observers to register for notification of changes in the property of labels and other GUI components.

[Patterns and Objects](#tmp_f353b6c4930e82b6df695a2b6a8bbd14_uEhiwq.ch.fixed.fc.tidied.stylehacked.xfixed_split_003.html_TOC)

48: What does the Mediator Pattern do?

Answer:

The Mediator Pattern is used to define an object that encapsulates how a set of objects interact by keeping the objects from referring to one another in an explicit manner, also allowing the developer to vary their interaction independently.

49: What does a Proxy Pattern do?

Answer:

A Proxy Pattern is used to establish a placeholder object that manages access to a target object.

50: What is a Proxy Object?

Answer:

A Proxy Object is an object that can be used to isolate clients from shifts in a state of a desired object, like when loading an image results in discernible duration.

51: What is the use of a Chain of Responsibility Pattern?

Answer:

The Chain of Responsibility Pattern is used mainly to avoid coupling the sender of a request to its receiver by giving more than one object a chance to handle the

request.

52: What happens in the Chain of Responsibility?

Answer:

In Chain of Responsibility, an object model takes on the tasks of finding which object can and will satisfy a client’s request; this direct approach goes beyond the two lookup mechanisms that are built into Java:

a. The Method lookup and

b. The exception handling.

53: What happens when an Exception is thrown in Design Patterns?

Answer:

When an Exception is thrown, the Java Interpreter looks back up the call stack to find a Method called from a block that is enclosed in the try/catch statement. If this try/catch statement does not catch an Exception of the type thrown, the Java Interpreter keeps looking. This can propagate up to the main() Method. If the Exception is not handled there, the Java Interpreter prints out an error message and stack trace and then exits.

54: What does the Method Lookup do in Design

Patterns?

Answer:

The Method Lookup is used as an algorithm for deciding definition of a Method to use when a client calls an object’s Method.

55: What is the Flyweight Pattern used for in Design Patterns?

Answer:

The Flyweight Pattern is used for addressing sharing, relying on an object’s ability to be responsible to more than a single client, where an ordinary object does not have to worry too much about shared responsibility.

56: How can Flyweight be recognized?

Answer:

This can be achieved by having a class with a Method other than a constructor that returns the object that has to be shared.

57: Which are the most common Immutable objects in Java?

Answer:

The most common Immutable objects in Java are the

instances of the string class, where once a string is created; neither the developer nor the client can change its characters.

58: What are Constructor Methods?

Answer:

Constructor Methods resemble any other Methods, but Java has different rules that specifically govern the use of constructors and especially those that have special abilities to work with one another.

59: What are Java Constructor Methods?

Answer:

The Java Constructor Methods are special Methods which are governed by a number of semantic and syntactic rules. These rules are used because they are different from other objects in Java.

60: What are Superclasses in Java?

Answer:

Superclasses are developed when a class has no declared constructor and Java has to supply one by default; if the first statement in a constructor is not a specific invocation of another construction, then Java inserts a call to the

super() Method.

61: How can a call to the super() Method be avoided in Java?

Answer:

This can be achieved by invoking in an explicit manner a superclass constructor or by invoking another constructor of the current class with a call to this() Method.

62: What are Construction Oriented Patterns used for?

Answer:

Construction Oriented Patterns are designs which allow a client to construct new objects through different means other than calling a class constructor.

63: What is the Builder Pattern used for in Design Patterns?

Answer:

The Builder Pattern is used to move the construction logic for an object outside the class to instantiate; this is done to either reduce the size of the class that has many Methods or to allow step by step construction of a target object.

64: What is the Factory Method Pattern used for?

Answer:

The Factory Method Pattern is used to let a class developer define the interface for creating an object while retaining control of which class to instantiate.

65: How can the Factory Method be recognized as working in Design Patterns?

Answer:

To see if the Factory Method is working the developer has to check if the operation creates a new object, then returns the type that is an interface and that it is implemented by several classes.

66: What does the Iterator Pattern do?

Answer:

The Iterator Pattern is used mainly to provide a way to access the elements of collection sequentially.

67: What are the iterator() Methods used for?

Answer:

The iterator() Methods are mainly a part of the factory Method patterns and are used for creating an object that returns a sequence of the elements of a collection.

68: What is a Parallel Hierarchy in Design Patterns?

Answer:

A Parallel Hierarchy is a pair of class hierarchies where classes in one hierarchy have a corresponding class in the other hierarchy.

69: What is the Abstract Factory Pattern used for?

Answer:

The Abstract Factory Pattern is used, most of the time, to provide for the creation of the family of related, or dependent, objects.

70: What is the Prototype Pattern used for?

Answer:

The Prototype Pattern is used for allowing a client to create new object by copying an example with the major difference between calling a constructor and copying an object being that a copy typically includes some of the original object.

71: What is a Memento in Design Patterns?

Answer:

A Memento is a small repository that saves an object’s state and that also provides storage and restoration of an

object’s state.

72: How is a Memento created in Design Patterns?

Answer:

A Memento can be created by using another object, a string or a file, with the anticipated duration between the storage and the reconstruction of an object having an effect on the strategy that can be used in its design.

73: What is Persistent Storage?

Answer:

Persistent Storage is used to fulfill the intent of the Memento Pattern and it is a natural extension to the undo functionality that the developer implements in his program.

74: What does Object Serialization do?

Answer:

Object Serialization is used to provide a simple means for a Memento to persist across multiple sessions that occur; for an example in a particular week.

75: What does the java.io package do?

Answer:

The java.io package is used to provide support for an object deserialization when its class has changed since the serialization was written.

76: How can Persistent Storage of an object be achieved?

Answer:

Persistent Storage of an object can be achieved by writing a textual description of it and by saving an object’s data as an XML file or even in a proprietary language chosen by the designer.

77: What is the difference between an Operation and a Method as specified by the UML?

Answer:

The difference is that an Operation is a specification of a service that can be requested from an instance of a class and a Method is an implementation of a class.

78: What is an Algorithm?

Answer:

An Algorithm is a sequence of instructions that accept inputs and produces output; it is mainly similar to a Method, but an algorithm requires more than one Method to execute in an object oriented program.

79: What is Polymorphism?

Answer:

Polymorphism is the principle that Method invocation depends on both the operation that is to be invoked and also the class of the invocation receiver.

80: When does the Term Operation apply?

Answer:

The Term Operation applies when discussing the idea that Methods in different classes most of the time have the same interface; it always refers to the specification of a service.

81: When does the Term Signature apply?

Answer:

The Term Signature applies when discussing the rules that govern how Java matches a call to a Method in the receiving object.

82: What does a Method Declaration in Java include?

Answer:

A Method Declaration in Java includes the header and the body, with the body being a series of instructions that are called in action by invoking the Method’s signature and the header including the Method return type and the modifiers.

83: What does the Sorting Method do?

Answer:

The Sorting Method has different algorithms used, but most of the times the developer can choose only one to sort various collections of objects.

84: What is a Hook Method?

Answer:

A Hook is a Method call that the developer places in his code to give other developers a way and a chance to insert code at a specific spot in a procedure.

85: What is a Template Method?

Answer:

The Template Method functions as a contract between developers, where a developer may supply an algorithm and another developer may supply a certain step of an algorithm.

86: What is a State of an object?

Answer:

The State of an object is a combination of the current values of the object’s attributes; it is usually a prominent aspect of the object’s behavior.

87: How can Transition between States be handled?

Answer:

Transition between States can be handled by having the developer allow for the states to retain a context reference that contains a set of states.

88: What does the State Pattern do?

Answer:

The State Pattern is sued for code simplification by distributing an operation across a collection of classes that represent an object’s various states.

89: What is a Strategy?

Answer:

A Strategy is a plan or approach, similar to an algorithm that pursues an output given a set of inputs.

90: What is the use of a Strategy Pattern?

Answer:

A Strategy Pattern is used to encapsulate alternative strategies in different classes that in turn implement a common operation; this results in a clean and simple code.

91: What does the Command Pattern do?

Answer:

The Command Pattern is used to establish the signature of a Method, most of the time with the execute() or perform() Methods; it also allows for defining different implement-tations of an interface.

92: What does an Interpreter Pattern do?

Answer:

An Interpreter Pattern is used to distribute an operation across a collection of classes, just like the state and strategy patterns would.

93: What is the use of an interpreter object?

Answer:

An Interpreter Object is used to run the execution of a collection of rules, allowing for the developer to build expression evaluators and command languages.

94: What does a Parser Object do?

Answer:

A Parser is an Object used to recognize text and take apart its structure according to a set of rules into a form suitable for further processing.

95: What is an Extension in Design Patterns?

Answer:

An Extension represents the addition of a class, an interface and/or Method to an already existing code base; the main way to extend code is to write a new class or extend a certain class through delegation.

96: When does Extension through Delegation occur?

Answer:

This process takes place when a class has Methods that forward calls to identical operations that are supplied by another object; this process makes available the behavior of the forwarded class on the class that the developer wishes to extend.

97: What is the purpose of a Decorator Pattern?

Answer:

A Decorator Pattern is used to allow the developer to compose an object’s behavior dynamically by combining polymorphism with delegation, which results in the extension of an object’s behavior.

98: What is a Stream in Design Patterns?

Answer:

A Stream is a serial collection of bytes of characters like those that appear in a document; in Java each stream object most of the time contains another stream object to which it forwards its operations.

99: What does the next() Method do in Design Patterns?

Answer:

The next() Method is used to check if a certain value is loaded and then checks if it has reported the interior node of the composite that is traversed.

100: How is Iteration achieved in a Multi Thread Application?

Answer:

This can be achieved by synchronization of the monitor on a mute object, the developer can then block all access while iterating or block access for a short period of time to make a clone of the collection.

101: What is Façade Pattern used for?

Answer:

The Façade Pattern deals with a subsystem of classes. A subsystem of classes consists of a set of classes that work in conjunction with each other for the purpose of

providing a set of related features (functionality).

102: What is the meaning of a subsystem in real world applications?

Answer:

In real world applications, a subsystem could comprise of a large number of classes. Clients of a subsystem may need to interact with a number of subsystems classes for their needs. This kind of direct interaction of clients with subsystems classes leads to a high degree of coupling between the client’s objects and the system. Whenever a subsystem class undergoes a change, such as change in its interface, all of its dependent client classes may get affected.

103: Main advantage of the Façade Pattern?

Answer:

The Façade Pattern provides a higher level, simplified interface for a subsystem resulting in reduced complexity and dependency. This in turn makes the subsystem usage easier and more manageable.

104: What provides the Façade Pattern?

Answer:

A Façade is a class that provides a simplified interface for a subsystem to be used by clients. With a Façade object in place, clients interact with the Façade object instead of interacting directly with subsystem classes. The Façade object takes up the responsibility of interacting with subsystem classes.

105: What should you know when applying the Façade Pattern?

Answer:

A Façade should not be designed to provide any additional functionality. Also one should never return subsystem components from Façade Methods to clients.

[Proxies](#tmp_f353b6c4930e82b6df695a2b6a8bbd14_uEhiwq.ch.fixed.fc.tidied.stylehacked.xfixed_split_003.html_TOC)

106: What are the characteristics of a Proxy Object?

Answer:

A Proxy Object is an intermediary between a client object and the target object. It receives calls from a client object and forwards them to the target object.

107: What is the difference between Proxy and Decorator?

Answer:

The Proxy client object cannot access the target object directly. The Decorator client object does have the ability to access the target object directly (if needed).

A Proxy object provides access control to the target object; the Decorator object does not control access to the target object.

108: What about the functionality added to an object by Proxy and Decorator object?

Answer:

A Proxy object does not add any additional functionality, but the Decorator adds additional functionality to an object.

109: What does a Remote Proxy do?

Answer:

The Remote Proxy is used to provide access to an object located in a different address space.

110: What does a Virtual Proxy do?

Answer:

A Virtual Proxy is used to provide the required function-ality to allow the on-demand creation of a memory intensive object (unless required).

111: What does a Cache Proxy/Server Proxy do?

Answer:

These two kinds are used to provide the functionality required to store the results of most frequently used target operations. The Proxy Objects stores these results in some kind of repository. When a Client Object requests the same operation, the proxy returns the operation results from the storage area without actually accessing the target object.

112: What does Firewall Proxy do?

Answer:

The primary use of a Firewall Proxy is to protect target objects from the bad clients. A Firewall Proxy can also be used to provide the functionality required to prevent clients from accessing harmful targets.

113: What does Protection Proxy do?

Answer:

The Protection Proxy is used to provide the functionality required for allowing different clients to access the target object at different levels. A set of permissions is defined at the time of creation of the proxy. Subsequently, those permissions are used to restrict access to specific parts of the proxy (in turn of the target object). A Client Object is not allowed to access a particular Method if it does not have a specific right to execute the Method.

114: What does Synchronization Proxy do?

Answer:

The Synchronization Proxy is used to provide the required functionality to allow safe concurrent access to a target object by different client objects.

115: What does Smart Reference Proxy do?

Answer:

The Smart Reference Proxy is used to prevent the accidental disposal/deletion of the target object when there are clients currently with references to it. To accomplish this, the proxy keeps a count of the number of references to the target object. The proxy deletes the target object if and when there are no references to it.

116: What does Counting Proxy do?

Answer:

The Counting Proxy is used to provide some kind of audit mechanism before executing a Method on the target object.

117: What is the difference between Proxy and Façade?

Answer:

A Proxy Object represents a single object and the Façade represents subsystems of objects. The Proxy Object provides access control to the single target object. The Façade Object provides a simplified higher level interface to a subsystem of components.

118: What about the Client Object Access to the target?

Answer:

In the case of Proxy, the Client Object cannot access the target object directly, but for the Façade, the Client Object does have the ability to access the subsystem objects

directly, if needed.

119: What is the difference between Proxy and Chain of Responsibility?

Answer:

A Proxy Object contains a single object, and the Chain can contain many objects. Client requests are first received by the Proxy Object, but are never processed directly by the Proxy Object. In the case of Chain of Responsibility, client requests are forwarded to the next object in the chain only if the current receiver cannot process the request.

120: What happens with the response to the request in the case of these two patterns?

Answer:

In the case of Proxy Pattern, the response to the request is guaranteed, provided the communication between the client and the server locations is working.

In the case of Chain of Responsibility, the response is not guaranteed. It means that the request may end up reaching the end of the chain and still might not be processed.

121: What does the concept of Remote Method

Invocation mean in Java?

Answer:

In Java, the concept of Remote Method Invocation (RMI) is a way to program distributed code. It makes extensive use of Remote Proxy Pattern.

122: What does the RMI do?

Answer:

The Remote Method Invocation enables a client object to access remote objects and invoke Methods on them as if they are local objects.

123: What are the RMI Components?

Answer:

The following components working together provide the stated RMI functionality:

a. Remote Interface,

b. Remote Object,

c. RMI Registry,

d. Client,

e. RMIC- Java RMI Stub Compiler.

124: What represents the Remote Interface?

Answer:

A Remote Object must implement a Remote Interface (one that extends java.rmi.Remote). A Remote Interface declares the Methods in the Remote Object that can be accessed by its clients. In the other words, the Remote Interface can be seen as the client's view of the Remote Object.

125: What are the requirements to provide a Remote Interface?

Answer:

The requirements are to extend the java.rmi.Remote interface and all the Methods in the remote interface must be declared to throw java.rmi.RemoteException exception.

126: What is the responsibility of Remote Object?

Answer:

A Remote Object is responsible for implementing the Methods declared in the associated Remote Interface.

127: What are the requirements to provide a Remote Object?

Answer:

It must provide implementation for a Remote Interface, it must extend java.rmi.server.UnicastRemoteObject. Also it must have a constructor with no arguments and it must be associated with a server. The server creates an instance of the remote object by invoking its zero argument constructors.

128: What is RMI Registry?

Answer:

The RMI Registry provides the storage area for holding different remote objects. A remote object needs to be stored in the RMI registry along with a name reference to it for a client object to be able to access it. Only one object can be stored with a given name reference.

129: What represents the Client for RMI?

Answer:

The Client is an application object attempting to use the Remote Object. It must be aware of the interface implemen-ted by the remote object. It can search for a Remote Object using a name reference in the RMI Registry. Once the remote object reference is found, it can invoke Methods on this object reference.

130: What represents the RMIC: Java RMI Stub Compiler?

Answer:

Once a remote object is compiled successfully, RMIC Stub Compiler can be used to generate Stub and Skeleton class files for the remote object. Stub and Skeleton classes are generated from the compiled remote object class. These Stub and Skeleton classes make it possible for a client object to access the remote object in a seamless manner.

131: What is the RMI Communication Mechanism?

Answer:

Normally, a client object cannot directly access a remote object. In order to make this possible, the RMIC generates Stub of the remote object class and the remote interface needs to be copied to the client computer.

132: How does the RMI Communication Mechanism work?

Answer:

The Stub acts as a Remote Proxy for the remote object and it is responsible for forwarding Method invocations on the remote object to the server where the actual remote object implementation resides. Whenever a client references the remote object, the reference is made to a local Stub. The Stub forwards this call to the remote server. On the server the RMIC generates skeleton of the remote object receives this call. The skeleton is a server side object and it does not need to be copied to the client computer.

133: What is the responsibility of the Skeleton?

Answer:

The Skeleton is responsible for dispatching calls to the actual remote object implementation. Once the remote object executes the Method, results are send back to the client in the reverse direction.

134: What is the connection between RMI and Proxy Pattern?

Answer:

The Stub class is acting as a remote proxy for the remote object and this makes possible for a client to treat a remote object as if it is available locally. Thus, any application that uses RMI contains an implicit implementation of the Proxy pattern.

135: What is a Virtual Proxy?

Answer:

A Virtual Proxy Pattern is a memory saving technique that recommends postponing an object creation until it is truly

needed.

136: What is the advantage of using a Virtual Proxy?

Answer:

The advantage of using a Virtual Proxy is that the application has a faster start up time because it is not required to create and load all of the application objects.

137: What is the disadvantage of using a Virtual Proxy?

Answer:

The disadvantage of using a Virtual Proxy is that the object that is accessed has to be checked to make sure that it is not null after the object is created.

138: What happens when one applys a Virtual Proxy Pattern?

Answer:

When a Virtual Proxy Pattern is applied, a separate object referred to as Virtual Proxy can be designed with its interface the same as that of the actual object.

139: What is the Counting Proxy used for?

Answer:

The Counting Proxy is used to design a set of operations

like logging that need to be performed before and after a client object invokes a Method.

140: What is an Aggregate Object?

Answer:

An Aggregate Object represents the union of other objects, which in turn carry themselves objects of their own.

141: What happens when an Aggregate Object is constructed?

Answer:

When an Aggregate Object is constructed, all of its member variables that represent a set of constituting objects have to be initialized.

Answer:

There are two types of Aggregate Relationships. They are:

a. Aggregation

b. Composition.

143: What happens when Aggregation takes place?

Answer:

When Aggregation takes place, the parts that make up the

Aggregate object can exist without a meaning, without the parent of the Aggregate object.

144: What happens when Composition takes place?

Answer:

During the process of Composition, the set of constituting objects that are in relation with the Aggregate object cannot exist meaningfully without the Aggregate object.

145: What happens to an object during early Initialization?

Answer:

During early Initialization, an Aggregate object is always treated as a union of Constituting objects, meaning that an Aggregate object cannot exist without its constituting objects.

Early Initialization reveals any problems with the construction of any of the Constituting objects at the time of constructing the parent Aggregate itself.

JVM stands for Java Virtual Machine and it is responsible for reclaiming the memory that has been allocated to objects when they go out of scope.

An object that goes Out of Scope is marked as eligible for garbage collection, although the collection does not begin immediately.

150: What does the concept of Caching mean?

Answer:

The process of Caching takes place when an object is kept in memory in any form, with the goal of providing a faster response time to a client request.

151: What does the Command Pattern do?

Answer:

The Command Pattern is used to allow requests to be repacked into an object, thus giving control over request queuing, sequencing and undoing.

152: What does the Mediator Command do?

Answer:

This command encapsulates the direct object to object communication details along a set of objects in a separate object and eliminating the need for the objects to interact with each other directly.

153: What does the Memento Command do?

Answer:

The Memento Command allows a state of an object to be captured and then stored; also the object can be placed back to its previous state when the need arises.

154: What does the Observer Command do?

Answer:

This command promotes a publisher to subscriber communication model when there are too many dependencies between objects so that when one objects changes state, all the others are notified so that they can update their state.

The Null Object Command provides a way of encapsulating

*Review these typical interview questions and think about how you would answer them. Read the answers listed; you will find best possible answers along with strategies and* *suggestions.*

1: Tell me about yourself?

Answer:

The most often asked question in interviews. You need to have a short statement prepared in your mind. Keep your answer to one or two minutes. Don’t ramble. Be careful that it does not sound rehearsed. Limit it to work-related items unless instructed otherwise. Talk about things you have done and jobs you have held that relate to the position you are interviewing for. Start with the item farthest back and work up to the present (If you have a profile or personal statement(s) at the top of your CV use this as your starting point).

2: Why did you leave your last job?

Answer:

Stay positive regardless of the circumstances. Never refer to a major problem with management and never speak ill of supervisors, co- workers or the organization. If you do, you will be the one looking bad. Keep smiling and talk about leaving for a positive reason such as an opportunity, a chance to do something special or other forward- looking reasons.

3: What experience do you have in this field?

Answer:

Speak about specifics that relate to the position you are applying for. If you do not have specific experience, get as close as you can.

4: Do you consider yourself successful?

Answer:

You should always answer yes and briefly explain why. A good explanation is that you have set goals, and you have met some and are on track to achieve the others.

5: What do co-workers say about you?

Answer:

Be prepared with a quote or two from co-workers. Either a specific statement or a paraphrase will work. Bill Smith, a co-worker at Clarke Company, always said I was the hardest worker’s he had ever known. It should be as powerful as Bill having said it at the interview herself.

6: What do you know about this organization?

Answer:

This question is one reason to do some research on the organization before the interview. Research the company’s products, size, reputation, Image, goals, problems, management style, skills, History and philosophy. Be informed and interested. Find out where they have been and where they are going. What are the current issues and who are the major players?

7: What have you done to improve your knowledge in the last year?

Answer:

Try to include improvement activities that relate to the job. A wide variety of activities can be mentioned as positive self-improvement. Have some good ones handy to mention.

8: Are you applying for other jobs?

Answer:

Be honest but do not spend a lot of time in this area. Keep the focus on this job and what you can do for this organization. Anything else is a distraction.

9: Why do you want to work for this organization?

Answer:

This may take some thought and certainly, should be based on the research you have done on the organization. Sincerity is extremely important here and will easily be sensed. Relate it to your long-term career goals. Never talk about what you want; first talk about their Needs. You want to be part of an exciting forward-moving company. You can make a definite contribution to specific company goals.

10: Do you know anyone who works for us?

Answer:

Be aware of the policy on relatives working for the organization. This can affect your answer even though they asked about friends not relatives. Be careful to mention a friend only if they are well thought of.

11: What kind of salary do you need?

Answer:

A loaded question! A nasty little game that you will probably lose if you answer first. So, do not answer it. Instead, say something like, that’s a tough question. Can you tell me the range for this position? In most cases, the interviewer, taken off guard, will tell you. If not, say that it can depend on the details of the job. Then give a wide range.

Answer:

You are, of course, a team player. Be sure to have examples ready. Specifics that show you often perform for the good of the team rather than for yourself is good evidence of your team attitude. Do not brag; just say it in a matter-of-fact tone. This is a key point.

Answer:

I'd like it to be a long time. Or As long as we both feel I'm doing a good job.

Answer:

This is serious. Do not make light of it or in any way seem like you like to fire people. At the same time, you will do it when it is the right thing to do. When it comes to the organization versus the individual who has created a harmful situation, you will protect the organization. Remember firing is not the same as layoff or reduction in force.

Answer:

The interviewer is not looking for a long or flowery dissertation here. Do you have strong feelings that the job gets done? Yes. That's the type of answer that works best here. Keep it short and positive, showing a benefit to the organization.

Pick a specific incident. Concentrate on your problem solving technique and not the dispute you settled.

46: What position do you prefer on a team working on a project?

Answer:

Be honest. If you are comfortable in different roles, point that out.

47: Describe your work ethic.

Answer:

Emphasize benefits to the organization. Things like, determination to get the job done and work hard but enjoy your work are good.

48: What has been your biggest professional disappointment?

Answer:

Be sure that you refer to something that was beyond your control. Show acceptance and no negative feelings.

49: Tell me about the most fun you have had on the job.

Answer:

Talk about having fun by accomplishing something for the organization.

50: What would you do for us? (What can you do for us that someone else can’t?)

a) Relate past experiences that represent success in Working for your previous employer.

b) Talk about your fresh perspective and the relevant experience you can bring to the company.

c) Highlight your track record of providing creative, Workable solutions.

51: Do you have any questions for me?

Answer:

Always have some questions prepared. Questions prepared where you will be an asset to the organization are good. How soon will I be able to be productive? What type of projects will I be able to assist on?
