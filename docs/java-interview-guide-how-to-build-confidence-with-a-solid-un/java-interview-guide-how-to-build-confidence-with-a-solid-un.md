## Java 编程语言

### Java 的历史

Java 是由 Sun Microsystems 于 1995 年推出的一种面向对象的编程语言。与 C++ 不同，它允许开发者编写可以在多个平台上运行的代码。这种原则被称为“一次编写，到处运行”（WORA），它避免了开发者为不同的操作系统编写不同的应用程序。Java 借鉴了 C++ 的大部分语法，但通过提供自动内存管理等功能以及消除多重继承等陷阱简化了开发工作。

### Java 虚拟机

WORA 原则的实现归功于 Java 虚拟机（JVM）。虚拟机是模拟物理机器的软件。在传统的编程语言中，代码被编译为特定平台的机器语言。在 Java 中，代码被编译为称为字节码（`bytecode`）的虚拟机语言。JVM 充当字节码和底层物理机器之间的中间媒介。

每个支持 Java 的平台都有自己的 JVM 实现。Java 应用程序是可移植的，因为每个 JVM 都遵循标准接口。JVM 和标准库的发行包称为 Java 运行环境（JRE）。JRE 和开发工具（如编译器和调试器）的发行包称为 Java 开发包（JDK）。

### 过程化编程 vs 面向对象编程

过程化编程是一种编写代码的风格，通过执行一系列线性过程来产生结果。面向对象编程是一种使用对象来封装状态和行为的代码编写风格。由于其无状态的特性，过程化代码在小型项目或多线程环境中更容易使用，但面向对象的代码要灵活得多且更易维护。

## 面向对象概念

### 抽象

抽象是从狭窄视角感知实体的行为。例如，在教育语境下，一个人可以被简化为学生；在就业语境下，一个人可以被简化为员工。每个抽象都将人的属性减少为相关信息的子集。抽象的目标是减少软件系统的复杂性。

### 封装

封装是一种通过故意隐藏信息来鼓励抽象的技术。例如，汽车发动机的机械细节被封装在方向盘和脚踏板之后。任何熟悉此接口的人都可以开车，而无需知道引擎盖下是什么类型的引擎。Java 通过使用接口以及提供限制类、字段和方法可见性的访问修饰符来鼓励封装。

### 多态性

多态性是一种通过允许实体承担多种形式来鼓励抽象的技术。例如，智能手机是多态的，因为它可以承担相机、网络浏览器、音乐播放器或数字钟的角色。每个应用程序都向用户暴露一个相关的接口。在 Java 中，对象可以采取其层次结构中任何父类的形式或任何接口的形式。

### 可变性

可变性指的是实体改变其状态的能力。iPod 是可变实体的例子，因为它的内容经常变化。黑胶唱片是不可变实体的例子，因为它的内容是永久刻制的。不可变对象在软件应用程序中提供了许多好处，例如稳定性和线程安全。`String` 和所有原始类型包装类都是不可变对象的示例。为了使一个对象变为不可变，该类必须是 `final` 的，所有字段必须是 `final` 的，并且不能暴露任何可变字段或修改可变字段的方法。

### 耦合

耦合指的是实体之间依赖程度。例如，焊接在主板上的手机电池是紧耦合的，因为在不影响另一个组件的情况下，无法替换电池或主板。卡扣式安装在手机背部的电池是松耦合的，因为这两个实体可以独立地替换。在软件应用程序中，解耦的组件更灵活且更易维护。

### 内聚性

内聚性指的是实体的关注点。例如，瑞士军刀是一个低内聚实体，因为它能做很多事情，但每项工作都做得不够好。多功能工具永远无法比一个充满高内聚性工具的工具箱更有生产力。在软件应用程序中，内聚性强的组件更健壮且更易于测试。

## 面向对象编程（第一部分）

### 类与对象

Java 对象是由称为“类”（`class`）的蓝图构建的。类定义了对象的名称、对象以字段（`fields`）的形式拥有的状态类型，以及对象以方法（`methods`）的形式拥有的行为。

当使用 `new` 关键字实例化对象时，类文件及其所有的父类都会被系统类加载器加载到 JVM 中。在类的一次初始化之后，对象将通过调用一个名为构造函数（`constructor`）的特殊方法进行初始化。构造函数在递归调用其所有父类的构造函数后执行初始化逻辑。在初始化子类之前必须初始化父类，因为子对象可能依赖父类的功能。

### 基本类型

基本类型是固定大小的数据类型，它是预定义的并保留作为关键字。基本类型是用于存储对象中状态的构建块。共有 8 种基本类型：`boolean`、`byte`、`short`、`int`、`long`、`float`、`double` 和 `char`。基本类型不是对象，但每个基本类型都有一个对应的包装对象（`wrapper object`）。

编译器可以通过一个名为“自动装箱”（`autoboxing`）的过程自动将基本类型转换为其包装对象。相反，编译器可以通过一个名为“自动拆箱”（`unboxing`）的过程将包装对象转换为其基本类型。自动拆箱的一个常见陷阱发生在 `null` 对象引用被拆箱为基本类型时，导致 `NullPointerException`。

### 数组

数组是一个可以持有固定数量单类型值的对象。数组的容量在数组初始化时定义，并且可以通过从零开始的索引访问其元素。数组是协变的（`covariant`），这意味着数组可以强制转换为其父类类型的数组。例如，`String[]` 可以强制转换为 `Object[]`，因为 `String` 类继承了 `Object` 类。

### 字符串

字符串是表示文本的唯一对象。可以在不使用 `new` 关键字的情况下分配字符串值，尽管编译器实际上在内部创建了 `String` 对象。可以通过重载的 `+` 运算符进行字符串拼接，编译器会在创建不可变的 `String` 实例之前，将其转换为在 `StringBuilder` 的 `char[]` 缓冲区上的方法调用链。`StringBuilder`（以及线程安全的替代方案 `StringBuffer`）通过修改可变的 `char[]` 缓冲区来提高性能。字符串的不可变属性允许编译器在一个名为“内化”（`interning`）的过程中将其缓存。

### 枚举

枚举（`Enums`）是枚举类型的缩写，是表示一组单例常量的特殊类。实际应用包括一周的几天、任务的状态级别或安全组的角色。引入枚举是为了取代 `String` 和 `Integer` 常量，它们要强大得多，因为它们可以包含方法、实现接口并提供类型安全。然而，枚举不能被子类化或扩展除了隐式继承的 `Enum` 类之外的任何类。

### 包

类和其他资源被组织在具有唯一命名空间的文件夹中，这些文件夹被称为“包”（`packages`）。包通常按照两种竞争性的方法论进行组织：按层级分包（`package-by-layer`）和按功能分包（`package-by-feature`）。

按层分包策略根据类在应用程序中的层级将类分组。例如，按层分包的结构可能包含模型（`model`）、控制器（`controller`）、服务（`service`）、DAO 和工具（`utility`）包。按层分包适用于小型应用程序，但由于跨越较少包的紧耦合类过多，它的可扩展性并不良好。

按功能分包策略根据类在应用程序中的内聚性将类分组。例如，按功能分包的结构可能包含客户（`customer`）、订单（`order`）、产品（`product`）、评论（`review`）和报告（`report`）包。按功能分包鼓励高模块化和松耦合，优于按层分包。

## 面向对象编程（第二部分）

### 方法

方法包含了提供行为的逻辑。方法声明包含修饰符、返回类型、方法名、参数类型及其对应的名称以及可抛出的异常。方法签名是参数的组合。注意，参数名称不包含在方法签名中。

方法可以通过一个名为递归（`recursion`）的过程调用自身。递归是循环的替代方案，提供了自然重复的问题，例如数学序列或分治算法。没有终止条件的递归方法最终会导致 `StackOverflowError`。

### 引用传递与值传递

传递给方法的方式取决于编程语言是引用传递还是值传递。例如，想象在放风筝并将风筝的控制权传递给朋友。引用传递类似于将线系给他们，而值传递则需要系一个重复的风筝并传递它。在这两种情况下，朋友都可以对风筝施加影响，但在引用传递中朋友可以更改指向的对象。

Java 中的所有参数都是值传递的。对于基本类型参数，基本类型的值复制并传递给方法。对于对象参数，对象的指针被复制并传递给方法。

### final 关键字

`final` 关键字决定对象引用在赋值后是否可以更改。在风筝的例子中，使用 `final` 关键字类似于将线胶在手上。`final` 关键字通常与 `static` 关键字结合使用创建常量。但是要注意 `final` 关键字并不防止对象的内部状态改变。`final` 关键字也可以应用于类级别以防止子类扩展该类，或应用于方法级别以防止子类重写方法。

### static 关键字

`static` 关键字决定属性是属于类还是属于对象实例。例如，想象拿着一个房屋的蓝图。不同房屋之间唯一的属性（例如窗户或门的数量）是实例属性的示例。写在蓝图上的属性（例如建造房屋的数量）是静态属性的示例。对象可以访问类的静态属性，但类在没有对象引用的情况下无法访问实例属性。

### 访问修饰符

访问修饰符决定了类、字段和方法的可见性，以便隐藏信息以降低复杂度。四种访问修饰符有：

- `public`（公有的）：对所有类可见。
- `protected`（保护的）：对子类和同一包中的类可见。
- `<无>`（默认）：对同一包中的类可见。
- `private`（私有的）：仅对当前类可见。

### 注解

注解可以应用于字段、方法、类和包，用以在代码中嵌入元数据。注解本身对代码库没有影响，但它们可以在编译时或运行时被检测，以提供额外功能。例如，`@Override` 注解可以用于重写父类方法的方法，允许编译器防止由于无效的方法签名导致的错误。`@Column(name)` 注解可以将字段映射到数据库列，允许数据访问对象在运行时动态生成 SQL 查询语句。

## Object 超类

Java 中的每个类都直接或间接地是 `Object` 类的后代。`Object` 类提供了几个方法，可以在子类中可选地扩展它们。

### 克隆

`clone()` 方法最初设计用于返回实现 `Cloneable` 接口的对象的副本。克隆既可以是**浅拷贝**（与原始对象共享相同的引用），也可以是**深拷贝**（将原始对象的值复制到新对象中）。遗憾的是，正确地重写此方法是非常困难的，而且它并没有拷贝构造函数的优势，拷贝构造函数提供了更大的灵活性和更整洁的契约。

### 相等性

`equals()` 方法比较两个对象的相等性。默认实现依赖于标识符（`==`）来判断两个对象是否指向内存中的相同地址。鼓励子类重写此方法，以测试两个对象是否包含相同的信息，而不是内存中的相同位置。请注意，如果你重写了 `equals()` 方法，根据约定你也必须重写 `hashCode()` 方法。

### 哈希码

`hashCode()` 方法将对象的状态处理成一个整数，这对于哈希表数据结构非常有用。默认情况下，哈希值是通过将对象的内部地址转换为整数来实现的。哈希值必须保持一致性，并且对于根据 `equals()` 方法相等的对象，必须始终返回相等的值。

### 字符串表示

`toString()` 方法返回对象的文本表示，主要用于日志记录和调试。默认情况下，`toString()` 方法返回对象的类名，随后是其哈希码的十六进制表示。

### 获取类

`getClass()` 方法返回一个 `Class` 对象，其中包含有关类的信息以及用于反射访问字段和方法的工具方法。`getClass()` 方法是 `final` 的，不能被子类重写。

### 最终化

`finalize()` 方法最初设计在对象被垃圾回收器销毁之前调用。然而，如果一个对象从未被解除引用，或者应用程序在垃圾回收器运行之前退出，则该对象可能不会进入垃圾回收状态。由于其不确定性以及对象可能通过创建额外的引用而被无意“复活”的可能性，通常不建议依赖此方法进行清理操作。

### 等待、通知、全通知

最终类方法 `wait()`、`notify()` 和 `notifyAll()` 提供了底层并发操作，允许线程之间的通信。例如，一个线程可以停止执行，直到收到来自另一个线程的通知。Java 在 `java.util.concurrent` 包中提供了更高级并发数据结构。

## 组合与继承

### 组合

组合是一种通过将功能委托给其他对象来防止代码重复的技术。例如，`Party` 类可以将方法调用委托给一个 `List` 对象，以便为宾客列表提供功能。这允许 `Party` 类选择性地暴露 `addGuest()` 等方法，而不是暴露 `List` 接口中的所有方法。

### 继承

继承是一种通过从父对象继承功能来防止代码重复的技术。例如，`Party` 类可以扩展 `ArrayList` 来为宾客列表提供功能。这允许 `Party` 对象被用于增强 for 循环或接受 `List` 的方法中。不允许多重继承，以防止父类在独立实现相同功能时产生的歧义。这种歧义由于生成的对象层次结构的形状被称为“菱形问题”（或“死亡菱形”）。

### 方法重写 vs 方法重载

方法重写允许子类更改父类的功能。这发生在子类定义了一个与父类方法具有相同方法签名的非静态方法时。从 Java 5 开始，重写的方法可以声明相同的返回类型或协变（子类）返回类型。即使对象被强制转换为其父类类型，重写的方法也会被调用。

方法重写经常与方法重载混淆。当一个类中的两个或多个方法具有相同名称但不同的方法签名时，就会发生方法重载。方法重载通过允许客户端调用方法的适当版本，而无需为可选参数传递空值，从而为 API 提供了灵活性。

### 组合 vs 继承

组合和继承都提供代码复用，但很难确定哪种关系更合适。作为一条通用规则，询问两个对象之间是“拥有”（HAS-A）关系还是“是”（IS-A）关系。例如，一个派对“拥有”一个宾客列表，因此 `Party` 应该由一个 `List` 组成。另一方面，一个学生“是”一个人，因此 `Student` 应该继承自 `Person`。



虽然两种方法都是强大的，但它们各自都有缺点。组合需要委托代码，并在没有引入额外接口的情况下阻止了多态。继承强制了类与类之间的紧耦合。在疑问时，组合是优选方法，因为它比继承更灵活。

## 抽象类与接口

### 抽象类

抽象类设计用于扩展，且不能实例化。例如，抽象类 `Person` 可能包含通用属性，并依赖 `Employee` 和 `Student` 等具体子类提供额外功能。抽象类可以同时包含具体方法和抽象方法，但它只能通过在对象层次中实现所有抽象方法的具体子类来实例化。

### 接口

接口通过描述对象可以的形式来促进多态性。例如，想象一个对纳税人员感兴趣的政府机构。与其代码库与 `Student` 和 `Employee` 对象紧密耦合，他们不如引入一个 `Taxable` 接口并要求人们提供自己的实现。接口只能包含常量字段和空方法。一个类可以实现多个接口，但它必须为每个方法提供实现（重复的方法被视为一个）。

### 抽象类对比接口

认为抽象类和接口在功能上竞争是一个常见的误区；实际上它们经常协作工作。例如，Java 的 `AbstractList` 类部分实现了 `List` 接口的方法，减轻了 `ArrayList` 和 `LinkedList` 等子类的负担。总的来说，抽象类用于规划继承层次结构并简化子类的工作。接口用于引入抽象层并解耦代码模块。

## 匿名类

为了减少语言的冗长性，Java 允许使用 `new` 关键字实例化匿名类。例如，Swing 应用中的每个按钮都有一个 `ActionListener`，该监听器在按钮被点击时会被调用。与其为每个操作创建一个新的类文件，你不如声明实现 `ActionListener` 接口的匿名类。

匿名类提供了对闭包的支持。闭包是一个代码块，它可以在被传递的同时，保持对闭层作用域中变量的访问。例如，一个更改 Swing 应用标题的按钮需要一个闭包来访问窗口框架。虽然匿名类看起来可以直接访问闭层变量，但实际上，这些变量是按照方法参数相同的方式（值传递）进行复制的。为了防止歧义，所有闭层变量在被匿名类访问之前必须声明为 `final`。

Java 8 以 Lambda 表达式的形式为闭包提供了更为简洁的支持。Lambda 表达式是包含单个方法的匿名类的单行表示法。

## 异常

异常是特殊的对象，当错误中断代码的正常执行时就会被抛出。所有异常都是 `Throwable` 类的子类，并分为两类：未检查异常和检查异常。

### 未检查异常

未检查异常表示应用程序中的缺陷，例如在空对象引用上调用方法，或将对象强制转换为无效类型。方法可以抛出未检查的异常，而无需强制其调用者建立错误处理策略。未检查异常继承自 `RuntimeException` 类。常见的未检查异常包括 `NullPointerException`、`IllegalArgumentException` 和 `ClassCastException`。

### 检查异常

检查异常表示发生在应用程序控制之外的缺陷，例如打开一个不存在的文件或使用无效凭据连接数据库。抛出检查异常的方法会强制其调用者建立错误处理策略。调用者必须将方法封装在 `try/catch` 块中，或者将异常添加到其方法声明中，以将责任进一步推向调用栈顶部。检查异常继承自 `Exception` 类。常见的检查异常包括 `IOException`、`FileNotFoundException` 和 `InterruptedException`。

## 未检查异常 vs 检查异常

检查异常一直是 Java 社区中争议的焦点，因为它们经常被误用。官方文档指出：“如果可以合理预期客户端能从异常中恢复，请将其变为检查异常。如果客户端无法采取任何操作从异常中恢复，请将其变为未检查异常。”当不确定时，优先选择未检查异常，因为它允许客户端选择是否合适的错误处理策略适当。

## 错误

`Error` 是由 JVM 抛出的，用于表示发生了致命条件。`Error` 直接继承自 `Throwable` 类，这使得它们具有未检查异常的行为。常见的错误包括 `OutOfMemoryError` 或 `StackOverflowError`。

## Try/Catch/Finally

Java 提供了三个用于建立错误处理策略的关键字。`try` 关键字界定了一个可能抛出异常的代码块。`catch` 关键字指定特定类型异常的处理器。在 `try` 块内抛出的异常将由第一个 `catch` 块捕获，该块的异常类型要么与抛出的异常匹配，要么是抛出异常的父类。

`finally` 关键字界定了一个无论是否抛出异常都会被调用的代码块。`finally` 块通常用于提供清理操作。例如，尝试更新数据库的代码可能会被一个 `finally` 块封装，因为无论更新是否成功，都应该关闭数据库连接。

### Try-With-Resources

Java 7 引入了 `try-with-resources` 语句，它允许实现 `AutoCloseable` 接口的资源被声明为 `try` 块内部的参数。当 `try` 块完成时，会自动调用资源的 `close()` 方法。

## 泛型

### 编译时错误 vs 运行时错误

编译时错误是阻止程序编译的错误。运行时错误是在执行期间发生的错误，例如非法类型转换。编译时错误更容易修复。运行时错误更难检测并可能导致不可预测的行为，因此应在编译阶段尽可能捕获。

### 泛型

泛型的引入是为了防止由于类型转换引起的运行时错误。泛型是为了类型安全。如果没有泛型，实现 `List` 将需要类型转换。

### 泛型通配符

与数组不同，泛型是不变的，这意味着泛型对象不共享相同的关系。例如，泛型上界通配符 `? extends Number` 允许 `Number` 类型及其所有子类。下界通配符 `? super Number` 允许 `Number` 类型及其所有父类。

## 类型擦除

为了保持后向兼容性，泛型类型被编译器移除并替换为对象转换，这一过程被称为类型擦除。类型擦除消除了重新编译旧代码的需求，但也引入了一些限制。例如，泛型异常是不允许的，因为 `catch` 块无法区分 `GenericException<String>` 和 `GenericException<Integer>`。

## 并发

Java 通过使用线程支持并发编程。线程是应用程序中的单一执行路径。JVM 通常作为单进程启动，产生多个共享其资源的线程。修改共享资源的线程必须经过协调以防止不可预测的行为。

### 线程生命周期

线程通过实例化 `Thread` 类的子类，或通过带有 `Runnable` 参数实例化 `Thread` 对象来产生。当调用 `start()` 方法时，线程进入可运行状态。JVM 使用基于优先级的调度算法来决定执行哪个线程。当调度程序调用 `run()` 方法时，线程进入运行状态。然而，如果需要获取锁或等待另一个线程的通知，线程可能会进入阻塞状态。线程在 `run()` 方法完成后销毁。

### 同步

可变资源需要同步，因为多个线程的操作可能会交错执行。例如，`c++` 操作看起来可能是原子的，但它实际上由三个步骤组成：读取 c 的值、增加 c 的值和写入 c 的值。如果一个线程读取了 c 的值并进入阻塞状态，另一个线程可能会读取相同的值，计数器只会增加 1。同步访问 `c++` 操作将强制所有三个步骤原子地完成。

虽然同步可以防止线程干扰和内存一致性错误，但它可能会降低性能并引发死锁的可能性。当两个线程互相等待对方执行时，就会发生死锁。

#### synchronize 关键字

`synchronized` 关键字用于指定同步方法和语句。同步代码块由一个锁保护，该锁一次只能由一个线程获取。在 `synchronized` 静态方法中，隐式使用单例类对象作为锁。在 `synchronized` 非静态方法中，对象实例被隐式地用作锁。在 `synchronized` 语句中，必须作为参数提供锁。多个锁允许实现更细粒度的同步级别。

例如，假设有一个带有 `synchronized count()` 方法的 `Counter` 类。如果 `count()` 方法是静态的，那么应用程序中同一时间只有一个线程可以增加计数器。如果 `count()` 方法是非静态的，则可以实例化多个 `Counter` 对象并并发地进行增加。如果 `Counter` 类有两个变量和两个独立的 `count()` 方法，每个方法可以使用带有不同锁的 `synchronized` 语句，这样两个变量就可以并发地增加。

#### volatile 关键字

`volatile` 关键字用于指示变量的值可能会被多个线程修改。Java 内存模型允许线程为了性能缓存变量的值。如果一个方法依赖于共享变量的最新值，则必须使用 `volatile` 关键字。例如，一个执行 `while (!finished)` 循环的方法，如果另一个线程负责更新其值，则该方法需要将 `finished` 变量声明为 `volatile`。

内存写入对另一个代码块可见的保证被称为“先发生之前”（happens-before）关系。`volatile` 关键字和 `synchronized` 关键字都保证了“先发生之前”关系，但 `synchronized` 关键字还保证了对代码块的原子性访问。

### 并发数据结构

Java 5 在 `java.util.concurrent` 包中引入了若干高层数据结构。`CopyOnWriteArrayList` 是 `ArrayList` 的线程安全替代方案，它仅在修改时复制底层数组。`ConcurrentHashMap` 是 `HashMap` 的线程安全替代方案，仅在被修改的映射分段上产生同步开销。`BlockingQueue` 的引入是为了允许生产者在队列满时阻塞等待，并允许消费者在队列空时阻塞等待。

### 执行器框架

执行器框架为多线程任务执行提供了一层抽象。`ExecutorService` 管理一个接受 `Runnable` 或 `Callable` 任务的线程池。提交任务会立即返回一个 `Future` 对象，该对象包含返回运行任务状态和结果的方法。执行器框架有效地将任务与其执行策略解耦。

### ThreadLocal 存储

`ThreadLocal` 类允许将值存储在当前运行的 `Thread` 对象内部。例如，想象追踪一个从 servlet 开始并穿过服务的 HTTP 请求。与其在每个方法中将事务 ID 作为参数传递，不如将其存储在 `ThreadLocal` 对象中，并在沿途中静态地获取它。`ThreadLocal` 变量减少了方法的冗长性，但必须确保在线程返回线程池之前移除了该值。

### 原子变量

Java 引入了若干具有内置并发特性的变量，如 `AtomicInteger`、`AtomicLong` 和 `AtomicBoolean`。例如，`AtomicInteger` 可以替换甚至优于我们的 `Counter` 类，因为它通过原生方法调用实现。原生方法调用在 JVM 之外以一种依赖于平台的编程语言执行。

## 内存管理

### 堆内存

Java 对象存在于称为“堆”的动态大小内存区域中。堆被分为年轻年代对象和老年代对象。在典型的应用程序中，大多数对象都是短命的。为了提高性能，存活的对象会被迁移到老年代堆空间，在那里它们在年轻年代堆空间的激进垃圾回收期间会被忽略。

### 垃圾回收

当堆满时，会自动调用垃圾回收程序。垃圾回收器识别不再被应用程序引用的对象并将其删除以释放内存。可以通过 `System.gc()` 方法手动调用垃圾回收器，但无法保证该过程何时开始。

用于垃圾回收的算法被称为“标记-清除”。在第一步中，识别并标记内存中被引用的对象。在第二步中，删除未标记的对象，释放内存块。剩余内存可以被压缩成连续的块，其过程类似于对硬盘进行碎片整理。

### 强引用

强引用是一种典型的引用，例如将对象赋值给变量或将对象放入数组。对对象的强引用保证了该对象将保留在堆上。如果一个对象无法通过任何强引用链被访问，则该对象就符合垃圾回收条件。

强引用会随着时间的推移而积累。当应用程序使用的内存超过分配的堆空间时，结果是 `OutOfMemoryError`。幸运的是，Java 提供了不同的引用对象来防止此问题。当应用程序填满堆时，结果就是内存泄漏。

### 内存泄漏

尽管 Java 有自动内存管理，但内存泄漏仍然可能。例如，想象托管世界上最大的数据库。为了提高性能，我们可以使用 `ConcurrentMap` 通过将名称与 `User` 关联来缓存一颗星星。然而，随着更多用户查找星星，我们的缓存会像黑洞一样增长，直到耗尽所有空间。

内存泄漏通常难以定位，因为产生的 `OutOfMemoryError` 可能从应用程序的任何部分抛出。调试内存泄漏通常需要性能分析器的帮助。分析器可以分析 JVM 崩溃时创建的堆转储，重建引用层次以确定大部分内存被保留的位置。

### 软引用

软引用是一种可以通过调用 `SoftReference` 容器的 `get()` 方法获取的对象。软可及对象不会被激进地垃圾回收，使得它们非常适合缓存。例如，如果我们在映射中存储 `SoftReference<Star>` 值，我们的缓存将增长直到填满堆，此时 `get()` 方法将开始返回 `null`。

### 弱引用

弱引用是一种只能通过调用 `WeakReference` 容器的 `get()` 方法获取的对象。弱可及对象会被激进地垃圾回收，使得它们非常适合短暂的对象关联。例如，如果我们允许用户编辑星星，我们可以使用 `ConcurrentMap` 通过将名称与 `User` 关联来同步对星星的访问。然而，如果用户过早关闭浏览器，星星将残留在映射中。假设 `User` 也作为强引用存储在会话对象中，可以使用 `WeakReference<User>` 来确定会话何时过期，因为在会话垃圾回收后 `get()` 方法将返回 `null`。

### 引用队列

在我们两个示例中，存在一个微妙的问题。我们的 `SoftReference<Star>` 缓存会自动移除 `Star` 对象，但我们仍可以用键和空 `SoftReference` 容器填满映射。幸运的是，Java 以 `ReferenceQueue` 的形式提供了一种优雅的解决方案。

`ReferenceQueue` 是一个传递给引用对象构造函数的队列。当被引用类封装的对象被垃圾回收时，该 `Reference` 会被放入 `ReferenceQueue`。然后可以对该队列进行清理操作。如果我们对 `SoftReference` 和 `WeakReference` 类建模以存储星星名称，我们就有了一个用于移除过期映射条目的方便的回调。

### 幻引用

幻引用是一个封装在 `PhantomReference` 容器中的对象。然而，在 `PhantomReference` 上调用 `get()` 方法始终返回 `null`。幻引用结合引用队列提供了一种比 `finalize()` 方法更安全的替代方案，因为不存在通过新引用复活死对象的可能性。

### 连接



# Connection 接口

Connection 接口封装了与数据库的通信。Connection 由 `DriverManager` 或 `DataSource` 提供。`DriverManager` 需要如 url 和凭据等连接细节，而 `DataSource` 在接口后隐藏了连接细节。`DataSource` 通常由应用服务器通过名为 Java 命名和目录接口（JNDI）的查找服务提供。`DataSource` 比 `DriverManager` 更优，因为它更灵活且更容易更改。

## 语句

Statements 由 Connection 提供，用于封装 SQL 查询。`PreparedStatements` 由数据库进行预编译，对于重复执行或包含输入参数的查询提高了性能。`CallableStatements` 用于执行包含输入和输出参数的存储过程。

## 结果集

ResultSets 由 Statements 提供，用于封装查询结果。`ResultSet` 包含一个游标，可以遍历各个行并提取类型安全的值。根据数据库的能力，`ResultSets` 可以配置为支持双向滚动以及行修改。

## SQL 注入

SQL 注入是一种流行的攻击向量，允许将恶意查询嵌入到通过字符串拼接构建的 Statements 中。可以通过使用 `PreparedStatements` 注册输入值来防止 SQL 注入。

Servlet API 提供了 servlet 容器的规范。servlet 容器通过将请求委托给 Web 应用来处理 HTTP 请求，而应用程序会将请求委托给 Servlet。

Web 应用被打包成名为 WAR 文件的 Web 存档。WAR 文件包含类、库以及名为 `web.xml` 的部署描述符。部署描述符是一个描述应用程序如何部署的配置文件。例如，`web.xml` 文件告诉 servlet 容器哪些 URL 模式映射到 Servlets。

## Servlets

Servlets 是由 servlet 容器管理的单例对象。当 servlet 初始加载时，容器调用 `init()` 方法。传入的请求并发委托给 `service()` 方法。最后，当应用程序关闭时，容器调用 `destroy()` 方法。

`HttpServlet` 是 Servlet 的实现，包含与 HTTP 请求相对应的方法，如 `doGet()`、`doPost()`、`doPut()` 和 `doDelete()`。`HttpServlet` 提供了对请求参数的访问，以及一个可以跨请求存储状态的会话对象。会话通过浏览器 cookie 中的标识符进行关联。

## JavaServer Pages

Servlets 在通过 Java 代码构建 HTML 文档方面是著名的笨拙。JavaServer Pages (JSP) 是文本文档，通过使用标签和统一表达式语言 (EL) 静态和动态内容。JSPs 被编译为 Servlets，并对请求和响应对象具有隐式访问。

Servlets 和 JSPs 经常通过 `RequestDispatcher` 协同工作。`RequestDispatcher` 将请求控制从一个资源转移到另一个资源。例如，servlet 通常处理请求的逻辑并委托给 JSP 渲染响应。

## 过滤器

过滤器拦截 servlet 请求以提供交叉切点功能。例如，安全过滤器可以将未身份验证的用户重定向到登录页面。过滤器映射到部署描述符中的 URL 模式。

## 模型-视图-控制器

模型-视图-控制器 (MVC) 是一种鼓励 Web 应用中关注点分离的设计模式。模型（Model）表示领域对象，例如从数据库检索的数据。视图（View）是模型的可视化，例如构建 HTML 文档的 JSP。控制器（Controller）促进模型的更改，例如处理表单提交的 Servlet。存在多个框架来促进 MVC 模式，例如 Spring MVC。

# Web 服务

## 面向服务的架构

面向服务的架构 (SOA) 是一种通过网络向客户端提供服务的模式。服务跨越广泛的应用程序，从发送电子邮件到生成随机数。

## Web 服务

Web 服务是 SOA 在互联网上的实现。Web 服务暴露了独立于平台或编程语言的契约。两种最流行的实现方式是简单对象访问协议 (SOAP) 和表象性状态转移 (REST)。

## SOAP

SOAP 是一种通信协议，它使用 XML 定义服务描述语言 (WSDL)。WSDL 文档描述的 API 可以被调用者解析以自动生成类。Java XML Web 服务 API (JAX-WS) 提供了通过注解生成基于 SOAP 的 Web 服务的规范。Apache CXF 是 JAX-WS 流行的开源实现。

## REST

REST 是一种仅依赖 HTTP 协议设计 Web 服务的模式。REST Web 服务暴露了意义的 URL，利用 GET、POST、PUT 和 DELETE 方法访问资源。REST 架构没有规定标准数据格式，但 JSON 经常作为 XML 的轻量级替代方案。Java RESTful Web 服务 API (JAX-RS) 提供了通过注解生成基于 REST 的服务的规范。Jersey 是 JAX-RS 流行的开源实现。

## SOAP vs REST

当需要严格的契约来支持紧耦合系统之间的复杂操作时，SOAP Web 服务非常有用。REST Web 服务更灵活，但缺少 WSDL 文档对于复杂服务来说可能是不可接受的。由于 XML 负载的冗余，SOAP Web 服务通常比 REST 慢。

# 算法

## 大 O 表示法

大 O 表示法用于衡量操作相对于输入规模的复杂度。

- O(1) 描述复杂度与输入无关的算法，例如通过索引访问数组中的元素。
- O(n) 描述复杂度随输入线性增长的算法，例如遍历数组。
- O(n^2) 描述复杂度呈平方级增长的算法，例如将数组中的每个元素与数组中的其他所有元素进行比较。
- O(log n) 描述复杂度呈对数增长的算法，例如不断将数组对半直到只剩一个元素。
- O(n log n) 描述复杂度呈对数级增长的算法，例如将数组对半并对每个半部分进行遍历。

## 二分查找

二分查找是一种 O(log n) 算法，用于在排序的项列表中查找值。它通过在列表中间查找值，并递归地丢弃超出范围的一半列表来工作。如果列表未排序，则二分查找的结果是不确定的。`Arrays` 和 `Collections` 类提供了二分查找方法。

## 排序算法

### 插入排序

插入排序是一种平均复杂度为 O(n^2) 的排序算法。它通过遍历列表并通过原地交换元素来对之前的元素进行排序。

### 合并排序

合并排序是一种稳定的平均复杂度为 O(n log n) 的排序算法。它通过递归地将列表拆分为单个子列表，并合并每个子列表以产生排序结果。合并排序是分治算法的一个示例，该算法递归地将问题简化为平凡的解决方案。

### 快速排序

快速排序是一种不稳定的平均复杂度为 O(n log n) 的排序算法。它通过定义一个基准（pivot）并交换元素，使得较小的值位于基准之前，较大的位于基准之后。剩余的基准被递归排序。从 Java 7 开始，快速排序是 `Arrays` 类中排序基本类型的默认实现。

### Timsort

Timsort 是一种稳定的平均复杂度为 O(n log n) 的排序算法。Timsort 是一种源自合并排序和插入排序的混合算法。它通过识别自然排序的数据序列（runs）或使用插入排序创建最小尺寸的序列来工作。这些序列以与合并排序相同的方式合并。由于 Timsort 能够利用部分排序的值，其比较次数通常少于 O(n log n)。从 Java 7 开始，Timsort 是 `Arrays` 和 `Collections` 类中排序对象的默认实现。

# JAVA 集合框架

## Java 集合框架

Java 集合框架 (JCF) 提供了实现 `Collection` 接口的常用数据结构。集合是泛型对象的抽象表示。

## List（列表）

List 是一个持有索引集合的数据结构。`ArrayList` 类使用索引数组来存储其值。如果超过了容量，则会将值复制到更大的数组中，但可以通过在构造函数中指定初始容量来避免。`ArrayList` 不是线程安全的，`CopyOnWriteArrayList` 是一个线程安全的替代方案。

`LinkedList` 类使用 Node 对象链来创建一个动态大小的列表。一个节点包含一个值，以及指向链中前一个节点和后一个节点的引用。这允许在不重组列表的情况下插入或删除节点，但需要遍历列表来通过索引访问元素。`LinkedList` 不是线程安全的，但可以通过 `Collections#synchronizedList` 方法进行装饰。

## Map（映射）

Map 是一个将键与值关联的数据结构。`HashMap` 类使用链表数组来存储 Entry 对象。一个条目包含一个键、一个值，以及指向链中下一个条目的引用。当你将一个键/值对放入 map 时，一个数学函数（如模运算符 `%`）会将键的哈希码限制在数组的索引上。映射到相同索引的唯一键会被链接在一起，但重复的键将覆盖现有的条目。当你通过键查找值时，会重新计算索引并检查链表中的每个条目，直到找到匹配的键。

`HashMap` 要求键正确实现 `hashCode()` 和 `equals()` 方法。如果哈希值不唯一，map 的性能将会下降，因为链表将不成比例地增长。如果哈希值不一致，条目可能会在 map 中丢失并内存泄漏。

如果 `HashMap` 的大小超过容量的 75%，数组将翻倍并对所有条目进行重新哈希。这可以通过在构造函数中指定初始容量和负载因子来避免。`HashMap` 不维护条目的插入顺序，但 `LinkedHashMap` 通过在辅助 `LinkedList` 中存储条目提供了该功能。`HashMap` 不是线程安全的，`ConcurrentHashMap` 是一个线程安全的替代方案。

## Deque（双端队列）

Deque（双端队列）是一种可以两端插入或检索值的数据结构。按照后进先出（LIFO）策略移除元素的双端队列称为栈。按照先进先出（FIFO）策略移除元素的双端队列称为队列。`ArrayDeque` 类使用对象数组存储其值。`ArrayDeque` 可以作为栈或队列，在相同用途下通常优于 `Stack` 和 `LinkedList` 类。`ArrayDeque` 不是线程安全的，`ConcurrentLinkedDeque` 是一个线程安全的替代方案。

## Binary Search Tree（二分查找树）

二分查找树 (BST) 是一种在分层树中排序节点的数据结构。红黑树是 BST 的一种实现，根据其位置为每个节点着色。相邻节点的颜色可以决定树是否平衡。不平衡的树会退化为 O(n) 查找，因此在插入或删除节点后使用平衡操作，以保证在 O(log n) 时间内查找。

`TreeMap` 是红黑树的实现，使用条目节点存储其值。Entry 对象包含一个键、一个颜色，以及指向其父条目、左条目和右条目的引用。`TreeMap` 根据键的自然排序或由 `Comparator` 提供的排序策略存储其条目。自然排序的树要求键在 `Comparable` 接口中正确实现 `compareTo()` 和 `equals()` 方法。`TreeMap` 按排序顺序遍历其条目。`TreeMap` 不是线程安全的，但可以通过 `Collections#synchronizedSortedMap()` 方法进行装饰。

## Heap（堆）

堆是一种无序数据结构，在分层树中组织节点。在最大堆中，父节点的值始终大于其子节点的值。在最小堆中，父节点的值始终小于其子节点的值。

堆是优先级队列的高效实现。优先级队列根据优先级提供元素，并在优先级相同时退到 FIFO 策略。`PriorityQueue` 类使用对象数组存储其值。尽管堆在视觉上表示为树，但它们可以紧凑地存储在数组中，并通过索引运算定位节点。`PriorityQueue` 不是线程安全的，`PriorityBlockingQueue` 是线程安全的。

## Set（集合）

Set 是一个持有唯一值集合的数据结构。Sets 通常将功能委托给 map，因为 map 的键已经是唯一的。`HashSet` 利用 `HashMap`，它不维护元素的插入顺序。`LinkedHashSet` 利用了 `LinkedHashMap`，它通过辅助的 `LinkedList` 维护插入顺序。`TreeSet` 利用了 `TreeMap`，它维护其元素的自然排序。这些类都不是线程安全的，但 `Collections.newSetFromMap()` 方法可以创建一个基于 `ConcurrentHashMap` 的集合。

## 迭代器 (Iterator)

迭代器是一个可以访问和移除集合中元素的对象。快速失败迭代器（fail-fast iterator）如果检测到在其 `remove()` 方法之外对集合发生了结构性变化，将抛出 `ConcurrentModificationException`。安全迭代器（fail-safe iterator）不会抛出异常，因为它在原始集合的副本上进行操作。

# 重要接口

## Autocloseable

`Autocloseable` 接口用于 try-with-resources 块以清理资源。`Autocloseable` 定义了一个 `close()` 方法，该方法会在 try-with-resources 块完成后由 JVM 调用。

## Comparable

`Comparable` 接口确定了同类型对象之间的自然排序。`Comparable` 定义了一个泛型 `compareTo(T)` 方法，返回一个整数，表示一个对象是小于、等于还是大于另一个可比较的对象。`Comparable` 对象的列表可以在 `Collections.sort(List)` 方法中排序。

## Comparator

`Comparator` 接口确定了同类型对象之间的排序策略。它可以用于对未实现 `Comparable` 的对象进行排序，或者以一种不同于其自然排序的方式对对象进行排序。`Comparator` 定义了一个泛型 `compare(T, T)` 方法，返回一个整数，表示第一个对象小于、等于还是大于第二个对象。可以通过 `Collections.sort(List, Comparator)` 方法使用比较器对列表进行排序。

## Iterable

`Iterable` 接口定义了一个返回迭代器的方法。实现 `Iterable` 的对象可以用于增强型 for 循环（enhanced for-loop）。注意，虽然数组可以在增强型循环中使用，但它们没有实现 `Iterable` 接口。

## Runnable

`Runnable` 接口封装了在线程内部运行的动作。`Runnable` 定义了一个 `run()` 方法，该方法在线程转换到可运行状态后由线程调度器调用。

## Callable

`Callable` 接口封装了在线程内部运行并计算结果的任务。`Callable` 定义了一个泛型 `call()` 方法，该方法返回结果或抛出异常。`Callable` 贯穿执行器框架。

## Serializable

`Serializable` 接口是一个标记接口，表示对象具备被序列化的条件。序列化是将对象转换为存储在文件系统中或通过网络传输的字节的过程。可以通过实现三个特殊的私有方法提供自定义的序列化逻辑：`writeObject()`、`readObject()` 和 `readObjectNoData()`。每个可序列化类都被分配了一个名为 `serialVersionUID` 的可配置版本号，用于确保反序列化过程中的兼容性。

# 设计模式与核心技术指南

## 创建型设计模式

构建者模式为具有大量参数的构造函数提供了一种替代方案。构建者对象通过链式的流式方法调用，临时存储新对象的状态，直到在最后一步中构建出目标对象。Google Guava 库中的 `MapMaker` 类就是构建者模式的示例。

### 工厂模式

工厂模式提供了抽象类或接口的实例，而不会让客户端承担实现细节的负担。这对于封装复杂的创建逻辑或为了性能而利用对象池非常有用。`Calendar.getInstance()` 方法是工厂模式的示例。

### 抽象工厂模式

抽象工厂模式也被称为工厂的工厂，它提供了工厂类的实例，而不会让客户端承担实现细节的负担。这对于封装一组相关工厂类的创建逻辑非常有用。`DocumentBuilderFactory` 类是抽象工厂模式的示例。

### 原型模式

原型模式通过原型创建一个克隆对象。当一个对象的创建开销极其昂贵（例如数据库查询的结果）时，这种方法非常有用。`Object.clone()` 方法是原型模式的示例。

### 单例模式

单例模式将类的实例化限制为单个实例。单例比全局变量更好，因为它们可以被延迟初始化，尽管某些实现需要显式的同步来完成。`Runtime.getInstance()` 方法是单例模式的示例。

## 结构型设计模式

结构型设计模式解决了由于不同对象之间的关系而产生的常见问题。

### 适配器模式

适配器模式将不兼容的对象转换为模块接受的格式。这允许不同的代码模块之间进行通信而不会产生耦合。`Arrays.asList()` 方法是适配器模式的示例。

### 组合模式

组合模式将对象集合视为单个对象。当一组对象共享相似的功能时（例如 Swing 应用程序中的元素），这种方法非常有用。`Container.add()` 方法是组合模式的示例。

### 装饰器模式

装饰器模式通过包装对象来为对象提供额外的行为。这为创建多个子类提供了一种灵活的替代方案。`Collections.unmodifiableList(List)` 方法是装饰器模式的示例。

### 外观模式

外观模式为大量的代码提供了一个简化的接口。当系统复杂或设计不当，且客户端只对部分功能感兴趣时，这种方法非常有用。SL4J 库中的 `Logger` 接口是外观模式的示例。

### 享元模式

享元模式通过复用对象来减少应用程序的内存占用。当频繁实例化大量不可变对象时，这种方法非常有用。`Integer.valueOf(String)` 方法是享元模式的示例。

## 行为型设计模式

行为型模式解决了由于对象之间的交互而产生的常见问题。

### 命令模式

命令模式封装了执行动作所需的所有信息。对于需要在创建上下文之外调用的操作，这种方法非常有用。`Runnable` 接口是命令模式的示例。

访问者模式将算法与其操作的对象结构分离开。当不同的算法需要遍历复杂对象中进行相似的路径时，这种方法非常有用。`ElementVisitor` 接口是访问者模式的示例。

## 反射

反射允许程序在运行时操作对象，而无需在编译时了解该对象。例如，如果你想调试一个没有重写 `toString()` 方法的对象，可以使用反射来检查每一个字段。反射之所以可能，是因为存在一组代表编程结构的类，如 `Class`、`Field` 和 `Method`。

### Class

`Class` 是由 JVM 构建的特殊对象，代表应用程序中的类和接口。如果你将类文件视为对象的蓝图，那么可以将 `Class` 类视为“蓝图的蓝图”。可以通过调用 `getClass()` 方法从对象获取 `Class` 实例，也可以通过 `Class.forName()` 方法通过其全限定名进行查找。

`Class` 为对象提供了类型内省。类型内省允许程序在运行时检查对象的属性。例如，`Class` 对象包含了内省方法，如 `getName()`、`getDeclaredFields()` 和 `getDeclaredMethods()`。`Class` 还可以使用 `newInstance()` 方法创建对象。这在需要实例化 XML 文件定义的对象的框架中被广泛使用。

### Field

`Field` 提供了对类或接口中单个字段的访问。`Field` 包含了内省方法，允许你从字段中获取值，同时也包含了反射方法，允许你向字段中设置值。然而，必须通过 `setAccessible()` 方法在 `Field` 对象上设置标记，以允许访问可见性有限的字段。

### Method

`Method` 对象提供了对类或接口中单个方法的访问。`Method` 包含了内省方法，可以提供有关方法声明的信息，同时也包含了反射方法，允许你调用该方法。然而，必须通过 `setAccessible()` 方法在 `Method` 对象上设置标记，以允许访问可见性限制的方法。

### 优缺点

反射是一种强大的工具，在 Java 库的无数扩展中起着至关重要的作用，例如测试框架、IoC 容器、ORM 映射器、性能分析器和调试器。另一方面，Java 是一种强类型语言，提供了稳健的编译时检查，而这种保护在反射中很大程度会丢失。反射还允许访问预期范围之外的字段和方法，从而破坏了封装。最后，由于 JVM 上的额外开销，反射的性能比非反射代码慢。

## 依赖注入

### 控制反转

控制反转（IoC）是一种将软件组件与其依赖项解耦的模式。例如，一个密码找回服务可能需要访问一个可以发送电子邮件的服务。一个控制其依赖项的密码服务需要直接实例化并配置电子邮件服务。而一个对依赖项具有反转控制的密码服务将由其他对象提供电子邮件服务。放弃对依赖项控制的服务更加灵活，因为可以在不更改服务任何代码的情况下提供不同的实现。例如，在测试期间可以注入一个模拟电子邮件服务，以避免发送邮件或模拟失败。

### 服务定位器 vs 依赖注入

IoC 的两种常见实现方式是服务定位器模式和依赖注入。服务定位器为对象请求依赖项提供了一个中心存储库。依赖注入进一步利用了反转原则，允许容器通过构造函数参数或 setter 方法直接将依赖项注入到组件中。

### 构造函数注入 vs Setter 注入

构造函数注入要求组件为每个依赖项声明一个带有参数的构造函数。这允许任何初始化逻辑在构造函数中运行，但具有多个依赖项的组件可能有复杂的构造函数声明。Setter 注入要求组件为每个依赖项声明 setter 方法。Setter 注入更加灵活，但任何初始化逻辑必须在所有依赖项注入之后进行。在任何情况下，都需要一个容器来管理组件与其依赖项之间的关系。

### Spring 容器

Spring 框架是 Java 语言最流行的扩展之一。尽管 Spring 库已扩展到许多领域，该库的核心是一个依赖注入容器。Spring 容器负责实例化、配置并将组件（称为 bean）注入到运行中的应用程序。

### Spring 配置

Spring 容器需要配置来定义 bean 及其在应用程序中的关系。配置可以以 XML、注解或 Java 代码的形式提供。XML 配置由于其直观性被广泛使用，但它容易受到重构错误的影响，因为类和包名通常会发生变化。注解提供了 XML 的替代方案，但生成的配置是分散的，任何更改都要求修改源码。Java 配置文件结合了 XML 的集中配置和注解的便利性，但缺乏 XML 提供的某些灵活性。

### Spring 生命周期

Spring 容器通过使用可用配置选项之一实例化 `ApplicationContext` 开始。容器实例化所有 bean，并通过构造函数注入、setter 注入或反射注入它们的依赖项。最后，容器会调用 bean 上挂钩到生命周期的回调方法。例如，容器将在任何实现 `InitializingBean` 的 bean 上调用 `afterPropertiesSet()`。

## 面向切面编程

### 核心关注 vs 横切关注

核心关注是对应用程序业务逻辑有贡献的工作单元，例如在数据库中存储记录或生成报告。横切关注是跨越核心关注并支持应用程序的功能，例如日志记录或缓存。

### 面向切面编程

面向切面编程（AOP）通过切面的使用隔离横切关注。切面的工作方式是针对一个方法（称为连接点，join point）并在周围封装额外的代码。连接点由一个称为切点（pointcut）的表达式确定。例如，为了找到应用程序中最慢的方法，你可以声明一个针对所有公共方法的切点，并比较每个连接点执行前后的时间。

### 代理对象

实现面向切面编程的一种简单方法是使用代理对象。代理是一个包装器，可以为感兴趣的对象提供额外功能。代理可以通过接口或继承来实现。

### 接口代理

实现接口的对象可以由实现相同接口的另一个类代理。例如，为了记录 `ArrayList` 的每个方法调用，你可以创建一个实现 `List` 的 `ProxyList` 类，并将每个方法委托给一个私有的 `ArrayList`。

每个委托方法都提供了一个可以被日志代码包裹的连接点。

该代理可以传递给任何接受 `List` 的方法。然而，接口代理的一个局限性是组合对象内部的任何自调用方法都不会被代理。例如，如果 `ArrayList` 中的 `remove()` 方法内部调用了 `get()` 方法，那么该调用将不会被记录，因为连接点永远不会被触发。

### 继承代理

非最终（non-final）的对象可以由扩展它的类进行代理。例如，为了记录 `ArrayList` 上的每个方法调用，你可以创建一个扩展 `ArrayList` 的 `ProxyList`，并重写每个方法，通过对 `super()` 的委托调用。每个重写的方法都提供了一个可以被日志代码包裹的连接点。

该代理可以传递给任何接受 `List` 或 `ArrayList` 的方法。然而，继承代理的一个局限性是最终（final）类和最终方法无法被代理。

### 运行时织入 vs 二进制织入

织入是将切面和对象链接在一起的过程。代理对象是运行时织入的示例，可以通过纯代码模式实现。二进制织入则将切面直接注入字节码中。二进制织入可以在编译时通过自定义编译器进行，也可以在加载时通过自定义类加载器进行。二进制织入没有接口代理或继承代理的所有局限性，但它通常需要专用库的帮助。

### AspectJ

AspectJ 是一种广泛使用的 AOP 框架，支持编译时织入、加载时织入以及针对外部类的编译后织入。AspectJ 通常与 Spring 框架使用，Spring 为切面以及运行时织入提供了额外的支持。

## 单元测试

### 测试驱动开发

测试驱动开发鼓励编写松耦合、高内聚且频繁测试的代码模块。TDD 周期从为不存在的功能编写自动化测试用例开始。然后，开发者产生使测试成功的最少代码。随着越来越多的测试用例的加入，会形成一个全面的测试套件，能够检测并防止由新功能导致的 bug。

TDD 也可以用于修复。在修复 bug 之前编写测试用例可以确定修复是否有效，同时保证 bug 永远不会再次出现。

### 单元测试

单元测试依赖断言来验证代码的行为。如果未满足预期，断言将抛出错误，例如字段与预期值不匹配。如果单元测试在完成时没有触发任何断言或抛出任何异常，则测试成功。Java 提供了 `assert` 关键字，但它依赖于 JVM 参数来启用，因此最好使用更灵活的框架。JUnit 是一个流行的单元测试框架，它包含了丰富的断言 API 以及对测试固件的支持。

### 测试固件

测试固件是对象的固定状态，作为运行测试的基准。例如，测试固件可以丢弃并重建内存数据库，以便允许数据访问测试在每次测试执行后都在干净的数据集上运行。

### 模拟对象

模拟对象模仿那些因不实际而不纳入单元测试的对象的行为。例如，每次运行单元测试时都给信用卡充值或发射导弹是极其高昂的。模拟对象实现了与其所模仿的对象相同的接口，允许开发者在不修改被测试代码的情况下模拟控制场景。模拟对象可以手动创建，但像 Mockito 等框架提供了强大的代理，可以追踪并验证方法调用的行为。

## 编程问题

### 如何处理编程问题

在面试期间，你可能会被要求解决高级编程问题。为了展示健康的解决问题方法，请遵循以下步骤：

1. 复述问题以确保你正确理解了它。
2. 提供一个简单的解决方案，无论效率如何。
3. 批判你的解决方案并对其进行优化分析。

识别问题的本质可以帮助你解决它。例如，需要重复步骤的问题适合递归。涉及数据集合的问题通常会利用现有的数据结构。练习解决示例题，学习发现解决方案的过程，而不是记忆解决方案本身。

### 示例编程问题

#### 你会如何写一个计算数字阶乘的方法？

阶乘是一个整数及其下方所有整数的积（4! = 4*3*2*1）。阶乘是一个自然的递归操作，如果你将公式可视化为解决方案的一部分（4*3*2*1），这一点是显而易见的。该公式可以被转换为递归方法调用：`n * factorial(n-1)`。然而，递归算法的第一行应该定义一个终止条件。在这里，输入为 1 不需要递归，因为结果仅仅是 1。

由于方法调用的开销，递归方法比循环要慢。可以通过创建一个向终止条件迈进并更新局部变量状态的循环，将递归方法转换为迭代方法。在实践中，你应该始终优先考虑简单性优于过早优化，但在面试语境下，你应该尽可能保持批判性。

#### 你会如何判断一个字符串是否是回文？

回文是一个正向读和反向读都相同的单词。一个简单的解决方案是反转字符串并与原始字符串进行比较。`String` 类没有反转方法，但你可以使用 `StringBuilder.reverse()` 方法或递归公式：`hello = reverse(hell)`。

与其创建额外的实例，更有效的解决方案是使用带有双指针的 `String.charAt()` 方法。如果指针在汇合前每个字符都匹配，则该字符串是回文。

#### 你会如何验证括号是否平衡？

为了简化这个问题，你可以忽略无关字符并将所有的括号添加到字符串中。然后，你可以递归地遍历字符串并移除每一对相邻的开闭括号 `()`。当字符串不再有配对时，剩余的字符将决定括号是否平衡。

作为一种优化，每当你向字符串添加闭括号时，都可以检查上一个字符是否是开括号并丢弃它们。事实上，如果这样做，就不需要递归了，因为你实际上是在将字符串当作栈处理。这一点，你可以使用 `ArrayDeque` 推入和弹出开括号，并在结束后检查栈是否为空。

#### 给定一个 1 到 100 缺失一个数字的无序列表，你会如何确定缺失的数字？

解决问题的简单方案是遍历列表 100 次，并在每次迭代中搜索特定值。然而，应该批评任何平方时间运行的解决方案。如果你先对列表进行排序，可以在线性对数时间内找到与相应索引不符的数字。更快的方法是你可以将每个值放入 `HashSet` 中，在线性时间内找到缺失值。

无法比线性时间更快地解决这个问题，但重要的是，时间复杂度只衡量算法的增长率。事实上，可以通过计算所有数字之和并从由公式 $n(n+1)/2$ 提供的总和中减去它来更有效地解决这个问题。每当你批判一个解决方案时，当时间复杂度不再是因素时，记住考虑内存。
