
# Java 尝试使用资源

> 原文：<https://jenkov.com/tutorials/java-exception-handling/try-with-resources.html>

Java *try with resources* 构造，又名*Java try-with resources*，是一种异常处理机制，可以在您使用完资源时自动关闭资源，如`Java InputStream`或`JDBC`连接。为此，您必须打开并使用 Java *try-with-resources* 块中的资源。当执行离开 *try-with-resources* 块时，在 *try-with-resources* 块中打开的任何资源都将自动关闭，无论是否从 *try-with-resources* 块内部或在试图关闭资源时抛出任何异常。

这个 *Java try-with-resources 教程*解释了 *Java try-with-resources* 构造如何工作，如何正确地使用它，以及如何处理从 *try-with-resources* 块内部以及在关闭资源期间抛出的异常。

## 用资源尝试

为了了解 Java *try-with-resources* 构造是如何工作的，让我们看一个 Java *try-with-resources* 的例子：

```
private static void printFile() throws IOException {
    try(FileInputStream input = new FileInputStream("file.txt")) {
        int data = input.read();
        while(data != -1){
            System.out.print((char) data);
            data = input.read();
        }
    }
}
```

这个 *try-with-resources* 示例展示了如何在 *try-with-resources* 块中打开一个 Java `FileInputStream`，从 `FileInputStream` 中读取一些数据，并在执行离开 *try-with-resources* 块（未明确显示）时自动关闭 `FileInputStream`。

注意上面的 *try-with-resources* 示例中方法内的第一行：

```
try(FileInputStream input = new FileInputStream("file.txt")) {
```

这是 *尝试资源* 构造。`FileInputStream` 变量在 `try` 关键字后的括号内声明。此外，一个 `FileInputStream` 被实例化并赋给变量。

当 `try` 块完成时，`FileInputStream` 将自动关闭。这是可能的，因为 `FileInputStream` 实现了 Java 接口 `java.lang.AutoCloseable`。实现该接口的所有类都可以在 *try-with-resources* 构造中使用。

## 使用资源进行尝试 Java 9 增强

在 Java 9 之前，必须在 *try-with-resources* 构造的 *try* 块的括号内创建自动关闭的资源。从 Java 9 开始，这就不再需要了。如果引用资源的变量实际上是 final，那么只需在 *try* 块括号内输入对该变量的引用。下面是 Java 9 *try-with-resources* 增强的一个例子：

```
private static void printFile() throws IOException {
    FileInputStream input = new FileInputStream("file.txt");
    try(input) {
        int data = input.read();
        while(data != -1){
            System.out.print((char) data);
            data = input.read();
        }
    }
}
```

注意 `input` 变量现在是如何声明的，并且在 *try* 块之外分配了一个 `FileInputStream`。还要注意，`input` 变量是如何在 *try* 块的括号内引用的。这样，一旦退出 *try* 块，Java 仍然会正确关闭它。

## 使用多种资源

您可以在 Java *try-with-resources* 块中使用多个资源，并让它们自动关闭。下面是一个在 *try-with-resources* 块中使用多个资源的例子：

```
private static void printFile() throws IOException {
    try(
        FileInputStream input = new FileInputStream("file.txt");
        BufferedInputStream bufferedInput = new BufferedInputStream(input)
    ) {
        int data = bufferedInput.read();
        while(data != -1){
            System.out.print((char) data);
            data = bufferedInput.read();
        }
    }
}
```

这个例子在 *try* 关键字后的括号内创建了两个资源。一个 `FileInputStream` 和一个 `BufferedInputStream`。当执行离开 *try* 块时，这两个资源都会自动关闭。

### 地产禁用令

Java *try-with-resources* 构造中声明的资源将以与括号中创建/列出它们的顺序相反的顺序关闭。在上一节的例子中，首先关闭 `BufferedInputStream`，然后关闭 `FileInputStream`。

## 自定义可自动关闭的实现

Java *try-with-resources* 构造不仅仅适用于 Java 的内置类。您也可以在自己的类中实现 `java.lang.AutoCloseable` 接口，并将它们与 *try-with-resources* 构造一起使用。

`AutoClosable` 接口只有一个名为 `close()` 的方法。界面看起来是这样的：

```
public interface AutoClosable {
    public void close() throws Exception;
}
```

任何实现这个接口的类都可以与 Java *try-with-resources* 构造一起使用。下面是一个简单的实现示例：

```
public class MyAutoClosable implements AutoCloseable {
    public void doIt() {
        System.out.println("MyAutoClosable doing it!");
    }

    @Override
    public void close() throws Exception {
        System.out.println("MyAutoClosable closed!");
    }
}
```

`doIt()` 方法不是 `AutoClosable` 接口的一部分。它在那里是因为我们希望能够做一些事情，而不仅仅是关闭对象。

下面是一个如何将 `MyAutoClosable` 与 *try-with-resources* 构造一起使用的示例：

```
private static void myAutoClosable() throws Exception {
    try(MyAutoClosable myAutoClosable = new MyAutoClosable()){
        myAutoClosable.doIt();
    }
}
```

下面是调用方法 `myAutoClosable()` 时打印到 `System.out` 的输出：

```
MyAutoClosable doing it!
MyAutoClosable closed!
```

如您所见，*try-with-resources* 是一种非常强大的方法，可以确保在 `try-catch` 块中使用的资源被正确关闭，无论这些资源是您自己创建的，还是 Java 的内置组件。

## 用资源尝试异常处理

Java *try-with-resources* 块的异常处理语义与标准 Java *try-catch-finally* 块的异常处理语义略有不同。在大多数情况下，修改后的语义会比原来的 *try-catch-finally* 块的语义更好地为您服务，即使您没有准确理解其中的区别。即便如此，在 *try-with-resources* 构造中，实际理解异常处理方式是一个好主意。因此，我将在这里解释 *try-with-resources* 构造的异常处理语义。

如果从 Java *try-with-resources* 块中抛出异常，那么在 *try* 块的括号中打开的任何资源仍然会自动关闭。异常的抛出将强制执行离开 *try* 块，这将强制自动关闭资源。一旦资源被关闭，从 *try* 块内部抛出的异常将会在调用栈中向上传播。

当您试图关闭某些资源时，它们也可能会引发异常。当您试图关闭某个资源时，如果该资源抛出异常，在同一个 *try-with-resources* 块中打开的任何其他资源仍将被关闭。关闭所有资源后，失败的关闭尝试的异常将在调用堆栈中向上传播。如果多个资源关闭尝试引发了多个异常，那么遇到的第一个异常将是在调用堆栈中向上传播的异常。其余的异常将被抑制。

如果从 *try-with-resources* 块内部抛出异常，并且当资源关闭时（当 `close()` 被调用时），在 *try* 块内部抛出的异常将被向上传播到调用堆栈。尝试关闭资源时引发的异常将被抑制。这与普通 try-catch-finally 块中发生的情况相反，在普通块中，遇到的最后一个异常是向上传播到调用堆栈的异常。

为了更好地理解 Java *try-with-resources* 构造的异常处理语义，让我们看一些例子。对于这些例子，我创建了下面的 `AutoClosable` 实现，我可以在使用和试图关闭时强制抛出异常：

```
public class AutoClosableResource implements AutoCloseable {
    private String name = null;
    private boolean throwExceptionOnClose = false;

    public AutoClosableResource(String name, boolean throwExceptionOnClose) {
        this.name = name;
        this.throwExceptionOnClose = throwExceptionOnClose;
    }

    public void doOp(boolean throwException) throws Exception {
        System.out.println("Resource " + this.name + " doing operation");
        if(throwException) {
            throw new Exception("Error when calling doOp() on resource " + this.name);
        }
    }

    @Override
    public void close() throws Exception {
        System.out.println("Resource " + this.name + " close() called");
        if(this.throwExceptionOnClose){
            throw new Exception("Error when trying to close resource " + this.name);
        }
    }
}
```

首先，让我们看一个使用单一资源的基本示例：

```
public static void main(String[] args){
    try {
        tryWithResourcesSingleResource();
    } catch (Exception e) {
        e.printStackTrace();
        Throwable[] suppressed = e.getSuppressed();
    }
}

public static void tryWithResourcesSingleResource() throws Exception {
    try(AutoClosableResource resourceOne = new AutoClosableResource("One", false)) {
        resourceOne.doOp(false);
    }
}
```

如果 `AutoClosableResource` 构造的第二个参数被更改为 `true`，它将在试图关闭时抛出一个异常。在这种情况下，当试图关闭时抛出的异常将沿调用堆栈向上传播到 `main()` 方法，在那里 *try-catch* 块将捕获它。在这种情况下，从 `e.getSuppessed()` 返回的 `Throwable` 数组将是一个空数组（大小为 0）。

如果 `resourceOne.doOp()` 的参数也被更改为 `true`，`doOp()` 方法将抛出一个异常。在这种情况下，正是这个异常被向上传播到调用堆栈的 `main()` 方法。试图关闭资源时抛出的异常可以在由 `e.getSuppressed()` 返回的 `Throwable` 数组中找到。

让我们看一个使用两个 `AutoClosable` 资源的例子：

```
public static void main(String[] args){
    try {
        tryWithResourcesTwoResources();
    } catch (Exception e) {
        e.printStackTrace();
        Throwable[] suppressed = e.getSuppressed();
        System.out.println("suppressed = " + suppressed);
    }
}

public static void tryWithResourcesTwoResources() throws Exception {
    try(AutoClosableResource resourceOne = new AutoClosableResource("One", true);
        AutoClosableResource resourceTwo = new AutoClosableResource("Two", true)
    ){
        resourceOne.doOp(true);
        resourceTwo.doOp(false);
    }
}
```

在只有一个资源抛出异常的情况下，无论是在使用期间还是试图关闭时，行为都与只使用一个资源时相同。然而，在上面的例子中，我已经强制两个资源在试图关闭时抛出异常，并且第一个资源在使用时抛出异常（当调用 `doOp()` 时）。在这种情况下，从 *try* 块内部抛出的异常会向上传播到调用堆栈。试图关闭资源时抛出的两个异常在由 `e.getSuppressed()` 返回的 `Throwable` 数组中可用。

记住，在 *try* 块中只能抛出一个异常。一旦抛出异常，*try* 块代码就会退出，并且尝试关闭资源。

### 捕捉块

您可以将一个 *catch* 块添加到一个 *try-with-resources* 块中，就像您可以添加到一个标准的 *try* 块中一样。如果从 *try-with-resources* 块的 *try* 块中抛出异常，那么 *catch* 块将捕获它，就像它与标准的 *try* 构造一起使用时一样。

在进入 *catch* 块之前，*try-with-resources* 构造将尝试关闭在 *try* 块中打开的资源。如果在试图关闭其中一个资源时抛出异常，这些异常将可以从 *catch* 块中的异常的 `getSuppressed()` 方法中获得。下面是一个 Java *try-with-resources* 块与一个 *catch* 块的例子：

```
try(AutoClosableResource resourceOne = new AutoClosableResource("One", true)) {
    resourceOne.doOp(true);
} catch(Exception e) {
    Throwable[] suppressed = e.getSuppressed();
    throw e;
}
```

在上面的例子中，`AutoClosableResource` 被配置为在调用 `doOp()` 和试图关闭（通过 `close()`）时抛出异常。从 `doOp()` 抛出的异常在 *catch* 块中被捕获，它的 `getSuppressed()` 方法返回一个数组，该数组包含当试图关闭资源时抛出的异常。

如果只有在试图关闭资源时才抛出异常，那么 *catch* 块也将捕获它。该异常的 `getSuppressed()` 方法将返回一个空数组，因为没有隐藏异常。

### 最终阻止

也可以将 *finally* 块添加到 Java *try-with-resources* 块中。它的行为就像一个标准的 *finally* 块，这意味着它将在退出 *try-with-resources* 块之前的最后一步被执行——在任何 *catch* 块被执行之后。

如果您从 *try-with-resources* 构造的 *finally* 块中抛出一个异常，所有之前抛出的异常都将丢失！下面是一个从 Java *try-with-resources* 构造的 *finally* 块中抛出异常的例子：

```
public static void main(String[] args){
    try {
        tryWithResourcesSingleResource();
    } catch (Exception e) {
        e.printStackTrace();
        Throwable[] suppressed = e.getSuppressed();
    }
}

public static void tryWithResourcesSingleResource() throws Exception {
    try(AutoClosableResource resourceOne = new AutoClosableResource("One", true)) {
        resourceOne.doOp(false);
    } catch(Exception e) {
        Throwable[] suppressed = e.getSuppressed();
        throw e;
    } finally {
        throw new Exception("Hey, an exception from the finally block");
    }
}
```

注意，从 *catch* 块中抛出的异常将被忽略，因为新的异常是从 *finally* 块中抛出的。如果没有 *catch* 块，也是如此。那么从 *try* 块内部抛出的任何异常都会丢失，因为新的异常是从 *finally* 块内部抛出的。任何先前的异常都没有被抑制，所以它们在从 *finally* 块抛出的异常中不可用。

### 手动添加隐藏的异常

`Throwable` 类有一个名为 `addSuppressed()` 的方法，它将一个 `Throwable` 对象作为参数。如果你需要的话，使用 `addSuppressed()` 方法可以将被抑制的异常添加到另一个异常中。下面的示例展示了如何手动将隐藏的异常添加到 Java 异常中：

```
Exception finalException = null;
try(AutoClosableResource resourceOne = new AutoClosableResource("One", true)) {
    resourceOne.doOp(false);
} catch(Exception e) {
    finalException = new Exception("Error...");
    finalException.addSuppressed(e);
    for(Throwable suppressed : e.getSuppressed()){
        finalException.addSuppressed(suppressed);
    }
} finally {
    if(finalException != null){
        throw finalException;
    }
}
```

注意如何在 *try-with-resources* 构造之外声明 `Throwable` 引用。否则 *捕捉* 和 *最后* 块不能访问。

在大多数情况下，您不需要手动将隐藏的异常添加到异常中，但是现在您至少已经看到了如何做，以防您遇到需要它的情况。

## 资源管理与尝试-捕捉-最后，老学校的风格

Java 7 中添加了 Java *try-with-resources* 构造。在 Java 7 之前，管理需要显式关闭的资源有些繁琐。您必须手动处理资源的正确关闭。这不是一个容易正确处理的任务。要理解为什么，请看下面的方法，该方法读取一个文件并将其打印到 `System.out`：

```
private static void printFile() throws IOException {
    InputStream input = null;
    try {
        input = new FileInputStream("file.txt");
        int data = input.read();
        while(data != -1){
            System.out.print((char) data);
            data = input.read();
        }
    } finally {
        if(input != null){
            input.close();
        }
    }
}
```

粗体标记的代码是代码可以抛出 `Exception` 的地方。如你所见，这可能发生在 `try` 区块的 3 个地方，以及 `finally` 区块的 1 个地方。

无论 `try` 程序块是否抛出异常，总是执行 `finally` 程序块。这意味着无论 `try` 区块发生什么情况，`InputStream` 都是关闭的。或者说，试图关闭。如果关闭失败，`InputStream` 的 `close()` 方法也可能抛出异常。

假设从 `try` 块内部抛出了一个异常。然后执行 `finally` 块。想象一下，从 `finally` 块中也抛出了一个异常。您认为哪个异常会在调用堆栈中向上传播？

从 `finally` 块抛出的异常将被向上传播到调用堆栈，即使从 `try` 块抛出的异常可能与传播更相关。
