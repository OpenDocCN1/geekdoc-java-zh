Advantages of objects

Objects provide a number of benefits, including:

  • Garbage Collection: The idea of garbage collection is the automated reclamation of runtime memory. It functions as though there are disparities between an item and its goals, which are thought to be unnecessary. The objectʼs stated memory is present. The memory is examined to detect things that are not being used, and the unneeded objects are then deleted in a process known as automatic garbage collection.

Advantages and disadvantages of vector in Java

Vector is safe to use in a multi-threaded context because, it is synchronized. There is no need to worry about setting an initial size that can accommodate all items, because a vector can grow or shrink dynamically as elements are added or removed. If you need to deal with older Java code that utilizes Vector, it is a suitable option because it has been a part of Java since its birth and is still supported.

Vectorʼs synchronization may cause it to perform less quickly than other collection types, such as ArrayList. Although Vector is still available, it could be more difficult to find examples and assistance for it because more recently developed Java code frequently uses the more contemporary collection classes. Utilizing Vectorʼs synchronization facilities will increase the overhead of your code if you do not require them.

When a class implements an interface, it may be more formal about the behavior it guarantees to deliver. Access modifiers

Access level modifiers determine whether other classes can use a particular field or invoke a particular method. There are two levels of access control:

  • At the top level: public, or package-private (no explicit modifier).
  • At the member level: public, private, protected, or package-private (no explicit modifier).

A class may be declared with the modifier public, in which case that class is visible to all classes everywhere. If a class has no modifier (the default, also known as package-private), it is visible only within its own package (packages are named groups of related classes — you will learn about them in a later lesson.)

At the member level, you can also use the public modifier or no modifier (package-private) just as with top-level classes, and with the same meaning. For members, there are two additional access modifiers: private and protected. The private modifier specifies that the member can only be accessed in its own class. The protected modifier specifies that the member can only be accessed within its own package (as with package-private) and, in addition, by a subclass of its class in another package. Comparison between Runnable interface and thread class

In this section, we are going to present the comparison between runnable interface and thread class in a pointwise manner:

  • Multiple inheritance in not supported in Java: We can extend another class when we implement the Runnable interface, but we cannot extend another class when we extend the Thread class since Java does not allow multiple inheritance. So, implementing Runnable and extending Thread do the same thing, but implementing Runnable leaves us with the option of extending another class. As a result, it is preferable to use Runnable interface.
  • Safety of thread: When we implement the Runnable interface, the same object is shared by several threads, but when we extend the Thread class, each thread is assigned a separate object.
  • Property of inheritance: When we extend Thread, all of the Thread classʼs features are inherited, but when we implement the Runnable interface, no further features are inherited because Runnable just has one abstract function, the run() method. As a result, implementing Runnable interface means performing lightweight operation.
  • Use of interface: Even Java recommends coding to interface. So, we must implement Runnable rather than extending thread. Also, Thread class implements Runnable interface.
  • Do not extend unless you modify fundamental behavior of class: Only when you want to change run() method and other methods, extend the Thread class. If you just want to change the run() method, implementing the Runnable interface is the best choice having only one abstract method (run()). We must not extend the Thread class unless we want to change its core behavior.
  • Flexibility in code when we implement Runnable: When we extend Thread first, all thread characteristics are inherited, and our class becomes a direct subclass of Thread, so any action we perform is in the Thread class. However, when we implement Runnable, we establish a new thread and send the runnable object as a parameter, we can pass the runnable object to executorService, and we can do a lot more. So, when we use Runnable, we have more possibilities which leads to code flexibility.

Thread priority

Each thread is given a priority by Java, which specifies how it should be handled in relation to the other threads. The relative priority of one thread to another is indicated by thread priorities, which are integers.

To determine when to move from one running thread to the next, a threadʼs priority is employed instead. A context switch would be appropriate here. The following guidelines for determining whether a context switch occurs are straightforward:

  • A thread can voluntarily relinquish control. This is done by explicitly yielding, sleeping, or blocking on pending I/O. In this scenario, all other threads are examined, and the highest-priority thread that is ready to run is given the CPU.
  • A thread can be preempted by a higher-priority thread. In this case, a lower-priority thread that does not yield the processor is simply preempted—no matter what it is doing— by a higher-priority thread. Basically, as soon as a higher-priority thread wants to run, it does. This is called preemptive multitasking.

In cases where two threads with the same priority are competing for CPU cycles, the situation is a bit complicated. For operating systems such as Windows, threads of equal priority are time-sliced automatically in round-robin fashion. For other types of operating systems, threads of equal priority must voluntarily yield control to their peers. If they do not, the other threads will not run.

Benefits of multi-threading

One of multithreadingʼs key advantages is the concurrent activity that speeds up programs. Multi-threading enables the efficient usage of several processing subsystems as well as the full exploitation of parallel hardware. While multi-threading is crucial for maximizing the performance of symmetric multiprocessors, it also boosts performance on systems with a single processor by increasing the overlap of processes like computation and I/O. Some of the most important benefits of multi-threading are:

  • Improved throughput: Many concurrent computer operations and I/O requests within a single process.
  • Simultaneous and fully symmetric use of multiple processors for computation and I/O
  • Superior application responsiveness: If a request can be launched on its own thread, applications do not freeze or show the hourglass. An entire application will not block, or otherwise wait, pending the completion of another request.
  • Improved server responsiveness: Large or complex requests or slow clients do not block other requests for service. The overall throughput of the server is much greater.
  • Minimized system resource usage: Threads impose minimal impact on system resources. Threads require less overhead to create, maintain, and manage than a traditional process.
  • Program structure simplification: Threads can be used to simplify the structure of complex applications, such as server-class and multimedia applications. Simple routines can be written for each activity, making complex programs easier to design and code, and more adaptive to a wide variation in user demands.
  • Better communication: Thread synchronization functions can be used to provide enhanced process-to-process communication. In addition, sharing large amounts of data through separate threads of execution within the same address space provides extremely high-bandwidth, low-latency communication between separate tasks within an application.

Thread synchronization

It is already mentioned that threads in Java are running in the same memory space, and hence it is easy to communicate between two threads. Inter-thread communications allow threads to talk to or wait on each other. Again, because all the threads in a program share the same memory space, it is possible for two threads to access the same variables and methods in object. Problems may occur when two or more threads are accessing the same data concurrently, for example, one thread stores data into the shared object and the other threads reads data, there can be synchronization problem if the first thread has not finished storing the data before the second one goes to read it. So we need to take care to access the data by only one thread process at a time. Java provides unique language level support for such synchronization. In this section, we will learn how synchronization mechanism and inter-thread communications are possible in Java.

To solve the critical section problem, one usual concept is known as monitor. A monitor is an object which is used as a mutually exclusive lock, called mutex. Only one thread may own a monitor at a given time. When a thread acquires a lock, it is said to have entered the monitor. All other threads attempting to enter the locked monitor will be suspended until the owner thread exits the monitor. However, in Java, there is no such monitor. In fact, all Java object have their own implicit monitor associated with them. Here, the key word synchronized is used by which method(s) or block of statements can be made protected from the simultaneous access. With this, when a class is designed with threads in mind, the class designer decides which methods should not be allowed to execute concurrently. When a class with synchronized method is instantiated, the new object is given its own implicit monitor. The entire time that a thread is inside of a synchronized method, all other threads that try to call any other synchronized method on the same instance have to wait. In order to exit the monitor and relinquish control of the object to the next waiting thread, the monitor owner simply needs to return from the method.

Suppose we want to maintain a bank account of customers. Several transactions, such as depositing some amount to an account and withdraw some amount from an account etc., are possible. Now, for a given account, if two or more transactions come simultaneously then only one transaction should be allowed at a time instead of simultaneous transaction processing so that data inconsistency will never occur. So, what we need is to synchronize the transaction.

Inter-thread communication

There are three ways for threads to communicate with each other. The first is through commonly shared data. All the threads in the same program share the same memory space. If an object is accessible to various threads, then these threads share access to that objectʼs data member and thus communicate each other.

The second way for threads to communicate is by using thread control methods. There are such three such methods by which threads communicate with each other: suspend(), resume(), join(). These methods can be used for the caller thread to wait for the completion of called thread.

The third way for threads to communicate is the use of three methods; wait(), notify(), and notifyAll(); these are defined in class Object of package java.lang. Actually, these three methods provide an elegant inter-process communication mechanism to take care of the deadlock situation in Java. As there is multi-threading in program, deadlock may occur when a thread holding the key to monitor is suspended or waiting for another threadʼs completion. If the other thread is waiting for needs to get into the same monitor, both threads will be waiting for ever. The uses of these three methods are briefed as follows:

  • wait( ): This method tells the calling thread to give up the monitor and make the calling thread wait until either a time out occurs or another thread calls the same threadʼs notify() or notifyAll() method.
  • Notify( ): This method wakes up the only one (first) waiting thread called wait() on the same object.
  • notifyAll( ): This method will wake up all the threads that have been called wait() on the same object

Operations regarding exception handling

There are five keywords related to exception handling and they are try, catch, finally, throws and throw. To process an exception when it occurs, the line that throws the exception is executed within a try block. A try block is followed by one or more catch clauses, which contain code to process an exception

Each catch clause has an associated exception type. When an exception occurs, processing continues at the first catch clause that matches the exception type. A finally block is where you put code that must run regardless of an exception. The coding block contains finally statements is a key tool for preventing resource leaks. At the time of closing a file or in the situation when recovering resources, place the code in a finally block to ensure that resource is always recovered.

The keyword throws indicates that a method can throw an exception that it does not handle. This declaration does permit another method to handle the exception. All Java methods use the throw statement for the purpose of throw an exception. The statement containing throw requires a single argument: a throwable object.

The mechanism of exception handling is composed of the following three operations:

  • The operation of declaring exceptions: According to specification, a method must specify the checked exception types in the method signature part, which the method may throw from its body, with the help of the keyword throws.
  • The operation of throwing an exception: At the time of encountering an abnormal scenario by a Java operation, the method having the statement that is erroneous, shall create a proper Exception object and throw the object to the Java runtime system with the help of the statement throw.
  • The operation of catching an exception: At the time of throwing an exception by a method, the JVM scans the call stack for an exception handler that is required. The specific exception handler can only handle a single type of exception. An exception handler that handles a specified class, can able to handle its subclasses also. In that case when no exception handler is identified in the call stack, the application exits.

Exceptions allow you to isolate the specifics of what to do when something unusual occurs from the primary logic of a program. Rules for creating packages

The rules for creating packages are as follows:

  • To prevent conflicts with class or interface names, package names are composed in all lowercase.
  • Companies utilize their inverted Internet domain name to start their package names, such as com.abc.mypack for a package called mypac written by a programmer at abc.com.

  • In some circumstances, the domain of the internet name may not be an acceptable package name. This can happen if the domain name has a hyphen or another special character. If the package name starts with a number or another character that is forbidden to use as the first character of a Java name, or if the package name contains a reserved Java keyword, like int. Some streams simply pass on data; others manipulate and transform the data in useful ways. A program uses an input stream to read data from a source, one item at a time. Character-oriented streams

This type of stream is designed to hold character data. Data is converted from the 16-bit Java char format used inside programs to the externally utilized UTF format. The platform based on Java uses Unicode standards to store character values. This internal format is automatically translated to and from the local character set using character stream I/O. The local character set in Western locations is often an 8-bit superset of ASCII. I/O with character streams is not more complex than I/O with byte streams for the majority of applications. Using stream classes for input and output results in automated translation to and from the local character set. Instead of requiring additional work from the programmer, a program that employs character streams instead of byte streams instantly adjusts to the local character set and is prepared for internationalization.

Standard input, output and error as predefined streams

The java.lang package is automatically imported by all Java programs, as you may know. A class named System, which contains many run-time environment components, is defined in this package. Process of reading data

There are four classes used to read data from keyboard and they are listed as follows:

  • InputStreamReader
  • Console
  • Scanner
  • DataInputStream

Let us discuss each class and the utility of each class:

  • InputStreamReader class: Data from the keyboard may be read using the InputStreamReader class. It has the responsibility to connect to the keyboardʼs input stream and transforms the byte-oriented stream into a character-oriented stream, among other things.

    A bridge between byte streams and character streams is an input stream reader. Using a given charset, it reads bytes and decodes them into characters.

  • BufferedReader class: The readLine() function of the BufferedReader class may be used to read data line by line. This function reads text from a character-input stream while buffering characters to make reading characters, arrays, and lines more successful. As it buffers input, it enhances performance.
  • DataInputStream: It is utilized to machine-independently read primitive Java data types from an underlying input stream. A data input stream can read data that an application writes via a data output stream. Multithreaded access to DataInputStream is not always secure.

  • Scanner class: A basic text scanner that uses regular expressions to parse strings and primitive types. Using a delimiter pattern that by default detects whitespace, a scanner divides its input into tokens. Afterwards, the tokens might be transformed into diverse values by utilizing the different subsequent techniques.

    For example, the following code allows a user to read a number from system.in:

    Scanner sc = new Scanner(System.in);

    int k = sc.nextInt(); // Scans the next token of the input as an int.

The java.util package has a class called Scanner, that is used to get input of primitive kinds such as strings and int, double, and so on. It is the simplest method for reading input into a Java program. Typically, the predefined object System.in—which stands for the standard input stream—is given when creating an object of the Scanner class. To read strings, we use nextLine().

Definition of Applet

The purpose of an applet is to be embedded into another application rather than run independently. Any applet that will be included in a web page or used by the Java Applet Viewer must have the Applet class as its super class. Between applets and their environment, the Applet class offers a standard interface. A Java applet is a particular type of Java program that may be downloaded and executed from the internet by a browser that supports Java technology. An applet generally operates in the context of a browser and is embedded into a web page. A subclass of the java.applet.Applet class is required for an applet. The standard interface between the applet and the browser environment is provided by the Applet class. The package java.applet contains the Applet class. Several methods in the applet allow you to have fine-grained control over how your applet is executed. All applets fall under the category of applet. As a result, all applets need to import java.applet. Furthermore, applets must import java.awt. The acronym AWT stands for Abstract Window Toolkit. Since every applet runs in a window, java.awt package import is required to add functionality for that window. The Java run-time interpreter for consoles does not run applets. Instead, they are either run by an applet viewer or a web browser. An applet does not start running at main(). System.out.println() does not produce output to the window of your applet. Instead, other AWT methods are used to handle it, such drawString(), which produces a string according to a given X,Y location. Input is also handled differently than in an application. The Applet tag contains properties for the appletʼs width, height, codebase, archive, name, and other properties that affect where the applet appears in the browser. You can give the name of the applet class that has to be loaded from the server using the code property. The dimensions of the applet instance within the browser are specified by its width and height.

Advantage of Applet

There are many advantages of applet. They are as follows:

  • Less response time as it operates at the client side.
  • Browsers on a variety of operating systems, such as Linux, Windows, Mac OS, etc., may use it.
  • Typically, applets are able to establish a network connection back to their source host.
  • HTML pages may be presented with ease by applets that operate within a web browser.
  • On the same page, applets can call the public methods of other applets.
  • There are no limitations applied to applets loaded over a network; instead, they are unrestricted while loading them from a location located in the userʼs CLASSPATH on the local file system.
  • Applets do not have to cease working when you leave their page, even if most do.

Drawbacks of Applet

There are certain limitations of applet in Java and they are as follows:

  • To run the applet, the client browser must have a plugin installed.
  • Native methods cannot be defined or libraries loaded by an applet.
  • Normally, it is unable to read or write files on the host it is running on.
  • It is only able to establish connections with the host from where it originated.
  • It is unable to launch any software on the host it is running on.
  • It is unable to read some system attributes.
  • The appearance of windows brought up by an applet varies from windows brought up by a program.

AES encryption and decryption

The class Cipher provides the functionality of a cryptographic cipher for encryption and decryption. It forms the core of the Java Cryptographic Extension (JCE) framework.

In order to create a Cipher object, the application calls the Cipherʼs getInstance method, and passes the name of the requested transformation to it. Optionally, the name of a provider may be specified.

A transformation is a string that describes the operation (or set of operations) to be performed on the given input, to produce some output. A transformation always includes the name of a cryptographic algorithm (for example, AES), and may be followed by a feedback mode and padding scheme.

A transformation is of the form:

  • algorithm/mode/padding
  • algorithm

(In the latter case, provider-specific default values for the mode and padding scheme are used). For example, the following is a valid transformation:

Cipher c = Cipher.getInstance("AES/CBC/PKCS5Padding");

Using modes such as CFB and OFB, block ciphers can encrypt data in units smaller than the cipherʼs actual block size. When requesting such a mode, you may optionally specify the number of bits to be processed at a time by appending this number to the mode name as shown in the AES/CFB8/NoPadding and AES/OFB32/PKCS5Padding transformations. If no such number is specified, a provider-specific default is used. Thus, block ciphers can be turned into byte-oriented stream ciphers by using an 8-bit mode such as CFB8 or OFB8.

Modes such as Authenticated Encryption with Associated Data (AEAD) provide authenticity assurances for both confidential data and Additional Associated Data (AAD) that is not encrypted. (Please see RFC 5116 for more information on AEAD and AEAD algorithms such as GCM/CCM.) Both confidential and AAD data can be used when calculating the authentication tag (similar to a Mac). This tag is appended to the ciphertext during encryption and is verified on decryption.

Class KeyGenerator provides the functionality of a secret (symmetric) key generator. Key generators are constructed using one of the getInstance class methods of this class. KeyGenerator objects are reusable, that is, after a key has been generated, the same KeyGenerator object can be re-used to generate further keys.

There are two ways to generate a key: in an algorithm-independent manner, and in an algorithm-specific manner. The only difference between the two is the initialization of the object:

  • Algorithm-Independent Initialization: All key generators share the concepts of a keysize and a source of randomness. There is an init method in this KeyGenerator class that takes these two universally shared types of arguments. There is also one that takes just a keysize argument and uses the SecureRandom implementation of the highest-priority installed provider as the source of randomness (or a system-provided source of randomness if none of the installed providers supply a SecureRandom implementation), and one that takes just a source of randomness.

    Since no other parameters are specified when you call the above algorithm-independent init methods, it is up to the provider what to do about the algorithm-specific parameters (if any) to be associated with each of the keys.

  • Algorithm-Specific Initialization: For situations where a set of algorithm-specific parameters already exists, there are two init methods that have an AlgorithmParameterSpec argument. One also has a SecureRandom argument, while the other uses the SecureRandom implementation of the highest-priority installed provider as the source of randomness (or a system-provided source of randomness if none of the installed providers supply a SecureRandom implementation).

    In case the client does not explicitly initialize the KeyGenerator (via a call to an init method), each provider must supply (and document) a default initialization.

Every implementation of the Java platform is required to support the following standard KeyGenerator algorithms with the keysizes in parentheses:

  • AES (128)
  • DES (56)
  • DESede (168)
  • HmacSHA1
  • HmacSHA256

Immutable arbitrary-precision integers. All operations behave as if BigIntegers were represented in twoʼs-complement notation (like Javaʼs primitive integer types). BigInteger provides analogues to all of Javaʼs primitive integer operators, and all relevant methods from java.lang.Math. Additionally, BigInteger provides operations for modular arithmetic, GCD calculation, primality testing, prime generation, bit manipulation, and a few other miscellaneous operations.

Semantics of arithmetic operations mimic those of Javaʼs integer arithmetic operators, as defined in The Java Language Specification. For example, division by zero throws an ArithmeticException, and division of a negative by a positive yield a negative (or zero) remainder. All the details in the Spec concerning overflow are ignored, as BigIntegers are made as large as necessary to accommodate the results of an operation.

Semantics of shift operations extend those of Javaʼs shift operators to allow for negative shift distances. A right shift with a negative shift distance results in a left shift, and vice-versa. The unsigned right shift operator (>>>) is omitted, as this operation makes little sense in combination with the infinite word size abstraction provided by this class.

Semantics of bitwise logical operations exactly mimic those of Javaʼs bitwise integer operators. The binary operators (and, or, xor) implicitly perform sign extension on the shorter of the two operands prior to performing the operation.

Comparison operations perform signed integer comparisons, analogous to those performed by Javaʼs relational and equality operators.

Modular arithmetic operations are provided to compute residues, perform exponentiation, and compute multiplicative inverses. These methods always return a non-negative result, between 0 and (modulus - 1), inclusive.

Bit operations operate on a single bit of the twoʼs-complement representation of their operand. If necessary, the operand is sign- extended so that it contains the designated bit. None of the single-bit operations can produce a BigInteger with a different sign from the BigInteger being operated on, as they affect only a single bit, and the infinite word size abstraction provided by this class ensures that there are infinitely many virtual sign bits preceding each BigInteger.

For the sake of brevity and clarity, pseudo-code is used throughout the descriptions of BigInteger methods. The pseudo-code expression (i + j) is shorthand for a BigInteger whose value is that of the BigInteger i plus that of the BigInteger j. The pseudo-code expression (i == j) is shorthand for true if and only if the BigInteger i represents the same value as the BigInteger j. Other pseudo-code expressions are interpreted similarly.

This class SecureRandom provides a cryptographically strong random number generator (RNG).

A cryptographically strong random number minimally complies with the statistical random number generator tests specified in FIPS 140-2, Security Requirements for Cryptographic Modules, section 4.9.1. Additionally, SecureRandom must produce non-deterministic output. Therefore, any seed material passed to a SecureRandom object must be unpredictable, and all SecureRandom output sequences must be cryptographically strong, as described in RFC 1750: Randomness Recommendations for Security.

A caller obtains a SecureRandom instance via the no-argument constructor or one of the getInstance methods:

SecureRandom random = new SecureRandom();

Many SecureRandom implementations are in the form of a pseudo-random number generator (PRNG), which means they use a deterministic algorithm to produce a pseudo-random sequence from a true random seed. Other implementations may produce true random numbers, and yet others may use a combination of both techniques.

Typical callers of SecureRandom invoke the following methods to retrieve random bytes:

SecureRandom random = new SecureRandom();

byte bytes[] = new byte[20];

random.nextBytes(bytes);

Callers may also invoke the generateSeed method to generate a given number of seed bytes (to seed other random number generators, for example):

byte seed[] = random.generateSeed(20);

The package java.net provides the classes for implementing networking applications. The java.net package can be roughly divided in two sections:

  • A Low Level API, which deals with the following abstractions:
    • Addresses, which are networking identifiers, like IP addresses.

Sockets

Sockets are means to establish a communication link between machines over the network. The java.net package provides 4 kinds of Sockets:

  • Socket is a TCP client API and will typically be used to connect to a remote host.
  • ServerSocket is a TCP server API and will typically accept connections from client sockets.
  • DatagramSocket is a UDP endpoint API and is used to send and receive datagram packets.
  • MulticastSocket is a subclass of DatagramSocket used when dealing with multicast groups.
  • Sending and receiving with TCP sockets is done through InputStreams and OutputStreams which can be obtained via the Socket.getInputStream() and Socket.getOutputStream() methods.

This class Socket implements client sockets (also called just sockets). A socket is an endpoint for communication between two machines.

The actual work of the socket is performed by an instance of the SocketImpl class. An application, by changing the socket factory that creates the socket implementation, can configure itself to create sockets appropriate to the local firewall.

This class ServerSocket implements server sockets. A server socket waits for requests to come in over the network. It performs some operation based on that request, and then possibly returns a result to the requester.

The actual work of the server socket is performed by an instance of the SocketImpl class. An application can change the socket factory that creates the socket implementation to configure itself to create sockets appropriate to the local firewall.
