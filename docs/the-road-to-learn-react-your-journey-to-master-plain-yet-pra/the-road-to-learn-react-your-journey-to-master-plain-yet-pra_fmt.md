你为什么要费力学习 React 呢？近年来，单页应用（SPA³¹）变得非常流行。Angular、Ember 和 Backbone 等框架帮助 JavaScript 开发者构建了超越原生 JavaScript 和 jQuery 使用的现代 Web 应用程序。这些流行解决方案的列表并非详尽。目前存在大量的 SPA 框架。考虑到发布日期，它们大多数属于第一代 SPA：Angular（2010年）、Backbone（2010年）和 Ember（2011年）。

React 的最初版本是由 Facebook 在 2013 年发布的。React 并不是 SPA 框架，而是一个视图库（view library）。它是 MVC³ 中的 V，允许你将组件渲染为浏览器中的可见元素。而 React 的整个生态系统使得构建单页应用成为可能。

但是，为什么你应该考虑使用 React 而不是第一代 SPA 框架？虽然第一代框架试图一次解决很多问题，但 React 只帮助你构建视图层。它是一个库，而不是框架。它背后的理念是：你的视图是一个可组合组件的分层结构。

在 React 中，你可以在为应用程序引入更多方面之前专注于你的视图层。其他任何方面都是你 SPA 的另一个构建块。这些构建块对于构建成熟的应用程序至关重要。你可以获得两个优势：

首先，你可以一步步学习这些构建块。你不需要担心一次性理解它们所有内容。这与从开始就给你提供每个构建块的框架不同。本书重点将 React 作为第一个构建块。最终会有更多构建块出现。

其次，所有的构建都是可交换的。这使得 React 周围的生态系统成为了一个创新的地方。多种解决方案正在相互竞争。你可以根据自己的用例选择最吸引你的解决方案。

第一代 SPA 框架已经达到了企业级水平。它们更加僵化。React 则保持着创新，并被 Airbnb、Netflix 以及 Facebook³⁵ 等多家技术领先公司采用。它们对 React 的未来投入投入，并对 React 及其生态系统本身感到满意。

React 可能是现在构建 Web 应用程序的最佳选择之一。现在它交付视图层，但 React 生态系统是灵活且可交换的框架³⁴React 拥有精简的 API、惊人的生态系统和优秀的社区。你可以阅读关于我为什么从 Angular 转向 React³⁵ 的经验。我强烈建议你理解为什么选择 React 而不是其他框架或库。毕竟，每个人都渴望体验 React 在未来几年将把我们带向何方。

## 全局安装与本地安装

`-g` 标志告诉 `npm` 全局安装。全局包可以在任何地方访问。你可以通过输入命令全局安装它们：

```bash
npm install -g <package>
```

`-g` 标志告诉 `npm` 全局安装。本地包用于你的应用程序。例如，`React` 就是一个本地包。你可以通过输入命令本地安装它：

```bash
npm install <package>
```

在 `React` 中，当你本地安装包时，它会被添加到 `package.json` 文件的 `dependencies` 中。

## 初始化项目

`-y` 标志是初始化 `package.json` 中所有默认值的快捷方式。如果你不使用标志，则必须配置文件。你可以通过输入命令初始化你的项目：

```bash
npm init -y
```

## 启动 React 应用的多种方法

### 使用 CDN

有多种方法可以启动 React 应用。第一种是使用 CDN。这听起来可能比实际要复杂。CDN 是一个[内容交付网络](https://en.wikipedia.org/wiki/Content_delivery_network*)。许多公司都拥有 CDN，公开托管文件供人们使用。这些文件可以是像 `React` 这样的库，因为毕竟打包后的 `React` 库只是一个 `react.js` JavaScript 文件。它可以被托管在某处，然后将其包含在你的应用程序中。

如何使用 CDN 启动 `React`？你可以在 HTML 中内联指向 CDN URL 的 `<script>` 标签。要启动 `React`，你需要两个文件（库）：`react` 和 `react-dom`。

```html
<script crossorigin src="https://unpkg.com/react@16/umd/react.development.js"></script>
<script crossorigin src="https://unpkg.com/react-dom@16/umd/react-dom.development.js"></script>
```

但是既然你可以使用 `npm` 来安装 `React` 这样的包，为什么要用 CDN 呢？

### 使用 npm

当你的应用程序使用 `package.json` 文件时，你可以从命令行安装 `react` 和 `react-dom`。要求是使用 `npm init -y` 将带有 `package.json` 文件的文件夹初始化为 `npm` 项目。你可以使用 `npm` 一行命令安装多个 node 包。

```bash
npm install react react-dom
```

这种方法通常用于将 `React` 添加到由 `npm` 管理的现有应用中。

遗憾的是，这并不是全部。你需要处理 [Babel](https://babeljs.io/) 来让你的应用程序支持 JSX（React 语法）和 JavaScript ES6。`Babel` 编译你的代码，以便浏览器可以解释 JavaScript ES6 代码和 JSX。并不是所有的浏览器都能解释这些语法。设置包含大量的配置和工具。对于 `React` 初学者来说，处理所有的配置可能会让他们措手不及。

## 使用 create-react-app

在学习 `React` 的道路上，你将使用 `create-react-app` 来引导你的应用程序。它是 Facebook 在 2016 年引入的针对 `React` 的内置零配置启动器。96% 的人会向学者推荐它。在 `create-react-app` 中，工具和配置在后台演进，而重点在于应用程序的实现。

要开始，你必须将该包安装到你的全局 node 包中。之后，你始终可以在命令行中使用它来引导新的 `React` 应用。

```bash
npm install -g create-react-app
```

你可以检查 `create-react-app` 的版本以验证是否在命令行中成功安装：

```bash
create-react-app --version
```

## 变量声明：var、let 与 const

我想你已经注意到我们用 `var` 声明了变量 `hello`。JavaScript ES6 提供了另外两个选项来声明变量：`const` 和 `let`。在 JavaScript ES6 中，你很少能再看到 `var`。

### const

用 `const` 声明的变量不能被重新赋值或重新声明。它不能被变异（改变、修改）。通过使用它，你拥了不可变的数据结构。一旦定义了数据结构，你就无法更改它。

**代码沙场**

```javascript
// not allowed
const helloWorld = 'Welcome to the Road to learn React';
helloWorld = 'Bye Bye React';
```

### let

用 `let` 声明的变量可以变异。

**代码沙场**

```javascript
// allowed
let helloWorld = 'Welcome to the Road to learn React';
helloWorld = 'Bye Bye React';
```

当你需要重新赋值变量时可以使用它。

然而，你必须小心使用 `const`。用 `const` 声明的变量不能被修改。但当变量是一个数组或对象时，它所持的值是可以更新的。它所持的值不是不可变的。

**代码沙场**

```javascript
const helloWorld = {
  text: 'Welcome to the Road to learn React';
};
helloWorld.text = 'Bye Bye React';
```

### 最佳实践

但是什么时候使用每种声明呢？关于用法有不同的意见。我建议尽可能使用 `const`。它表示你想要保持数据结构的不可变性，尽管对象和数组中的值可以被修改。如果你想修改你的变量，可以使用 `let`。

不可变性在 `React` 及其生态系统中是被推崇的。这就是为什么在定义变量时，`const` 应该是你的默认选择。尽管如此，在复杂对象内部的值是可以修改的。请注意这种行为。

在你的应用程序中，你应该使用 `const` 而不是 `var`。

```javascript
import React, { Component } from 'react';
import './App.css';
class App extends Component {
  render() {
    const helloWorld = 'Welcome to the Road to learn React';
    return (
      <div className="App">
        <h2>{helloWorld}</h2>
      </div>
    );
  }
}

export default App;
```

## 热模块替换 (HMR)

你可以在文件中做一件事来提升你的开发体验。但它是可选的，不至于在你学习时感到压力。

在 `create-react-app` 中，当你更改代码时浏览器会自动刷新，这是一个优势。尝试更改 `App.js` 文件中的变量。浏览器应该刷新页面。但有一种更好的方法。

热模块替换（HMR）是一种在浏览器中重新加载应用程序的工具。浏览器不再执行页面刷新。你可以在 `create-react-app` 中轻松激活它。在你的 `React` 入口 `src/index.js` 中，你添加一个配置：

```javascript
import React from 'react';
import ReactDOM from 'react-dom';
import App from './App';
import './App.css';

ReactDOM.render(
  <App />,
  document.getElementById('root')
);

if (module.hot) {
  module.hot.accept();
}
```

在第 3 步。即使源代码发生，它也会保持应用程序状态。应用程序本身会加载，但不会刷新页面。

- 更改你的 `src/App.js` 源代码几次以查看 HMR 的效果
- 观看 Dan Abramov 提供的《Live React: Hot Reloading with Time Travel^58 的前 10 分钟

```javascript
  return (
```

```javascript
// 不要这样做
{list.map(function(item, key) {
  return (
```

## JavaScript ES6 箭头函数

JavaScript ES6 引入了箭头函数。箭头函数表达式比函数表达式短。

```javascript
// function expression
```

App 类继承了 Component。基本上，你声明了 App 组件，但它继承自另一个组件。`extend`（扩展）意味着什么？在面向对象编程中，你有继承原则。它被用于将功能从一个类传递到另一个类。

### 单向数据流

现在你的 App 组件中有了一些内部状态。然而，你还没有操作本地状态。状态是静态的，因此它是组件的。体验状态操作的好方法是进行一些组件交互。

为显示列表中的每个项目添加一个按钮。按钮显示“Dismiss”（移除），并将该项目从列表中移除。当你只想保留一个未读项目列表并移除你不感兴趣的项目时，这最终会非常有用。

#### src/App.js

```javascript
class App extends Component {
  ...
  render() {
    return (
      <div className="App">
        {this.state.list.map(item => (
          <div key={item.id}>
            <span>
              <a href={item.url}>{item.title}</a>
            </span>
            <span>{item.author}</span>
            <span>{item.num_comments}</span>
            <span>{item.points}</span>
            <span>
              <button
                onClick={() => this.onDismiss(item.id)}
                type="button">
              Dismiss
            </button>
            </span>
          </div>
        ))}
      </div>
    );
  }
}
```

`onDismiss()` 类方法还没有定义。我们稍后会定义它，但目前重点应该放在按钮元素的 `onClick` 处理器上。如你所见，`onDismiss()` 方法在 `onClick` 处理器中被另一个函数包裹。这是一个箭头函数。通过这种方式，你可以悄悄传入项对象的属性，以识别要移除的项。另一种方法是在 `onClick` 处理器之外定义该函数，并仅将定义的函数传递给处理器。后面的章节将更详细地介绍元素中处理器的主题。

你注意到 `button` 元素使用了多行写法吗？注意，具有多个属性的元素如果写成一行，会变得混乱。这就是为什么 `button` 元素使用了多行和缩进来保持可读性。这不是强制性的，这只是我强烈推荐的一种代码风格建议。

现在如何实现 `onDismiss()` 功能。它接收一个 `id` 来标识要移除的项。该函数绑定到类并成为一个类方法。这就是为什么你通过 `this.onDismiss()` 而不是 `onDismiss()`。为了将 `onDismiss()` 定义为类方法，你必须在构造函数中对其进行绑定。绑定将在后面的章节中解释。

#### src/App.js

```javascript
class App extends Component {
  constructor(props) {
    super(props);
    this.state = {
      list,
    };
    this.onDismiss = this.onDismiss.bind(this);
  }
  render() {
    ...
  }
}
```

在下一步中，你必须在类中定义它的功能，即业务逻辑。类方法可以按照以下方式定义。

#### src/App.js

```javascript
class App extends Component {
  constructor(props) {
    super(props);

    this.state = {
      list,
    };

    this.onDismiss = this.onDismiss.bind(this);
  }

  onDismiss(id) {
    ...
  }

  render() {
    ...
  }
}
```

现在你能够定义类方法内部发生了什么。基本上，你想要从列表中移除由 `id` 标识的项，并将更新后的列表存储到本地状态中。之后，更新后的列表将在重新运行的 `render()` 方法中使用并进行显示。被移除的项不应该再次出现。

你可以使用 JavaScript 内置的 `filter` 功能从列表中移除项。`filter` 函数接收一个函数作为输入。该函数可以访问列表中的每个值，因为它遍历了列表。通过这种方式，你可以根据过滤条件评估列表中的每个项。如果某个项的评估结果为 `true`，则该项保留在列表中；否则，它将从列表中过滤掉。此外，重要的是，该函数返回一个新列表，而不是修改旧列表。它支持 React 中关于不可变数据结构的约定。

# 受控组件

你已经学习了 React 中的单向数据流。同样的规则也适用于输入字段，它通过用 `searchTerm` 更新本地状态来过滤列表。当状态变化时，`render()` 方法会再次运行，并使用来自本地状态的最新 `searchTerm` 来应用过滤条件。

但我们不是在输入元素中遗漏了什么吗？HTML 的 `input` 标签带有一个 `value` 属性。该属性具有在输入字段中显示的值。在这种情况下，它将是 `searchTerm` 属性。然而，在 React 中我们似乎不需要它。

那是错的。在原生 HTML 中，`<input>`、`<textarea>` 和 `<select>` 表单元素拥有自己的状态。当人们从外部更改它时，它们会在内部修改该值。在 React 中，应该确保让这些元素成为受控组件。

你应该如何做？你只需要设置输入字段的 `value` 属性。该值已经保存在 `searchTerm` 状态属性中了。为什么不从那里访问它呢？

### src/App.js

```javascript
class App extends Component {
  ...
  render() {
    const { searchTerm, list } = this.state;
    return (
      <div className="App">
        <form>
          <input
            type="text"
            value={searchTerm}
            onChange={this.onSearchChange}
          />
        </form>
        ...
      </div>
    );
  }
}
```

就是这样。输入字段的单向数据流循环现在是自包含的。内部组件状态是输入字段的单一事实源（single source of truth）。

整个内部状态管理和单向数据流对你来说可能是全新的。但一旦你习惯了，它将成为你在 React 中实现功能的自然流程。通常来说，React 将单向数据流的新模式引入了单页应用世界。现在它已经被多个框架和库采用。

# 受控组件

你已经学习了 React 中的单向数据流。同样的规则也适用于输入字段，它通过用 `searchTerm` 更新本地状态来过滤列表。当状态变化时，`render()` 方法会再次运行，并使用来自本地状态的最新 `searchTerm` 来应用过滤条件。

但我们不是在输入元素中遗漏了什么吗？HTML 的 `input` 标签带有一个 `value` 属性。该属性具有在输入字段中显示的值。在这种情况下，它将是 `searchTerm` 属性。然而，在 React 中我们似乎不需要它。

那是错的。在原生 HTML 中，`<input>`、`<textarea>` 和 `<select>` 表单元素拥有自己的状态。当人们从外部更改它时，它们会在内部修改该值。在 React 中，应该确保让这些元素成为受控组件。

你应该如何做？你只需要设置输入字段的 `value` 属性。该值已经保存在 `searchTerm` 状态属性中了。为什么不从那里访问它呢？

```javascript
src/App.js
class App extends Component {
  ...
  render() {
    const { searchTerm, list } = this.state;
    return (
      <div className="App">
        <form>
          <input
            type="text"
            value={searchTerm}
            onChange={this.onSearchChange}
          />
        </form>
        ...
      </div>
    );
  }
}
```

就是这样。输入字段的单向数据流循环现在是自包含的。内部组件状态是输入字段的单一事实源。

整个内部状态管理和单向数据流对你来说可能是全新的。但一旦你习惯了，它将成为你在 React 中实现功能的自然流程。通常来说，React 将单向数据流的新模式引入了单页应用世界。现在它已经被多个框架和库采用。

# 组件声明

到目前，你有了四个 ES6 类组件。但你可以做得更好。让我为你介绍函数式无状态组件，作为 ES6 类组件的替代方案。在重构你的组件之前，让我们先介绍 React 中不同类型的组件。

- **函数式无状态组件**：这些是接收输入并返回输出的函数。输入是 `props`。该组件是一个实例，即纯 JSX。到目前为止，它与 ES6 类组件非常相似。然而，函数式无状态组件是有函数的（functional），并且没有本地状态（stateless）。你无法通过 `this.state` 或 `this.setState()` 访问或更新状态，因为不存在该对象。此外，它们没有生命周期方法。你还没有学过生命周期方法，但你已经使用了两个：`constructor()` 和 `render()`。虽然 `constructor` 在组件的生命周期内运行一次，而 `render()` 类在开始时以及每次组件更新时运行一次。请记住，当你以后遇到生命周期方法时，函数式无状态组件是没有生命周期方法的。

- **ES6 类组件**：你已经在组件中使用了这种声明类型。在定义中，它们继承自 React 组件。它将 React 组件 API 中提供的所有生命周期方法继承给组件。你能够可以使用的是 `render()` 类方法。此外，你可以使用 `this.state` 和 `this.setState()` 在 ES6 类组件中存储和操作状态。

- **React.createClass**：这种组件声明用于旧版本的 React 并且仍用于 JavaScript ES5 应用程序。但 Facebook 已经将其声明为弃用，转而支持 JavaScript ES6。他们甚至在 15.5 版本中添加了弃用警告。你将在书中不会使用它。

所以基本上只剩下两种组件声明了。但什么时候该使用函数式无状态组件而不是 ES6 类组件呢？经验法则是，当你不需要本地状态或生命周期方法时，使用函数式无状态组件。通常你应该将你的组件实现为函数式无状态组件。一旦你访问状态或生命周期方法，就需要将其重构为 ES6 类组件。在我们的应用程序中，为了学习 React，我们采取了相反的方法。

回到你的应用程序。`App` 组件使用了内部状态。这就是为什么它必须保持为 ES6 类组件。另外三个 ES6 类组件是无状态的。它们不需要访问 `this.state` 或 `this.setState()`。更进一步，它们没有生命周期方法。让我们将 `Search` 组件重构为无状态函数组件，`Table` 和 `Button` 的重构将是你的主要练习。

## 生命周期方法

在开始使用 API 获取组件数据之前，你需要了解 React 生命周期方法。这些方法钩入 React 组件的生命周期。它们可以用于 ES6 类组件，但不能用于函数组件。你还记得上一章关于 JavaScript ES6 类以及它们如何使用的部分吗？除了 `render()` 方法，还有几个方法可以被重写。让我们深入了解它们：

你已经知道了用于 ES6 类组件的两个生命方法：`constructor()` 和 `render()`。`constructor` 只在组件实例创建并插入 DOM 时调用。`render()` 方法在挂载过程中调用，也会在组件更新时调用。每当组件的状态或 props 变化时，`render()` 方法就会被调用。现在你更多关于这些生命方法以及它们何时被调用的知识。组件的挂载（mounting）有两个生命方法：`componentWillMount()` 和 `componentDidMount()`。`constructor` 首先调用，`componentWillMount()` 在 `render()` 方法之前调用，而 `componentDidMount()` 在 `render()` 方法之后调用。总来说，挂载过程有 4 个生命方法，它们按以下顺序执行：

- `constructor()`
- `componentWillMount()`
- `render()`
- `componentDidMount()`

但是状态或 props 变化时的组件更新生命周期呢？总来说它有 5 个生命方法，顺序如下：

- `componentReceiveProps()`
- `shouldComponentUpdate()`
- `componentWillUpdate()`
- `render()`
- `componentDidUpdate()`

## 实战 API

最后但同样重要的是卸载（unmounting）生命周期。它只有一个生命方法：`componentWillUnmount()`。

最后，你不需要一开始就了解所有这些生命方法。这可能令人生望畏，但你不会使用所有的它们。即使在 React 应用中，你只会在 `constructor()` 和 `render()` 方法周围使用其中的几个。尽管如此，了解每个生命方法可以用于特定情况：

- **`constructor(props)`** - 在组件初始化时调用。你可以在该生命方法期间设置初始组件状态并绑定类方法。
- **`componentWillMount()`** - 在 `render()` 生命周期之前调用。这就是它可以用于设置内部组件状态，因为它将触发组件的渲染。
- **`render()`** - 该方法是强制的，并将元素作为输出。方法应该是纯的，因此不应修改组件状态。它接收 props 作为输入。
- **`componentDidMount()`** - 它只在组件挂载时调用。这是从 API 请求异步数据的完美时机。获取的数据将存储在内部状态中，以便在 `render()` 生命周期中显示。
- **`componentReceiveProps(nextProps)`** - 该生命方法在更新生命周期期间调用。当你获取下一个 props 时，你可以将下一个 props 与之前的 props 进行对比，使用这些 props 来应用不同的行为。此外，你可以在 next props 上设置状态。
- **`shouldComponentUpdate(nextProps, nextState)`** - 组件更新状态或 props 时总是会被调用。你将在 React 应用中使用来进行性能优化。根据你从此生命周期返回的布尔值，组件及其所有子组件将在更新生命周期上渲染或不渲染。你可以阻止组件的 render 方法。
- **`componentWillUpdate(nextProps, nextState)`** - 该生命方法在 `render()` 方法之前立即调用。你可以使用 next props 和状态。你可以使用该方法作为执行 render 方法之前进行准备工作的最后机会。注意，你不能随时触发 `setState()`。如果你想在 next props 上计算状态，必须使用 `componentReceiveProps()`。
- **`componentDidUpdate(prevProps, prevState)`** - 该生命方法在 `render()` 方法之后立即调用。你可以利用它执行 DOM 操作或执行进一步异步请求的机会。
- **`componentWillUnmount()`** - 在销毁组件之前调用。你可以使用该生命方法执行任何清理任务。

`constructor()` 和 `render()` 生命周期方法已经由你使用了。这些是 ES6 类组件中常用的生命方法。实际上，`render()` 方法是必须的，否则你将无法返回组件实例。

## 深入理解 API 实战 85

这里多了一个生命周期方法：`componentDidCatch(error, info)`。它在 React 16 中引入，用于捕获组件中的错误。例如，在你的应用程序中显示示例列表运行正常。但可能会出现一种情况：本地状态被意外设置为 `null`（例如，当从外部 API 获取列表时，请求失败且你将其本地状态设置为 `null`）。此后，你将无法再次对列表进行过滤和映射（map），因为它是 `null` 而不是空列表。组件将会崩溃，并导致整个应用程序失败。现在，通过使用 `componentDidCatch()`，你可以捕获错误，将其存储在本地状态中，并向应用程序用户显示可选的消息，告知发生了错误。

# 客户端缓存

每次提交搜索都会向 Hacker News API 发起请求。你可能会先搜索 "redux"，然后是 "react"，最后再次搜索 "redux"。总共发起了 3 次请求。但你只搜索了两次 "redux"，而且每次都花费了整个异步往返来获取数据。在客户端缓存中，你会存储每个结果。当向 API 发起请求时，它会检查结果是否已经存在。如果存在，则使用缓存。否则，发起 API 请求以获取数据。

为了让每个结果拥有客户端缓存，你需要在内部组件状态中存储多个结果而不是单个结果。结果对象将是一个 map，以搜索词为键，结果为值。来自 API 的每个结果将通过搜索词（键）保存。

这一章节的内容是为了用 `axios` 替换 `fetch`。在你的代码中，你调用了 `axios()`，它默认使用 HTTP GET 请求。你可以通过调用 `axios.get()` 来显式地发送 GET 请求。你也可以使用其他方法，例如 `axios.post()` 的 HTTP POST。你已经看到 `axios` 是一个向远程 API 执行请求的强大库。当你的 API 请求变得复杂或者你必须处理 Web 开发中的 Promise 问题时，我经常建议使用它而不是原生的 `fetch` API。在随后的章节中，你将学习如何在应用程序中对其进行测试。那时你就不需要担心浏览器或无头浏览器环境了。

我想为 `App` 组件中的 Hacker News 请求引入另一个改进。想象一下你的组件在浏览器首次渲染页面时挂载（mount）。在 `componentDidMount()` 中，组件开始发送请求，但由于你的应用程序引入了某种导航，你离开了此页面跳转到其他页面。你的组件卸载了，但此时你的 `componentDidMount()` 生命周期方法仍然有一个待处理的请求。它将尝试在 promise 的 `then()` 或 `catch()` 块中使用这个 `setState`。也许这时你会在第一次在命令行或浏览器开发者工具中看到以下警告：

## 命令行

> Warning: Can only update a mounted or moving component. This usually means called setState, replaceState, or forceUpdate on an unmounted component. This is a no-op.

你可以通过在组件卸载时中止请求，或者防止在卸载的组件上调用 `this.setState()` 来解决这个问题。尽管许多开发者并没有遵循这一点，但在 React 中这是一种最佳实践，可以保持应用程序的整洁并避免任何烦人的警告。然而，目前的 promise API 并没有实现中止请求的功能。因此，你需要自己解决这个问题。这可能也是为什么没有多少开发者遵循这一最佳实践的原因。下面的实现看起来更像是一个权宜之计，而不是持久的实现。因此，你可以决定是否要实现它来绕过卸载组件引起的警告。尽管如此，如果该警告在本书的后续章节或你未来的应用程序中出现，请记住它。到时候你就知道如何处理它了。

让我们开始解决这个问题。你可以引入一个持有组件生命周期的类字段（class field）。可以在组件初始化时将其初始化为 `false`，组件挂载时改为 `true`，然后在组件卸载时再次设置为 `false`。通过这样，你就可以跟踪组件的生命周期状态。这与通过 `state` 存储和修改的本地状态无关。对于 `setState()`，你应该能够直接在组件实例上访问它，而不需要依赖 React 的本地状态管理。此外，这种方式更改类字段不会导致组件的任何重新渲染。

```
src/App.js

class App extends Component {
  _isMounted = false;

  constructor(props) {
  }

  componentDidMount() {
    this._isMounted = true;

    const ( searchTerm ) = this.state;
    this.setState({ searchKey:searchTerm });
    this.fetchSearchTopStories(searchTerm);
  }

  componentWillUnmount() {
    this._isMounted = false;
  }

}
```

最后，你可以利用这个知识，不是中止请求本身，而是避免在组件已经卸载的情况下在组件实例上执行 `this.setState()`。这将防止上述警告。

```
src/App.js

class App extends Component {

  ...
  fetchSearchTopStories(searchTerm, page = 0) {
    axios(`${PATH_BASE}${PATH_SEARCH}?${PARAM_SEARCH}${searchTerm}&${PARAM_PAGE}=${page}&${PARAM_HPP}=${DEFAULT_HPP}`)
      .then(result => this.isMounted && this.setState({data: result.data}))
      .catch(error => this.isMounted && this.setState({ error })));
  }

}
```

总体来说，这一章节向你展示了如何在 React 中用一个库替换另一个库。如果你遇到任何问题，可以使用 JavaScript 库生态系统帮助自己。此外，你还看到了如何在 React 中避免在卸载的组件上使用 `this.setState()`。如果你深入研究 `axios` 库，你会发现一种可以从源头上取消请求的方法。这取决于你想了解多少关于这个主题。

Jest 允许你编写快照测试（snapshot tests）。这些测试会为渲染的组件创建一个快照，并将此快照与未来的快照进行对比。当未来的快照发生变化时，你会在测试中收到通知。你可以接受快照更改（因为你是有意地更改了实现），也可以拒绝更改并调查错误。它很好地补充了测试，因为你只需要测试渲染输出的差异。它不会增加维护成本，因为当你更改组件的渲染输出时，只需简单更改快照即可。

## 复习：setState()

到目前为止，你一直在使用 React 的 `setState()` 来管理组件内部状态。你可以向函数传递一个对象，并在其中部分更新内部状态。

代码游场

```javascript
this.setState({ foo: bar });
```

但 `setState()` 不仅接受一个对象。在它的第二个版本中，你可以传递一个函数来更新状态。

代码游场

```javascript
this.setState((prevState, props) => {
  ...
});
```

为什么要这样做呢？在一个关键的情况下，使用函数比对象更有意义。当状态依赖于之前的状态时。

## 驯服状态

之前的章节已经向你展示了在大型应用程序中，状态管理可能是一个至关重要的话题。通常情况下，不仅是 React，许多 SPA（单页应用）框架都为此苦恼。近年来，应用程序变得越来越复杂。如今 Web 应用程序面临的一个大挑战是如何驯服并控制状态。

与其他解决方案相比，React 已经迈出了大步。单向数据流和在组件中管理状态的简单 API 是不可或缺的。这些概念让你更容易理解你的状态以及状态的变化。它使得在组件层面以及在一定程度上的应用层面进行推理变得更容易。

在一个不断增长的应用程序中，理解状态变化变得越来越困难。在 `setState()` 中使用对象而非函数来操作状态时可能会引入 bug。你必须在组件之间提升状态以共享必要的状态，或者隐藏不必要的状态。可能会出现这种情况：一个组件在组件树中离得非常远，而它的兄弟组件又依赖于它。你可能需要在整个组件树中共享状态。结论是，组件对状态管理的参与程度更高了。但根结底，组件的主要职责应该是表示 UI，不是吗？

正因为所有这些原因，存在一些独立的解决方案来处理状态管理。这是一个强大的领域。你可以使用不同的解决方案来解决你的问题。为了解决状态管理扩展的问题，你可能听过 Redux¹³⁷ 或 MobX¹³⁸ 。你可以在 React 应用中使用其中任何一种解决方案。随之而来的是扩展程序 `react-redux`¹³⁹ 和 `mobx-react`¹⁴⁰，将它们集成到 React 视图层中。

Redux 和 MobX 不在本本书的涵盖范围内。当你读完这本书后，将获得关于如何继续学习 React 及其生态系统的指导。一条学习路径可以是学习 React。在你深入研究外部状态管理话题之前，我建议阅读这篇文章¹⁴¹。它旨在让你对如何学习外部状态管理有更好的理解。

## Eject

以下步骤和知识对于将应用程序部署到生产环境**并不是必要的**。尽管如此，我想向你解释它。`create-react-app` 自带一个功能以保持可扩展性并防止厂商锁定（vendor lock-in）。厂商锁定通常发生在你投入某项技术，但未来没有退路时。幸运的是，在 `create-react-app` 中你有这样一个名为“eject”的退路。

在 `package.json` 中，你会找到启动、测试和构建应用程序的脚本。最后一个脚本是 **eject**。你可以尝试它，但没有回头路。**这是一次单向操作。一旦你 eject，就无法回去了！** 如果你刚开始学习 React，离开 `create-react-app` 方便的环境是没有意义的。

如果你运行 `npm run eject`，该命令会将所有配置和依赖拷贝到你的 `package.json` 和新的 `config/` 文件夹中。你会将整个项目转换为带有包含 Babel 和 Webpack 等工具的自定义设置。毕竟，你将对这些工具拥有完全控制权。

官方文档说 `create-react-app` 适用于小型到中型项目。你不应该有义务必须使用 "eject" 命令。

- **React 组件语法：** 实现 React 组件的可能性和最佳实践随着时间不断演变。你会在其他学习资源中发现许多编写 React 组件（尤其是 React 组件）的方法。你可以查看这个 [GitHub 仓库¹¹⁶⁰](https://github.com/the-road-to-learn-react/react-alternative-class-component-syntax) 寻找编写 React 类组件的替代方案。通过使用字段声明，未来你可以将它们写得更加简洁。

- **其他项目：** 在学习 React 之后，在学习新知识之前，将所学应用到项目中总是好的。有很多教程可以让你仅使用 React 就构建一些有趣的东西，比如井字游戏或简单的 React 计算器。[查看关于如何构建分页列表和无限滚动列表¹¹⁶¹](https://www.robinwiier.de/react-paginated-list/) 或 [将你的 React 连接到 Stripe 进行收费¹¹⁶²](https://www.robinwiier.de/react-svg-patterns/)。通过尝试这些微型应用来熟悉 React。

- **UI 组件：** 你不应该犯过早在项目中引入 UI 库的错误。你应该首先学习如何使用标准 HTML 元素从零实现并使用下拉菜单、复选框或对话框。这些组件的大部分将管理它们自己的状态。复选框必须知道自己是否选中。你应该将其实现为受控组件。在你完成所有基础实现后，可以引入使用复选框和对话框作为 React 组件的 UI 库。

- **代码组织：** 在阅读本书时，你可能会遇到关于代码组织的章节。如果你还没有这样做，现在应用这些更改。它将帮助你通过结构化的文件和文件夹（模块）来组织项目。此外，它还能帮助你理解和学习代码分割、可重用性、可维护性和模块 API 设计的原则。你的应用程序将会增大，你需要对其进行模块化结构处理。因此，现在开始会更好。

- **测试：** 本书对测试仅浅尝辄止。如果你不熟悉这个通用话题，可以深入研究 React 应用程序背景下的单元测试和集成测试概念。在实现层面，我建议坚持使用 Enzyme 和 Jest，以完善你在 React 中通过单元测试和快照测试进行的方法。

- **路由：** 你可以使用 [react-router¹¹⁶⁴](https://github.com/ReactTraining/react-router) 为你的应用程序实现路由。到目前，你的应用程序中只有一个页面。React Router 帮助你实现跨 URL 的多个页面。当你为应用程序引入路由时，你无法向 Web 服务器发送请求来下一页。路由器将在客户端为你完成一切。动手实践，并在你的应用程序中引入路由吧。

- **类型检查：** 在一个章节中，你使用了 React PropTypes 来定义组件接口。这是防止 bug 的通用良好实践。但 PropTypes 仅在运行时检查。你可以更进一步，在编译时引入静态类型检查。[TypeScript¹¹⁶⁵](https://www.typescriptlang.org/) 是一种流行的方法。但在 React 生态系统中，人们经常使用 [Flow¹¹⁶⁶](https://flow.org/)，如果你有兴趣让你的应用程序更健壮，我建议尝试一下。

- **React Native：** [React Native¹¹⁶⁷](https://facebook.github.io/react-native/) 将你的应用程序带到移动设备上。你可以将从 React 学到的知识应用于 iOS 和 Android 应用程序。一旦你学会了 React，React Native 的学习曲线不应该是陡峭的。两者共享相同的原理。你只会遇到与 Web 应用程序不同的移动组件布局。
