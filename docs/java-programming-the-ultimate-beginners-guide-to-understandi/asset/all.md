that Java programs are slower than comparable C or C ++ programs. However, one can not say that in a general way, because the speed of Java programs depends on various factors.The Virtual Machine (VM), on which the Java program runs, plays a significant role at first. In the early days, Java code was interpreted. This has resulted in performance degradation that is virtually eliminated with modern Java VMs. For example, SUN's Java VM "compiles" Java programs at runtime. The result is a program that is barely slower than a comparable one written in C or C ++.Java programs have a fundamental speed disadvantage when "starting up", because each Java program must first start its own VM. In addition, loading the classes takes a long time. Recent implementations of the VM (2004) overcome the latter drawback by allowing classes of several programs to be used simultaneously so that after the first Java application has been started, subsequent loading is eliminated.Java programs have another speed penalty in that the field boundaries are checked every time the field is accessed. Modern VMs can, however, mostly "optimize away" the check by placing the area check in front of the loop body during loop passes rather than every field access. In this way, about 80 percent of the otherwise required range checks can be eliminated.Another disadvantage of Java code is that many methods (more precisely: non-final instance methods) are virtual at first. Again, however, compilers can perform optimizations; and because Java's runtime environment is optimized for running virtual methods, virtual method calls in Java are significantly faster than most C ++ compilers.Last but not least, the library also plays a role. The SUN-favored swing library, which is primarily responsible for graphics output, has no reputation for being particularly fast.But there are also conditions under which Java programs have speed advantages over C or C ++ programs. For example, Java's object creation speed is very high. So when it comes to generating many objects in a short amount of time, Java programs can be beneficial in practice. Java also has fewer aliasing issues than C or C ++. Aliasing means that memory areas overlap formally different objects. Since there are fewer aliasing problems in Java, Java programs can be profitably used in numerical tasks. Whether your own Java program is faster or slower in practice than one written in C ++ depends on many other factors. As already indicated, Java programs can run on fast and slow VMs. And if you compare the speed with C
