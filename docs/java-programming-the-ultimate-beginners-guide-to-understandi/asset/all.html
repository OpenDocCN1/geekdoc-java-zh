Java Programming Language
When the first computers appeared, there were no high-level languages ​​ like FORTRAN, COBOL, Pascal, C / C ++, Java, which we now use. Since the hardware structures of the different machines were different, the machine languages ​​ of different brands and models of computers (the only language the machines understood) were different from each other. Therefore, the first programmers were able to get the computer to work only with the machine language of the machine they used. In addition to being challenging to learn the machine language, the machine language learned for a machine did not apply to different brands and models. To overcome this challenge, the first assembler language and then top-level languages appeared. High-level languages ​​ have brought great comfort to programmers. Because the programmer could write the source program in any language without thinking about the operating system and the machine, for example, a source program written in C could be compiled and run on every operating system and machine with the appropriate compiler. [Of course, we ignore minor deviations from the standard from different companies that write C compilers.]
High-level languages ​​ such as FORTRAN, COBOL, Pascal, Modula, C, which are now called procedural languages, have successfully served programmers for many years; they still do. But there was a problem. A source program that was compiled on a particular type of machine running under a particular operating system could only be run on those machines running under that operating system. When the operating system and/or machine type changes; so when the platform changed, the program could not run there; it had to be recompiled with a compiler suitable for the new platform. We call it platform dependency. What we mean by platform dependency is the fact that a source program is compiled with a specific compiler running under a particular operating system and can only be run on certain types of computers. For example, WindowsIt is not possible to run a computer program compiled on a PC running under the operating system on a machine running under the Macintosh or Linux operating system.
The emergence of different operating systems and a large number of different hardware on the market, the development of computer networks, machines connected to a network operating under different operating systems of different brands and models of computers have exacerbated the problem.
The solution to the problem required the creation of a language that could operate independently of the platform. This was solved with the Java language developed by Sun. The Sun company, however, set out to solve this big problem and not to solve it. He wanted to develop a language that would make the electrical appliances easy to use. That was soon realized that this could only be done on a common platform. In 1995, Sun's programmer James Gosling created Java on all platforms.
Gosling made a simple but wonderful invention. He designed a typical virtual machine that can be installed on different operating systems and different hardware. This virtual machine called JVM (Java Virtual Machine) was distributed free of charge. The JVM can be easily installed on any platform. Source programs written in Java are converted to a machine language that can work with the java compiler in the JVM. On behalf of java byte code called by the JVM, this program is interpreted and executed. Java byte code, in a way, is the function of source programs written and compiled in procedural languages.
Anyone who wants to run Java applications can install the JVM on their own machine. For this, JRE (Java Runtime Environment) will be enough to download and install the program. The JRE is installed on the computer once. Then all Java applications can run on this machine. When a java application runs on the machine, the JRE automatically creates the JVM virtual machine.
JVM is a program that runs when needed; Like any program, it is deleted from the main memory when it is done. Therefore, it is not possible to damage the machine. Nowadays, most browsers encountering java applications are capable of automatically downloading and installing the JRE. 
Java is a simple, modern, object-oriented, type-protected language with good features of C and C ++. More than that, it is capable of working on any platform. This ability enabled him to find a wide range of applications not only on computers but also on internet applications, mobile phones, gaming machines, and home appliances. Therefore, we can consider Java as both a programming language and an environment. In this environment, operating system, networks, internet programming, database, and all middleware (middleware) technologies are located.
In summary, Java is a simple language. Easy to learn. It has all the skills of a general-purpose language. C has good features of C ++ languages. User-friendly and fast application development tool.

Advantages of Java Programming
Java is now available for a variety of computer systems and has found widespread use. Similarly, Java comes with an extensive class library that includes support for (almost) everyday programming task. The concept of the virtual machine enables a once-compiled program code to run on any platform for which a Java VM is available. Re-compiling on the respective target platform (as with C / C ++) is no longer necessary. Another advantage is the so-called "applets." These are Java programs that can be launched within a web browser, making it very easy to deploy applications over the Internet.
A tangible advantage - not only for large projects - is the free availability of integrated development environments, especially the Eclipse platform. For many programmers, tool support is a crucial criterion when choosing a programming language. Here Java is one of the most actively supported platforms.
Java has become established as the industry standard.
Disadvantages of Java Programming
Java programs require a runtime environment to run. On many computers, this is not preinstalled and has to be set up separately. The same applies to other popular programming languages, such as .NET or Perl. Likewise, the Java applet runtime environments built into popular browsers are often outdated. If you want to write Java programs for these browsers, you have to restrict yourself to an old language version or install a current runtime environment on the browser.
Furthermore, Java is not suitable for developing near-system programs such as hardware drivers. This is mainly because Java programs on theoretically arbitrary computer architectures and operating systems should be able to run unchanged. This abstraction no longer allows direct access to specific hardware-related functions. Other languages ​​ such as C or C ++ are more suitable for such tasks.
Speed ​ ​ of Java programs 
The prevailing opinion on the speed of Java programs is that Java programs are slower than comparable C or C ++ programs. However, one can not say that in a general way, because the speed of Java programs depends on various factors.
The Virtual Machine (VM), on which the Java program runs, plays a significant role at first. In the early days, Java code was interpreted. This has resulted in performance degradation that is virtually eliminated with modern Java VMs. For example, SUN's Java VM "compiles" Java programs at runtime. The result is a program that is barely slower than a comparable one written in C or C ++.
Java programs have a fundamental speed disadvantage when "starting up", because each Java program must first start its own VM. In addition, loading the classes takes a long time. Recent implementations of the VM (2004) overcome the latter drawback by allowing classes of several programs to be used simultaneously so that after the first Java application has been started, subsequent loading is eliminated.
Java programs have another speed penalty in that the field boundaries are checked every time the field is accessed. Modern VMs can, however, mostly "optimize away" the check by placing the area check in front of the loop body during loop passes rather than every field access. In this way, about 80 percent of the otherwise required range checks can be eliminated.
Another disadvantage of Java code is that many methods (more precisely: non-final instance methods) are virtual at first. Again, however, compilers can perform optimizations; and because Java's runtime environment is optimized for running virtual methods, virtual method calls in Java are significantly faster than most C ++ compilers.
Last but not least, the library also plays a role. The SUN-favored swing library, which is primarily responsible for graphics output, has no reputation for being particularly fast.
But there are also conditions under which Java programs have speed advantages over C or C ++ programs. For example, Java's object creation speed is very high. So when it comes to generating many objects in a short amount of time, Java programs can be beneficial in practice. Java also has fewer aliasing issues than C or C ++. Aliasing means that memory areas overlap formally different objects. Since there are fewer aliasing problems in Java, Java programs can be profitably used in numerical tasks. 
Whether your own Java program is faster or slower in practice than one written in C ++ depends on many other factors. As already indicated, Java programs can run on fast and slow VMs. And if you compare the speed with C ++, of course, the implementation of the underlying C ++ compiler also plays a role.
In any case, the practical speed difference is not significant in most cases today.
