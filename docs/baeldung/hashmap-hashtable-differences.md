Java 中的`Hashtable`和`HashMap`%0A%0A`Hashtable`和`HashMap`非常相似——都是实现了`Map`接口的集合。%0A%0A另外，`put()`、`get()`、`remove()`和`containsKey()`方法提供了常数时间性能 O(1)。在内部，这些方法基于使用存储桶存储数据的散列的一般概念。%0A%0A这两个类都不保持元素的插入顺序。换句话说，当我们迭代这些值时，添加的第一项可能不是第一项。%0A%0A但是它们也有一些不同之处，在某些情况下使一个比另一个更好。让我们仔细看看这些差异。%0A%0A## 3. `Hashtable`与`HashMap`的区别%0A%0A### 3.1. 同步%0A%0A首先，**`Hashtable`是线程安全的**，可以在应用程序的多个线程之间共享。%0A%0A另一方面，`HashMap`是不同步的，如果没有额外的同步代码，就不能被多线程访问。我们可以使用`Collections.synchronizedMap()`来制作一个`HashMap`的线程安全版本。我们也可以通过使用`synchronized`关键字来创建定制的锁代码或使代码线程安全。%0A%0A`HashMap`不同步，因此它比`Hashtable`更快，使用的内存更少。通常，在单线程应用程序中，非同步对象比同步对象更快。%0A%0A### 3.2. 空值%0A%0A另一个区别是`null`处理。`HashMap`允许添加一个以`null`为关键字的`Entry`，以及多个以`null`为值的条目。相比之下，**`Hashtable`根本不允许`null`**。我们来看一个`null`和`HashMap`的例子:%0A%0A```java%0AHashMap<String, String> map = new HashMap<String, String>();%0Amap.put(null, "value");%0Amap.put("key1", null);%0Amap.put("key2", null);%0A```%0A%0A这将导致:%0A%0A```java%0AassertEquals(3, map.size());%0A```%0A%0A接下来，让我们看看`Hashtable`有什么不同:%0A%0A```java%0AHashtable<String, String> table = new Hashtable<String, String>();%0Atable.put("key", null);%0A```%0A%0A这导致了一个`NullPointerException`。添加一个以`null`为关键字的对象也会导致一个`NullPointerException`:%0A%0A```java%0Atable.put(null, "value");%0A```%0A%0A### 3.3. 元素迭代%0A%0A`HashMap`使用`Iterator`来迭代值，而`Hashtable`使用`Enumerator`来迭代值。`Iterator`是`Enumerator`的继任者，消除了它的一些缺点。例如，`Iterator`有一个`remove()`方法从底层集合中移除元素。%0A%0A`Iterator`是一个快速失效迭代器。换句话说，当底层集合在迭代过程中被修改时，它抛出一个`ConcurrentModificationException`。让我们看看快速失效的例子:%0A%0A```java%0AHashMap<String, String> map = new HashMap<String, String>();%0Amap.put("key1", "value1");%0Amap.put("key2", "value2");%0A%0AIterator<String> iterator = map.keySet().iterator();%0Awhile(iterator.hasNext()){ %0A    iterator.next();%0A    map.put("key4", "value4");%0A}%0A```%0A%0A这抛出了一个`ConcurrentModificationException`异常，因为我们在迭代集合时调用了`put()`。%0A%0A## 4. 什么时候选择`HashMap`而不是`Hashtable`%0A%0A对于非同步或单线程应用程序，我们应该使用`HashMap`。%0A%0A值得一提的是，从 JDK 1.8 开始，`Hashtable`已经被弃用。不过，`ConcurrentHashMap`是`Hashtable`的绝佳替代品。我们应该考虑在多线程应用中使用`ConcurrentHashMap`。%0A%0A## 5.
