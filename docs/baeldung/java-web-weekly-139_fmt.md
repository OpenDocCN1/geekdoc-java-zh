## 2. 技术和思考

#### [>> DDD 解码——应用服务解释](https://web.archive.org/web/20220812063648/http://blog.sapiensworks.com/post/2016/08/19/DDD-Application-Services-Explained)【sapiensworks.com】

#### [>> DDD 解码——领域关系解释](https://web.archive.org/web/20220812063648/http://blog.sapiensworks.com/post/2016/08/24/DDD-Relationships)【sapiensworks.com】

DDD 绝对是增强你的架构能力的最好方式之一，这个系列清晰扼要地解释了一些基本概念。

#### [>> 搞定 JSON](https://web.archive.org/web/20220812063648/https://www.tbray.org/ongoing/When/201x/2016/08/20/Fixing-JSON)【tbray.org】

关于**在一些小调整的帮助下使 JSON 变得更好**的内部注释。

#### [>> 要框架还是要解决方案？](https://web.archive.org/web/20220812063648/http://www.ontestautomation.com/do-you-want-a-framework-or-a-solution/)【ontestautomation.com】

非常值得**以一种结构化的、有意识的方式对待测试自动化**，最重要的是以开放的心态去选择一个你可能还不熟悉的工具。否则——这是我的经验之谈——你可能会以不可靠测试的老鼠窝而告终。

#### [>> 多租户、多集群的伸缩 Elasticsearch](https://web.archive.org/web/20220812063648/https://www.loggly.com/blog/scaling-elasticsearch-for-multi-tenant-multi-cluster/)【loggly.com】

我真的很喜欢通读这篇文章，主要是因为我在 Elasticsearch 平台还不太成熟的时候，在该平台上实现了一个多租户实现。这是一个坚实的平台，但并非没有非常真实和棘手的问题。
