1        Getting Started
1.1     Java History
Java was created by James Gosling and his team at Sun Microsystems in the early 90s. The first version of Java was 1.0. Oracle acquired Sun Microsystems in 2010. At the time of writing this, the latest release of Java is Java 14.
1.2     Why Java
Java is Object oriented .
Earlier programming languages like C were procedural. The downside of a procedural language is that programs become large and complex.
To manage this complexity, Object oriented programming was conceived. Object oriented programming organises a program around its data and thus simplifies programming.
Java is platform independent.
Other programming languages like C or C++ are compiled into files that are operating system specific.
Java on the other hand is compiled into bytecode which is run within the Java Virtual Machine or the JVM. The JVM sits on top of the operating system. So, the same compiled file can be run on different operating systems.

13.6 Java’s exception hierarchy

13.6.2                      Exception
The java.lang.Exception class represents errors that can occur due to code and that an application can catch and handle. Exceptions are of two types as follows:
Unchecked Exceptions
The Exception class has an important subclass which is java.lang.RuntimeException . RuntimeException and all its subclass are known as unchecked exceptions. This is because the compiler does not force you to handle such exceptions. So even if code that might potentially throw an unchecked exception is written, the compiler does not cause an error. Some examples of unchecked exceptions are ArithmeticException , ArrayIndexOutOfBoundsException , etc
Checked Exceptions
All subclasses of Exception other than RuntimeException are known as checked exceptions. This is because these are checked by the compiler. So, if you write code that can cause a checked exception, a compilation error occurs if the exception is not caught and handled or declared in the throws clause.  Some examples of checked exceptions are IOException , AWTException , etc

17.2 Lambda Expressions
Lambda expressions are anonymous functions. They specify a method without a method name. They are used to implement the abstract method in a functional interface
17.2.1                      Lambda Expression Syntax
Lambda expressions have the following syntax:
  • Parameters – A lambda expression can accept zero or more parameters
  • Lambda operator – The -> sign is known as the lambda operator
  • Lambda body – This consists of the code that needs to be executed
Lambda Syntax Points to Remember
  • If a lambda expression does not accept any parameters, empty parentheses need to be specified
  • If a lambda expression accepts a single parameter, the parentheses around the parameter can be skipped
  • If a lambda expression accepts more than one parameter, the parameters need to be specified in parentheses and separated by commas
  • The data type of the parameters need not be specified, it is inferred
  • If the body of the lambda expression consists of a single statement, the curly brackets can be skipped
  • When a lambda expression returns a value, the return keyword maybe skipped if the body of the lambda expression consists of a single statement.
17.2.2                      Implementing Functional Interface with Lambda Expressions
