## 第 1 章：Python 编码通用概念

在我们正式进入书籍之前，这些是你应该意识到的编码通用概念；这些概念将让你的生活变得更轻松。

### 显式代码

虽然你可以用 Python 许多许多奇奇妙妙的事情，但最好保持其简单直观和显式。

**坏例子：**

```python
def make_complex(*args):
    x, y = args
    return dict(**locals())
```

**好例子：**

```python
def make_complex(x, y):
    return {'x': x, 'y': y}
```

比较这些示例；在后者的代码示例中，我们显式地从调用者那里接收 `x` 和 `y`，返回是一个显式的字典。

编写这段代码的开发者只需看第一行和最后一行就能知道要做什么；坏例子并非如此。

### 一行一个语句

虽然允许并且在很多情况下受到推崇像复合语句（如列表推导式）这样的语句，但在同一行代码上拥有两个互不关联的语句并不是一种好的做法。

**坏例子：**

```python
print 'one'; print 'two'
if x == 1: print 'one'

if <complex comparison> and <other
complex comparison>:
  # do something
```

**好例子：**

```python
print 'one'
print 'two'

if x == 1:
  print 'one'

cond1 = <complex comparison>
cond2 = <other complex comparison>
if cond1 and cond2:
  # do something
```

### 返回值

当你得到一个复杂性不断增长的函数时，在函数体中使用多个 `return` 语句并非罕见。然而，如果你想保持清晰的意图和良好的可读性，你应该尝试不要从函数体中的多个点返回值。

当涉及到函数内部返回值时，有两种情况：来自正常处理函数返回的结果，以及由于输入参数错误或任何导致函数无法完成计算的原因而产生的错误。

如果你不想在后的情况下抛出异常，那么可能需要返回诸如 `False` 或 `None` 的值，作为函数无法完成计算的指示。在这种情况下，最佳实践是尽快返回。

尽管如此，如果一个函数包含多个可能的出口，调试结果可能会变得非常困难，因此最好只保持一个出口。这有助于理清代码路径，而且如果你有多个出口，可能意味着你需要重新审视代码并进行整理。

**示例：**

```python
def complexfunction(c, b, a):
    if not c:
        return None # 抛出异常可能会更好
    if not b:
        return None # 抛出异常可能会更好
    # 尝试从 c, b 和 a 生成 x
    # 如果成功则不要返回 x
    if not x:
        # 对 x 的方案 B 计算
        return x # 单一出口对于值 x 将有帮助
```

## 第 2 章：编程建议

这些是编写 Python 代码的基本建议，如果你希望你的代码更有效、高效且具有可读性，就应该遵循这些建议。

- 你的代码编写方式不能损害其他 Python 实现，例如 `IronPython`、`Jython`、`PyPy`、`Psyco` 和 `Cython`。

  例如，你永远不要依赖 `CPython` 中高效的字符串拼接（形式为 `a=a+b` 或 `a+=b`）。这是一种相当脆弱的优化，尽管它在 `CPython` 中非常高效，因为它并不适用于所有类型，也不会出现在任何不使用引用计数的 Python 实现中。

  相反，当你使用对性能敏感的库部分时，你应该使用 `.join()` 形式。这将确保在所有不同的 Python 实现中连接都是线性的。

- 永远不要使用等值运算符对 `None` 等单例进行比较。相反，请使用 `is` 或 `not`。

  你还应该警惕使用 `if x` 而实际上你应该使用 `if x is not None`。

  这种情况的一个例子是，当你测试一个默认值为 `None` 的参数或变量是否真的被设置为了不同的值时。另一个值的代码的类型在布尔上下文中可能为假。

- 与其使用运算符 `not is`，不如你应该使用 `is not`。虽然它们在功能上是等同的，但前者的可读性评分较低，因此后者更受青睐。例如：

  **推荐：**

  ```python
  if foo is not None:
  ```

  **不推荐：**

  ```python
  if not foo is None
  ```

- 当你在使用富比较实现排序操作时，你应该实现所有的 6 个操作，而不是依赖其他代码来执行比较。这些操作是（`__eq__`、`__lt__`、`__ne__`、`__ge__`、`__gt__`、`__le__`）。

  为了减少工作量，有一个特定的装饰器可以帮助生成缺失的比较方法。该装饰器是 `functools.total_ordering()`。

  风格指南表明 Python 假设自反射规则。因此，Python 解释器可能会更改交换 `y > x` 与 `x < y` 的操作，或者可能会交换 `y >= x` 与 `x <= y`。

  你可能还会发现参数 `x == y` 已被交换为 `x != y`。`min()` 和 `sort()` 操作肯定会使用 `<` 运算符，而 `max()` 函数将使用 `>` 运算符。然而，作为最佳实践指南，你应该使用所有的操作以防产生混淆。

- 与其使用将 lambda 表达式绑定到标识符的赋值语句，不如使用 `def` 语句。

  **好的示例：**

  ```python
  def f(x): return 2*x
  ```

  **坏的示例：**

  ```python
  f = lambda x: 2*x
  ```

  第一个示例显示，赋予函数对象的名称是 `'f'` 而不是总的 `<lambda>`。这对于字符串表示以及回溯跟踪是最有用的，而且通过使用赋值语句，你放弃了 lambda 表达式相比 `def` 语句提供的唯一优势——即它可以被嵌入到更大的语句中。

- 当你想要派生异常时，请使用 `Exception` 而不是 `BaseException`。后者的继承是留给那些捕获它们几乎总是错误的异常的。

  当你设计异常层次结构时，应根据捕获异常时可能需要的质量来构建，而不是根据异常抛出的位置。始终回答一个问题“发生了什么错误？”而不是仅仅说某事错了。使用类命名的约定，但请记住为产生错误的异常类添加“Error” 后缀。

  没有必要对那些不是错误且用作流控制或其他形式的信号的异常添加任何特殊后缀。

- 当你使用异常链时，请仅在需要的地方使用它。

  当你故意替换内部异常时，请确保将正确的细节重新定位到新的异常中。这些示例包括：在将 `KeyError` 转换为 `AttributeError` 时确保属性的名称被保留，或者在将原始异常文本嵌入到新异常的消息中。

- 当使用 Python 2 且抛出异常时，请始终使用 `raise ValueError('message')` 而不是 `raise ValueError 'message'`。

  这是因为第二个示例在 Python 3 中既不是有效的也不是合法的语法。此外，使用包含的括号意味着，当你添加字符串格式化或异常参数过长时，不需要在行末使用续行符。

- 当你捕获异常时，应尽可能提到具体的异常，而不是使用裸的 `except:` 子句。

  **例如：**

  ```python
  try:
      import platform_specific_module
  except ImportError:
      platform_specific_module = None
  # KeyboardInterrupt 和 SystemExit 异常将被裸的 except: 子句捕获，这使得使用 CTRL+C 中断程序变得困难得多，而且它们还会掩盖可能存在的问题。
  ```

  如果你想捕获程序中信号错误的每个异常，请使用 `except Exception:`。

  一个原则是仅在以下两种情况下使用裸的 `except:` 子句：

  1. 如果回溯是由异常处理程序打印的；这样，用户就能感知到任何错误。
  2. 如果需要清理工作但代码允许通过 `raise` 将异常向上传播。更有效的方法是使用 `try...finally`。

- 当你将捕获的异常绑定到名称时，使用 `as`。

  ```python
  try:
      ...
  except Exception as e:
      ...
  ```

- 不要包含任何需要大量尾部空格的字符串字面量，因为这些空格无法区分，且某些文本编辑器会将它们删除。

- 不要使用 `==` 来比较布尔值与 `True` 或 `False`：

  **良好的示例：**

  ```python
  if greeting:
  ```

  **错误的示例：**

  ```python
  if greeting == True:
  ```

  **更糟糕的示例：**

  ```python
  if greeting is True:
  ```

## 第 3 章：代码布局

### 与起始分隔符对齐

```python
foo = long_function_name(var_four,
                         var_three,
                         var_two,
                         var_one)
```

### 包含了更多的缩进，以便将这与代码的其他部分区分开

```python
def long_function_name(
        var_four, var_three, var_two,
        var_one):
    print(var_four)
```

### 应该使用悬挂缩进来增加层级

```python
foo = long_function_name(
    var_four, var_three,
    var_two, var_one)
```

### 错误的方法

**第一行是不允许的，当你没有使用垂直对齐时：**

```python
foo = long_function_name(var_four,
                         var_three,
                         var_two, var_one)
```

**需要更多的缩进，因为缩进与其余部分无法区分：**

```python
def long_function_name(
    var_four, var_three, var_two,
    var_one):
    print(var_four)
```

当涉及到延续行时，4 个空格缩进的规则是可选的：

**悬挂缩进*可以*缩进比多或少于 4 个空格。**

```python
foo = long_function_name(
    var_four, var_three,
    var_two, var_one)
```

当你使用带有长条件的 `if` 语句时，该条件可以写在多行。请注意，对于条件语句中的其余行，很容易创建一个 4 个空格的自然缩进——使用一个 2 个字符的关键字（例如 `if`）配合一个空格和一个左括号。然而，在视觉上，这看起来可能与 `if` 语句内部缩进的代码某种不兼容，因为 `if` 内部的代码已经有了 4 个空格的缩进。对于是否将这些条件行与嵌套内部的代码区分开，并没有固定的位置，但你可以使用几个可以接受的选项，包括但不限于：

**没有使用额外的缩进：**

```python
if (this_is_one_thing and
    that_is_something_else):
    do_this()
```

**添加一条注释，这将在支持语法高亮的编辑器中提供一些帮助：**

```python
if (this_is_one_thing and
    that_is_something_else):
    # 因为两个条件都为真，我们可以
    # 进行调整。
    do_this()
```

**为条件延续行添加更多缩进：**

```python
if (this_is_one_thing
    and that_is_something_else):
    do_this()
```

现在，当你有一个多行结构时，闭合括号、圆括号或方括号可以与两个位置之一——要么在列表末尾行的非空格起始字符下方对齐：

```python
my_list = [
    6, 5, 4,
    3, 2, 1,
]

result = a_function_that_will_take_arguments(
    'f', 'e', 'd',
    'c', 'b', 'a'
)
```

或者它也可以与多行结构中第一行的起始字符对齐：

```python
my_list = [
    6, 5, 4,
    3, 2, 1,
]

result = a_function_that_will_take_arguments(
    'f', 'e', 'd',
    'c', 'b', 'a'
)
```

## 第 4 章：惯用法

编程惯用法简单来说就是 Python 代码应该的编写方式。我们通常将惯用代码称为 Python 风格代码，尽管编写某些内容通常有一种非常明显的方法，但对于 Python 新手来说，Pythonic 代码的实际编写方式可能有些晦涩。因此，你需要学习一些良好的惯用法，其中一些常见的有：

### 解包

只要你知道元组或列表的长度，解包允许你为每个元素赋予一个名称。例如，`enumerate()` 为列表中的每个项都返回一个包含 2 个元素的元组：

```python
for index, item in enumerate(this_list):
    # 对 index 和
    # item 进行操作
```

你也可以使用解包来交换变量：

```python
b, a = a, b
```

你还可以使用嵌套解包：

```python
c, (b, a) = 3, (2, 1)
```

当 Python 3 实现时，它带来了一种新的扩展解包方法：

```python
c, *the_rest = [3, 2, 1]
# c = 3, the_rest = [2, 1]
c, *the_middle, c = [4, 3, 2, 1]
# c = 4, the_middle = [3, 2], c = 1
```

### 创建忽略的变量

如果你想赋值某些内容但不需要使用该变量，你会使用 `__`。例如：

```python
filename = 'footbar.txt'
basename, _, ext = filename.partition('.')
```

**注意：**

你经常会看到建议使用单下划线 (`_`) 作为丢弃变量，而不是使用双下划线 (`__`)。这样做的问题在于，单下划线 `_` 倾向于在 `gettext()` 函数中被用作别名。它还用于存储交互式提示符处上一次操作的值。当你使用双下划线 `__` 时，它是清晰且方便的。它还消除了意外干扰单下划线其他用处的风险。

### 创建长度为 N 的列表

要创建一个长度为 N 的列表，使用列表推导式：

```python
zeros = [0 for _ in range(n)]
```

### 从列表创建字符串

创建字符串最常见的惯用法是 `join()`：

```python
letters = ['a', 'b', 'c']
word = ''.join(letters)
```

### 在集合中查找项目

偶尔，你需要搜索一个集合，有两种方法可以实现这一点——使用列表或集合：



```python
s = {'a', 'b', 'c'}
l = ['a', 'b', 'c']
```

现在，这两个函数看起来完全一样：

```python
def lookup_set(s):
    return s in s

def lookup_list(l):
    return s in l
```

由于性能存在差异，在以下情况下，使用集合或字典比列表会更好：

- 集合包含大量项目
- 需要频繁搜索项目
- 没有重复项目

唯一的例外是，你 200% 确定你的代码永远不会被那些不通或不读你语言的人阅读。

## 块注释

块注释倾向于适用于其后的部分或全部代码。注释的缩进方式应与其所指的代码完全一致，且每个块的每一行必须以 `#` 和后跟一个空格开头。唯一的例外是你在注释中使用了缩进文本。每个块注释中的所有段落必须用包含一个 `#` 的行来隔开。

### 内联注释

这些应该尽可能少地使用。回顾一下，内联注释是放置在与语句同一行的注释。内联注释与语句之间至少要有两个空格分隔，并且它们必须以一个 `#` 和后跟一个空格开头。

老实说，你应该避免使用内联注释，因为它们并不是真正必要的，并且会引起不必要的注意力分散。

例如，你不应该这样做：

```
x = x + 1    # 将 x 加1
```

但是，有时候，这可能是有用的：

```
x = x + 1  # 补偿
for the border
```

# 第 6 章：约定

为了让你的 Python 代码更易读，请遵循这些约定：

查看你的变量是否等于一个常量。没有必要将值与 `0`、`None` 或 `True` 进行显式比较；相反，你可以将其加入 `if` 语句。查看下面的示例：

### 一个糟糕的示例

```python
if attr == True:
    print 'True!'
```

```python
if attr == None:
    print 'attr is None!'
```

### 一个良好的示例

```python
## 只看值即可
if attr:
    print 'attr is the best!'
```

```python
### 或者检查相反的情况是什么
if not attr:
    print 'attr is the worst!'
```

```python
### 或者，由于 None 被视为假，
### 确保你对它进行了显式检查
if attr is None:
    print 'attr is None!'
```

## 如何访问字典元素

不要使用 `dict.has_key()` 方法，而是使用语法 `x in d` 或使用 `dict.get()` 来传递默认参数。

### 一个糟糕的示例

```python
d = {'hello': 'world'}
if d.has_key('hello'):
    print d['hello']      # 输出 'world'
else:
    print 'the_default_value'
```

### 一个良好的示例

```python
d = {'hello': 'world'}

print d.get('hello', 'default_value') # 输出 'world'
print d.get('thingy', 'default_value') # 输出 'default_value'
```

```python
### 或者：
if 'hello' in d:
    print d['hello']
```

## 用简短的方法操作列表

在操纵列表时，你不需要长篇大论；当你想要对列表执行操作时，使用列表推导式或 `filter()` 或 `map()` 函数来使用简洁的语法。

### 一个糟糕的示例

```python
### 过滤所有大于 4 的元素
a = [5, 4, 3]
b = []

for i in a:
    if i > 4:
        b.append(i)
```

### 一个良好的示例

```python
a = [5, 4, 3]
b = [i for i in a if i > 4]
### 或者：
b = filter(lambda x: x > 4, a)
```

### 另一个糟糕的示例

```python
### 为列表中的所有成员加 3
a = [5, 4, 3]
for i in range(len(a)):
    a[i] += 3
```

### 另一个良好的示例

```python
a = [5, 4, 3]
a = [i + 3 for i in a]
### 或者：
a = map(lambda i: i + 3, a)
```

你也可以使用 `enumerate()` 函数来记录你在列表中的位置：

```python
a = [5, 4, 3]
for i, item in enumerate(a):
    print(i, item)
## 输出
### 0 5
### 1 4
### 2 3
```

这个函数比尝试手动处理计数器更易读，而且对于迭代器来说要优得多。

## 从文件读取

当你想要从文件中读取内容时，最好使用 `with open` 语法，因为这将会自动为你关闭文件。

### 一个糟糕的示例

```python
f = open('file.txt')
a = f.read()
print a
f.close()
```

### 一个良好的示例

```python
with open('file.txt') as f:
  for line in f:
    print line
```

使用 `with` 语句要高效得多，因为它确保即使在 `with` 块包含异常，文件始终被关闭。

## 换行

逻辑代码行有接受的限制，当你有一行过长的代码时，应该将其拆分到几行。你的 Python 解释器会处理连续的行，只要每行的最后一个字符是反斜杠 (`\`)，它就会将行连接起来。然而，尽管这有时很有用，但你真的应该避免这样做，因为可能是脆弱的。如果你在反斜杠后添加了空格，就会出错。

```python
*args is equal to ('Galactus', 'Dad', 'God')
```

然而，你真的应该谨慎地使用这种结构，因为它确实有一些缺点。如果向函数发送一个包含相同或相似性质参数的列表，更好的定义是一个只有一个参数的函数；该单个参数将是一个序列或列表。例如，如果 `send` 有多个接收者，最好使用显式定义：`send('Hello', 'God', 'Dad', 'Galactus')`，然后使用 `send('Hello', ['God', 'Dad', 'Galactus'])` 调用它。这样，函数用户可以提前更改接收者列表，并为传递任何无法解包的序列（包括迭代器）提供了可能。

+ 4. 任意关键字参数字典 - 这是向函数传递参数的方式。如果函数需要未知数量的命名参数数组，可以使用 `**kwargs` 结构。在函数体内，`**kwargs` 是一个字典，包含了所有已传递且未被函数签名中其他关键字参数捕获的命名参数。

然而，你应该采取与处理任意参数列表时相同的谨慎程度，因为原因大体相同。这些是强大的技术，只有在你证明有必要使用它们时才应该使用。如果有更清晰、更简单的结构可以完成工作，则绝对不应该使用它们。

这真的取决于你这个程序员来决定哪些函数参数是可选关键字，哪些是位置参数，并决定是否应该使用更高级的技术来传递参数。

保持简单并遵循以下编写 Python 函数的规则：

- 具有良好的可读性 – 名称和参数不需要任何解释
- 易于更改 – 你可以添加关键字参数而不会破坏其他代码。

# 第 8 章：命名规范

坦率说，Python 库的命名规范有些混乱，因此我们永远无法做到完全一致。然而，对于所有新的包和模块，有一些推荐的命名标准，这些（包括任何第三方框架）都必须按照这些标准编写。尽管如此，如果你正在使用具有不同风格的现有库，请坚持该风格，因为一致性是优的，特别是在可读性方面。

要学习的第一条也是最重要的原则是：当你使用作为公共 API 可部分的名称时，你必须使用反映该名称用途的约定，而不是其实现方式。

## 描述性

有很多不同的命名风格，因此独立于使用情况来识别使用的是哪种风格是有帮助的。这些是最常见的区分命名风格：

- `B` – 单大写字母
- `b` – 单个小写字母
- `lowercase_with_underscores`（下划线小写）
- `lowercase`（全小写）
- `UPPERCASE_WITH_UNDERSCORES`（下划线大写）
- `UPPERCASE`（全大写）
- `CapitalizedWords` – 通常被称为驼峰命名（`CamelCase`），因为字母看起来有些*起伏*
- `mixedCase` – 与 `CamelCase` 不同，因为第一个字母是小写的
- `Capital_Words_With_Underscore` – 不好看的风格！

> * 在 `CamelCase` 中使用缩写词时，你应该确保所有缩写词字母都是大写的。例如，与其使用 `HttpServerError`，不如使用 `HTTPServerError`。

你也可以另一种风格，即添加一个唯一的短前缀，将一组相关的名称放在一起。这在 Python 中并不常见，但我提到它是为了让你知道它的存在。例如函数 `os.stat()` – 它将返回一个元组，其中包含名称如 `st_size`、`st_mode`、`st_mtime` 等的小项。

这些是一些使用尾随或前导下划线的形式，通常可以与任何大小写约定结合：

- `_one_leading_underscore`（前导下划线）：这通常是“内部使用”的指示，但并不强。
- `One_trailing_underscore`（尾随下划线）：通常用于防止与 Python 关键字冲突，例如：`Any.Toplevel(master,class='ClassName')`
- `__two_leading_underscores`（双前导下划线）：当你命名类属性时，这会触发名称修饰（mangling），例如：（在类 `FootBar` 内部，`__boo` 将变成 `__FootBar_boo`）
- `__two_leading_and_two_trailing_underscores`（双前导双尾下划线）：是位于用户控制命名空间中的属性或“魔法”对象。例如：`__init__`、`__file__` 或 `__name__`。

## 规范性

这些是你应该避免的：

在编写单字符变量名时，永远不要使用 `'O'`（大写 o）、`'l'`（小写 l）或 `'I'`（大写 i）。取决于你使用的字体，这些可能会与数字 `'o'` 和 `'1'` 混淆——如果你发现自己正在考虑使用 `'l'`，请用大写的 `'L'`。

## 模块和包的命名

所有模块名称都应该是短且全小写的。你可以在模块名中使用下划线，但仅当它能提高可读性时。Python 包也是如此——使用短且全小写的名称，但不要使用下划线。

如果你有一个用 C 或 C++ 编写的扩展模块，并配有一个具有面向对象接口的 Python 模块，则 C 或 C++ 模块将具有前导下划线，例如 `_socket`。

## 类名

类名通常使用 `CapWords` 或 `CamelCase` 约定。

内置名称有它们自己独立的约定，通常是单个单词或两个单词合并为一个，例如 `Hello` 或 `HelloWorld`。`CamelCase` 约定倾向于用于内置常量和异常名称。

## 类型变量名

类型变量的名称通常使用 `CamelCase`，并且优于短名称，例如 `Num`、`AnyStr`。你应该为变量添加后缀（`_co` 或 `_contra`）来声明逆变或协变行为。

例如：

```python
from typing import TypeVar

## 将变为

VT_co = TypeVar('VT_co', covariant=True)
KT_contra = TypeVar('KT_contra', contravariant=True)
```

### 异常名称

异常是类，因此，你应该使用类的约定进行命名。尽管如此，如果异常是一个错误，请确保在名称上使用 `'Error'` 后缀。

### 全局变量

只要变量在单个模块内部使用，其命名规范与函数命名相同。

### 函数名

所有函数名均为小写，并在需要的地方用下划线分隔单词，以提高可读性。

### 实例变量和方法名

再次，函数的命名约定也适用于此——使用带下划线的写写。如果你使用实例变量或非公共方法，可以使用单个下划线。为了防止名称与子类冲突，应使用双前导下划线作为触发名称修饰的方法。

当调用这些规则时，名称将与类名结合。例如，类 `Foo` 包含属性 `__init__`。不能通过 `Foo.__init__` 访问。根据规则，只有当名称可能与类属性冲突时，你才使用双下划线。

### 常量

这些通常定义在模块级，且全大写并用下划线分隔，例如 `MAX_OVERFLOW`。

## 继承设计

必须遵守的规则之一是确定实例变量或类方法是非公共还是公共。如果你无法决定，请选择非公共，因为你以后很容易将其改为公共，而将公共改为非公共并不那么容易。

公共属性是与类无关的客户端会使用的属性，而非公共属性是不打算供第三方使用的属性。对于公共属性，你保证了从开始到结束的后兼容性；而对于非公共属性，你不保证，并且可以删除或更改该属性。注意，没有使用“私有”一词，这是因为 Python 语言中没有真正的私有属性。

另一个属性类别是受保护属性。在 Python 中，它们属于子类 API。有些类专门设计为被继承的类，无论是为了扩展还是修改某些行为。当你设计这样一个类时，始终务必确保对属性做出明确决定——它们是公共的、还是仅供基类使用的，还是属于子类 API？

结合所有这些，这些是 Python 指南：

- 公共属性不得有前导下划线
- 如果公共属性与关键字冲突，在属性名称末尾添加尾随下划线。这是比使用...要优的方法。

拼写或缩写上的错误。

- 对于公共数据属性，最好的方法是只暴露属性名称，而不使用任何复杂的修改器（mutator）或访问器（accessor）方法。如果简单属性需要扩展其功能行为，Python 可以让你轻松实现。
- 如果你正在使用一个将被子类的类，并且你使用的属性也不会被子类使用，请考虑在开头添加两个下划线，但不要添加任何末尾下划线。这将触发名称修饰（name mangling），有助于降低当子类具有同名属性时发生名称冲突的风险。

# 第 9 章：在语句和表达式中使用空格

首先，是一些关于空格的槽点：

在以下情况下不要使用不必要的空格：

- 在大括号、中括号或圆括号内部：

### 良好的示例

```
ham(spam[1], {eggs: 2})
```

### 错误的示例

```
ham( spam[ 1 ], { eggs: 2 } )
```

- 在冒号、分号或逗号正之前：

### 良好的示例

```
if x == 4: print x, y; x, y = y, x
```

### 错误的示例

```
if x == 4: print x, y; x, y = y, x
```

然而，当你使用切片（slice）时，冒号类似于二进制运算符，两侧应包含等的空格。当你使用扩展切片（extended slice）时，两个冒号必须包含完全相同的空格级别。唯一的例外是省略了切片参数以及对应的空格。

### 良好的示例

```
spam[1:8], spam[1:8:2], spam[:8:2], spam[1:2], spam[1:8:]
```

```
spam[lower:upper], spam[lower:upper],
spam[lower::step]
spam[lower+offset : upper+offset]
spam[: upper_fn(x) : step_fn(x)], ham[::
step_fn(x)]
spam[lower + offset : upper + offset]
```

### 错误的示例

```
spam[lower + offset:upper + offset]
spam[1: 8], ham[1:8], ham[1:8 :2]
spam[lower : : upper]
spam[: upper]
```

- 在开始函数调用参数列表的左圆括号之前：

### 良好的示例

```
ham(1)
```

### 错误的示例

```
ham (1)
```

- 在开始切片或索引的左圆括号之前：

### 良好的示例

```
dict['key'] = 1st[index]
```

### 错误的示例

```
dict ['key'] = 1st [index]
```

- 当运算符（如赋值运算符）周围有多个空格，且为了与其他运算符对齐时：

### 良好的示例

```
x = 1
y = 2
long_variable = 3
```

### 错误的示例

```
x = 1
y = 2
long_variable = 3
```

## 其他建议

避免在代码中出现行尾空格，因为它是不可见的且可能导致混淆。例如，如果你输入了一个反斜杠，后面跟着一个空格然后换行——这不会被视为换行延续符。事实上，某些文本编辑器不会保留它，而且有些项目包含 `pre-commit` 钩子，会直接拒绝它——其中之一就是 CPython。

以下二进制运算符应被单个空格包围（两侧各一个）：

- 赋值 (`=`)
- 复合赋值 (`+=`, `-=` 等)

以下比较运算符的处理方式相同：

- `==`
- `<`
- `!=`
- `<>`
- `>=`
- `in`
- `not in`
- `is`
- `is not`

以及这些布尔值：

- `and`
- `or`
- `not`

如果你使用的运算符优先级不同，请考虑在优先级最低的运算符周围添加空格——在此处根据你的最佳判断。然而，你不应使用超过一个空格，并确保运算符的两侧空格数量相同——不要在一侧放 1 个而在另一侧放 2 个：

### 良好的示例

```
i = i + 1
submitted += 1
x = x*2 - 1
hypot2 = x*x + y*y
c = (a+b) * (a-b)
```

### 错误的示例



```
i = i + 1
submitted += 1
x = x * 2 - 1
hypot2 = x * x + y * y
c = (a + b) * (a - b)
```

当你使用 `=` 符号表示参数或关键字参数的默认值时，不要在符号周围使用空格：

### 良好的示例

```python
def complex(real, imag=0.0):
    return magic(r=real, i=imag)
```

### 错误的示例

```python
def complex(real, imag = 0.0):
    return magic(r = real, i = imag)
```

带有函数注解的冒号请使用标准规则，并确保有空格
