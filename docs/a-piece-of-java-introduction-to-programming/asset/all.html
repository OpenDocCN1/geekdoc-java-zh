Chapter 0: Welcome to Java
Welcome to learning how to program in Java! This book is meant for beginners in programming, so congratulations on starting your journey.
There’s many code examples provided, so I highly recommend you type along with the code and refrain from copying and pasting. We want to build the muscle memory in your typing to get comfortable with writing in Java.
There’s so much to learn, and I am no expert myself. I have struggled in my college years learning Java, and I hope to pass on some of my knowledge so that you don’t struggle as much as I did.
This book will not go over the nitty gritty technicals of how Java works at a machine level but just enough information to get you coding.
What is Java?
Java is a programming language first created by Sun MicroSystems in the 1990s, then later acquired by Oracle Corporation in the 2000s. Java is used to create desktop applications, web applications, and even apps for mobile devices, so it’s pretty versatile in use.
Java is a great language to learn to build your foundation in programming, specifically in object oriented programming. I believe when you learn Java, you're able to pick up on other languages pretty quickly since the OOP principles stay consistent. So Java is a nice transferable skill to have.

Section 2.4: Summary
Let’s summarize some “rules of thumb” for reading and writing in Java.
●      Code is run line-by-line. So the order of the code you write matters. You can’t write the print statement before writing our class container.
●           Anytime you create a new Java file, you must have the big container called “class.”
○           This rule of thumb will change as you advance in Java beyond this book.
●           Your class name must match the name of your file.
●          In order to execute your program on the  command window, you must always have the main() method.
●     Anytime you see ( ) in your code, it’s usually a method.
○      Exceptions to this rule: conditional statements, loops, math calculations. We’ll explore these in this book.
●      Anything between the curly braces { } is called a body . This is where we write executable code.
●     When you write “Java sentences,” or statements, they usually end with a semicolon. Semicolons are the period of the Java sentences.
●      When you compile your code, it’s javac <Name of File>.java
●           When you run your code, it’s java <Name of File>
●           You have to compile your code before running it.
●           We will be using // or /* */   to write comments.

●   Objects can access things that belong to the class. This is because static values do not change based on objects.

●           Do I know the value of this variable before creating an object for it?
●          If I want to change the value of a variable, do I want to apply this change for all objects, or should the change be object-specific?

In the long run, there was no special reason, but I recommend using instance methods rather than static methods from hereon when possible.

Chapter 19: == vs. equals()
We’ve learned how to compare the equality of two numbers using the == operator from Chapters 4 and 7.
We mostly used == to check the equality of two numbers. Note that you can use == to check the equality of any two primitive values .
But what if we wanted to compare two objects instead?
For objects:
●        If you want to compare the memory location of two objects, you use ==
●      If you want to compare the values held by the two objects, you use equals()
The equals() method exists on all objects, but we’ll focus on how to use equals() with Strings.
