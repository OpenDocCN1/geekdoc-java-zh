# OOPS（面向对象编程）

## 1: OOPS 的核心概念是什么？

回答：

面向对象的设计和编程基于四个核心概念。它们是：

- a) 抽象 (Abstraction)
- b) 多态 (Polymorphism)
- c) 继承 (Inheritance)
- d) 封装 (Encapsulation)

（即易记为 A-PIE）。

## 2: 什么是抽象（Abstraction）？

回答：

抽象是指表示本质特征而不包含背景细节或解释。

## 3: 什么是封装（Encapsulation）？

回答：

封装是一种用于隐藏对象属性和行为的技术，并仅在适当的情况下允许外部访问。它防止其他对象直接修改或访问被封装对象的属性或方法。

## 4: 抽象和封装之间的区别是什么？

回答：

抽象关注对象的外部视图（即接口）。封装（信息隐藏）防止客户端看到其内部视图/抽象行为实现的地方。抽象解决的是设计方面的问题，而封装是实现：封装是抽象的交付物。封装很少讨论为了适应开发人员需求对抽象进行分组。

## 5: 什么是继承（Inheritance）？

回答：

继承是一个类的对象获取另一个类的对象的属性的过程。被继承的类称为父类（superclass）。继承的类称为子类（subclass）。继承使用`extends`关键字。

使用继承的最常见原因有两个：

- a) 促进代码复用
- b) 使用多态

## 6: 什么是多态（Polymorphism）？

回答：

多态可以简述为“一种接口，多种实现”。多态是一种在不同语境下为某物赋予不同含义或用的特征——具体来说，允许变量、函数或对象等实体具有多种形式。

## 7: Java 如何实现多态？

回答：

通过继承、重载（Overloading）和重写（Overriding）在 Java 中实现多态。多态在 Java 中表现为具有相同名的多个方法。

在某些情况下，多个方法具有相同名称但参数列表不同（重载）。在其他情况下，多个方法具有相同名称、返回类型和相同的参数列表（重写）。

## 8: 解释多态的不同形式。

回答：

多态有两种类型，一种是编译时多态（Compile time polymorphism），另一种是运行时多态（run time polymorphism）。编译时多态是方法重载。运行时多态是通过继承实现的。

## 9: 什么是运行时多态或动态派发（dynamic dispatch）？

回答：

在 Java 中，运行时多态或动态派发是指重写方法的调用在运行时而不是编译时解析的过程。在此过程中，重写方法是通过引用变量调用的。

## 10: 什么是动态绑定（Dynamic Binding）？

回答：

绑定是将过程调用与响应调用的代码链接起来。动态绑定（也称为后期绑定）意味着与给定过程调用相关的代码在调用时是未知的。它与多态和继承相关。

## 11: 什么是方法重载（method overloading）？

回答：

方法重载是指在同一个类中具有相同名称但参数不同的多个方法。方法重载的好处是允许实现相同操作但参数数量或类型不同的方法。

### 注意

- a) 重载方法必须更改参数列表。
- b) 重载方法可以更改返回类型。
- c) 重载方法可以更改访问修饰符。
- d) 重载方法可以声明新的或更宽的异常。
- e) 方法可以在同类或子类中重载。

## 12: 什么是方法重写（method overriding）？

回答：

方法重写发生在子类声明了一个与其父类声明的方法具有相同类型参数的方法。重写的关键优势是能够定义特定特定子类类型的行为。

注意：重写方法的访问修饰符不能比被重写的方法更严格（你不能将标记为`public`的方法重写为`protected`）。你不能重写标记为`final`的方法。你不能重写标记为`static`的方法。

## 13: 方法重载和方法重写的区别是什么？

回答：

|  | 重载方法 (Overloaded) | 重写方法 (Overridden) |
| --- | --- | --- |
| 参数 | 必须更改 | 不能更改 |
| 返回类型 | 可以更改 | 除协变返回外不能更改 |
| 异常 | 可以更改 | 可以减少或消除。不能抛出新的或更宽的检查异常 |
| 访问 | 可以更改 | 不能变得更严格（可以更松） |
| 调用 | 引用类型决定选择哪个重载版本。在编译时完成。 | 对象类型决定选择哪种方法。在运行时完成。 |

## 14: 重载方法也可以被重写吗？

答案：

是的，派生类仍然可以重写重载的方法。多态仍然可以发生。编译器不会绑定方法调用，因为它是重载的，因为该方法现在或将来可能被重写。

## 15: 可以重写`main`方法吗？

答案：

不可以，因为`main`是一个静态方法（Static method）。在 Java 中，静态方法不能被重写。

## 16: 如何调用被重写方法的父类版本？

答案：

要调用在子类中被重写的父类方法，你必须直接通过父类实例调用该方法，或者在子类中使用`super`前缀。从子类的角度来看，`super`前缀提供了对父类该方法实现的显式引用。

```java
// 在子类中
super.overriddenMethod();
```

## 17: 什么是 Super？

答案：

Super 是用于访问父类方法或成员变量的关键字。如果方法隐藏了其父类中的某个成员变量，该方法可以通过`super`关键字引用被隐藏的变量。同样，如果一个方法重写了其父类中的某个方法，该方法可以通过`super`关键字调用被重写的方法。

注意：你只能回溯一级。在构造函数中使用`super()`，它必须是第一行代码，且你不能访问任何`this.xxx`变量或方法来计算它的参数。

## 18: 如何防止方法被重写？

答案：

为了防止特定方法在子类中被重写，在方法声明上使用`final`修饰符，这意味着“这是该方法的最终实现”，即其继承层次的终点。

```java
public final void exampleMethod() {
  // 方法语句
}
```

## 19: 什么是接口（Interface）？

答案：

接口是对实现类必须遵守的一组方法定义的描述。

注意：

- a) 你不能将接口标记为`final`。
- b) 接口变量必须是静态的（Static）。
- c) 接口不能扩展除其他接口以外的任何内容。

## 20: 我们可以实例化接口吗？

答案：

你不能直接实例化接口，但你可以实例化实现接口的类。

## 21: 我们可以为接口创建对象吗？

答案：

是的，总是必须为接口创建一个对象实现。接口本身无法实例化，因此你必须编写一个实现接口的类并履行其中定义的所有方法。

## 22: 接口有成员变量吗？

答案：

接口可以有成员变量，但这些变量是隐式的公共（public）、静态（Static）且最终的（final）。换句话说，接口只能声明常量，而不能声明所有实现都可用的实例变量（例如可以作为方法参数的关键引用）。

## 23: 接口中的方法允许哪些修饰符？

答案：

接口方法只允许使用公共（public）和抽象（abstract）修饰符。

## 24: 什么是标记接口（Marker interface）？

答案：

标记接口是不声明任何所需方法的接口，但表示它们与某些操作的兼容性。`java.io.Serializable`接口和`Cloneable`是典型的标记接口。它们不包含任何方法，但类必须实现这些接口才能被序列化。

## 25: 什么是抽象类（Abstract class）？

答案：

抽象类是包含一个或多个抽象方法的类。抽象方法是声明了但没有包含实现的方法。

注意：

- a) 即使只有一个方法是抽象的，整个类也必须声明为抽象的。
- b) 抽象类不能实例化，并要求子类为抽象方法提供实现。
- c) 你不能将一个类同时标记为抽象和`final`。

## 26: 我们可以实例化抽象类吗？

答案：

抽象类不能被实例化。它的唯一目的是被扩展。

## 27: 抽象类和接口的区别是什么？

答案：

| 抽象类 | 接口 |
| --- | --- |
| 抽象类可以提供完整的实现 | 接口只需要签名 |
| 抽象类只能继承一个 | 接口可以实现多个 |
| 抽象类可以非抽象方法 | 接口的方法都是抽象的 |
| 抽象类可以拥有成员变量 | 接口没有成员变量 |
| 抽象类可以具有任何可见性（public/private/protected） | 接口的可见性必须是公共的（public） |
| 如果在抽象类中添加新方法，可以选择实现 | 如果在接口中添加新方法，则没有 |
| 抽象类可以包含构造函数 | 接口不能包含构造函数 |
| 抽象类是快速的 | 接口是缓慢的 |

## 28: 什么时候应该使用抽象类，什么时候应该使用接口？

答案：

使用接口当：

- a) 设计会频繁变化时。如果各种实现共享签名，使用接口更好。
- b) 当你需要实现定义的方法时。

使用抽象类当：

- a) 如果各种实现是相同的，使用抽象类更好。
- b) 当你想提供通用的形式供类继承时。
- c) 抽象类是创建层次结构的极佳方式，也是叶子类的良好选择。

## 29: 当你将方法声明为抽象时，其他抽象方法可以访问它吗？

答案：是的，其他抽象方法可以访问你声明为抽象的方法。

## 30: 可以存在没有方法的抽象类吗？

答案：是的，可以存在没有方法的抽象类。

## 31: 什么是构造函数（Constructor）？

答案：构造函数是一种用于初始化对象的特殊方法。它的特殊之处在于名称与类名相同。它们没有返回类型，甚至没有`void`，因此不能返回值。它们不能被继承，尽管派生类可以调用基类的构造函数。当创建关联类的对象时，构造函数就会被调用。

## 32: 什么是默认构造函数？

答案：如果代码定义的类没有任何构造函数，编译器会自动为类提供一个无参数构造函数（默认构造函数）。默认构造函数的访问修饰符（public/private 等）与类本身相同。

## 33: 构造函数可以被继承吗？

答案：不可以，构造函数不能被继承，尽管派生类可以调用基类的构造函数。

## 34: 构造函数和方法的区别是什么？

答案：

| 构造函数 | 方法 |
| --- | --- |
| 创建类的实例 | 分组 Java 语句 |
| 修饰符 | 不能是抽象、最终、原生、静态或同步 | 可以是抽象、最终、原生、静态或同步 |
| 返回类型 | 无返回类型，甚至没有 void | void 或有效的返回类型 |
| 名称 | 与类名相同（约定首字母大写）——通常是名词 | 类以外的任何名称。方法名以小字母开头——通常是动作名称 |
| this | 指向同一类中的另一个构造函数。如果使用，它必须是构造函数的第一行 | 指向所属类的实例。不能在静态方法中使用 |

## 35: this() 和 super() 如何在构造函数中使用？

答案：

构造函数使用`this`来引用同一类中具有不同参数列表的另一个构造函数。构造函数使用`super`来调用父类的构造函数。如果构造函数使用了`super`，它必须在第一行使用；否则编译器会报错。

## 36: 类方法（Class Methods）和实例方法（Instance Methods）的区别是什么？

答案：

| 类方法 | 实例方法 |
| :--- | :--- |
| 类方法是声明为`Static`的方法。 | 另一方面，实例方法在调用之前需要类的实例存在， |
| 无需创建实例即可调用该方法 | 因此需要使用`new`关键字创建类的实例。实例方法在特定的类实例上操作。 |
| 类方法只能操作类成员而不能操作实例成员，因为类方法无法感知实例成员。 | 类实例方法也无法从类方法内部调用，除非它们是在该类的实例上调用的。 |
| 类方法是声明为`Static`的方法。无需创建实例即可调用该方法。 | 实例方法没有声明为`Static` |

## 37: 什么是 classpath？

答案：

Classpath 是 Java 在运行时和编译时查找类的路径。

## 38: 什么是访问修饰符（Access Specifiers）？

答案：

面向对象编程封装技术的一种。它涉及类中数据的隐藏，并使该类仅通过方法可用。Java 允许你通过所谓的访问修饰符控制对类、方法和字段的访问。

## 39: 列出 Java 中提供的访问修饰符？

答案：

Java 提供了四种访问修饰符，按权限从高到低列出：

- Public - 公有类、方法和字段可以从任何访问。
- Protected - 受保护的方法和字段只能在所属的类内部、其子类中以及相同包的类中访问。
- Default（无修饰符） - 如果你没有设置特定的访问级别，则该类、方法或字段可以从该类、方法或字段所属的包内部访问，但不能从包外部访问。
- Private - 私有方法和字段只能在所属的类内部访问。私有方法和字段在子类中不可见，也不会被子类继承。详情见下表。

| 情况 | Public | Protected | Default | Private |
| :--- | :--- | :--- | :--- | :--- |
| 同包类类可访问吗？ | 是 | 是 | 是 | 否 |
| 不同包类可访问吗？ | 是 | 否，除非是子类 | 否 | 否 |

## 40: 什么是 final 修饰符？

答案：

`final`修饰符确保程序员不能再次更改值。具体含义取决于应用于类、变量还是方法。

- final 类 - `final`类不能有子类。
- final 变量 - `final`变量一旦初始化就无法更改。
- final 方法 - `final`方法不能被子类重写。

## 41: final 方法的作用是什么？

答案：

将方法标记为`final`有两个原因：

- a) 禁止子类更改方法的含义。
- b) 通过允许编译器将对方法的调用内联（inline）Java 代码来提高效率。

## 42: 什么是静态块（Static block）？

答案：

静态块在类加载到 JVM 时精确执行一次。在进入`main`方法之前，静态块将先执行。

## 43: 什么是静态变量（Static variables）？

答案：

每个类只有一个副本的变量被称为静态变量。它们不属于类的特定实例，而是属于整个类。

它们通过使用`Static`关键字作为修饰符进行声明。

```java
Static type varIdentifier;
```

其中，变量名为`varIdentifier`，其数据类型由`type`指定。

**注意：** 代码中未被显式初始化的静态变量将自动用默认值初始化。

默认值取决于变量的数据类型。

## 44: 静态变量和非静态变量有什么区别？

**答案：**

静态变量与整个类相关，而不是类的特定实例相关。非静态变量在每个对象实例上都有独特的值。

## 45: 什么是静态方法（Static methods）？

答案：

使用`Static`关键字作为修饰符的方法称为静态方法或类方法。它们之所以被称为静态方法是因为它们影响整个类，而不是类的特定实例。静态方法始终在不引用类特定实例的情况下被调用。

注意：使用静态方法受到以下限制：

- a) 静态方法只能调用其他静态方法。
- b) 静态方法只能访问静态数据。
- c) 静态方法不能使用`super`或`this`关键字引用当前对象。

# JAVA 集合 (COLLECTION)

## 46: 什么是迭代器（Iterator）？

答案：

`Iterator`接口用于遍历集合（Collection）中的元素。迭代器允许你处理集合中的每个元素。

迭代器遍历集合所有元素的通用方式，无论它是如何组织的。`Iterator`是一个接口。

## 47: 如何使用 Iterator 遍历集合？

答案：

使用迭代器遍历集合内容请遵循以下步骤：

- a) 调用集合的`iterator()`方法获取从开始的迭代器。
- b) 设置一个循环，只要`hasNext()`返回`true`就继续循环。
- c) 在循环内部，通过调用`next()`获取每个元素。

## 48: 在迭代过程中如何删除元素？

答案：

迭代器也有`remove()`方法，调用`remove`时，当前的迭代元素会被删除。

## 49: Enumeration 和 Iterator 的区别是什么？

答案：



| Enumeration | Iterator |
| :--- | :--- |
| Enumeration 没有 `remove()` 方法 | Iterator 有 `remove()` 方法 |
| Enumeration 充当只读接口，因为它只有遍历和获取对象的方法 |  |

## 50：什么是 `ListIterator`？

答案：

`ListIterator` 与 `Iterator` 类似，但它允许我们向前或向后访问集合，并允许我们修改元素。

## 51：什么是 `List` 接口？

答案：

`List` 接口为有序集合提供了支持。`List` 可以包含重复元素。

## 52：`List` 接口的主要实现有哪些？

答案：

`List` 接口的主要实现如下：

- `ArrayList`：`List` 接口的可调整数组实现，是 `List` 接口最好的通用实现。
- `Vector`：同步的可调整数组实现，带有额外的“遗留方法”。
- `LinkedList`：`List` 接口的双向链表实现。如果在列表中频繁插入或删除元素，性能可能比 `ArrayList` 实现更好。适用于队列和双端队列（deques）。

## 53：`ArrayList` 相比数组有哪些优势？

答案：

`ArrayList` 相比数组的某些优势是：

- a) 它可以动态增长。
- b) 它提供了比数组强大的插入和搜索机制。

## 54：`ArrayList` 和 `Vector` 的区别？

答案：

| `ArrayList` | `Vector` |
| :--- | :--- |
| `ArrayList` 默认不同步。 | `Vector` 列表默认是同步的。 |
| `ArrayList` 只能使用 `Iterator` 访问元素。 | `Vector` 列表可以使用 `Iterator` 和 `Enumeration` 接口访问元素。 |
| `ArrayList` 在空间不足时将其数组大小增加 50%。 | `Vector` 在空间不足时默认将其数组大小翻倍。 |

## 55：如何从 `ArrayList` 获取数组？

```

## 56：为什么与 `LinkedList` 相比，`ArrayList` 的插入和删除较慢？

答案：

`ArrayList` 内部使用数组来存储元素，当数组通过插入元素被填满时，会创建一个大小大约为原数组 1.5 倍的新数组，并将旧数组的所有数据复制到新数组中。在删除时，数组中被删除元素之后的所有元素都必须向前移动一步，以填充删除操作留空间。

在链表中，数据存储在节点中，节点包含指向上一个节点和下一个节点的引用，因此添加元素非常简单，只需创建节点并更新上一个节点的 `next` 指针以及新节点的 `previous` 指针即可。

链表的删除操作非常快，因为它只需要更新被删除节点之前节点的 `next` 指针以及被删除节点之后节点的 `previous` 指针。

## 57：为什么 `ArrayList` 返回的迭代器被称为 Fail Fast（快速失败）？

答案：

因为如果在创建迭代器后，以任何通过迭代器自身的 `remove` 或 `add` 方法以外的方式对列表进行结构性修改，迭代器将抛出 `ConcurrentModificationException`。因此，在面对并发修改时，迭代器会快速且干净地失败，而不是在未来的某个不确定时间面临任意的、非确定性行为的风险。

## 58：你如何决定何时使用 `ArrayList`，何时使用 `LinkedList`？

## 59：什么是 `Set` 接口？

## 76：什么是 `Comparable` 接口？

```

## 78：Observer（观察者）和 Observable（观察对象）是如何使用的？

## 79：什么是同步（Synchronization）？

同步是控制多个线程访问共享资源的能力。同步停止多线程并发。通过同步，同一时间只有一个线程能够访问共享资源。

## 80：`yield()` 和 `sleep()` 之间有什么区别？

答案：

当一个对象调用 `yield()` 时，它会返回就绪状态（ready state）。但当一个对象调用 `sleep()` 方法时，会进入非就绪状态（not ready state）。

## 81：我们可以调用 `finalize()` 方法吗？

答案：

可以。如果某个方法在我们的类中是可访问的，没有人能阻止调用它。但如果一个对象是可达的（reachable），垃圾收集器就不会调用该对象的 `finalize` 方法。

## 82：时间分片（time slicing）和抢占式调度（preemptive scheduling）之间有什么区别？

答案：

在抢占式调度中，高优先级任务继续执行，直到它进入非运行状态（not running state）或出现更高优先级的任务。在时间分片中，任务执行预定义的一段时间，然后重新进入就绪任务池。

## 83：`&` 运算符与 `&&` 运算符之间有什么区别？

答案：

当评估包含 `&` 运算符的表达式时，两个操作数都会被评估，并且 `&` 运算符被应用于这两个操作数。

当评估包含 `&&` 运算符的表达式时，会评估第一个操作数。只有当第一个操作数返回 `true` 时，才会评估第二个操作数，否则第二部分将不会执行。`&&` 也称为短路（short cut）。

## 84：抽象类（abstract class）和接口（interface）之间有什么区别？

## 85：同步块（synchronized block）和同步方法（synchronized method）之间有什么区别？

# 128：线程和进程有什么区别？

**答案：**

进程运行在自己的地址空间中。线程共享拥有它们的进程的地址空间。

# 129：`Vector` 和 `ArrayList` 有什么区别？

**答案：**

`Vector` 是同步的，`ArrayList` 不是。`Vector` 有指定初始容量的构造函数，而 `ArrayList` 没有。默认情况下 `Vector` 增长 100%，而 `ArrayList` 增长 50%。

# 130：`Hashtable` 和 `HashMap` 有什么区别？

**答案：**

`Hashtable` 是同步的，`HashMap` 不是。`Hashtable` 不允许空值，但 `HashMap` 允许空值。

# 131：Java 中有哪些访问修饰符？

**答案：**

访问修饰符指定了方法或属性可以使用的范围。`public` 处处可用。`protected` 在同类及其子类中可用。包默认在同包内可用。`private` 仅在类内部可用。

# 132：为什么说 Java 是值传递（pass-by-value）？

**答案：**

将对象赋值给变量时，我们实际上是将对象的内存地址赋值给变量。因此，传递的值实际上是内存位置。这导致了对象引用，意味着多个变量可以引用同一个对象。

# 133：什么是不可变（immutable）？如何创建不可变对象？

**答案：**

不可变意味着对象在初始化后无法被修改。不可变类中不会有 setter 方法。通常这些类是 `final` 的。

# 134：Java 中的类加载器（class loader）是什么？

**答案：**

类加载器是负责加载类的类。所有 JVM 都包含一个原始类加载器（Primordial class loader）。

# 135：什么是弱引用（weak reference）？

**答案：**

弱引用是指防止引用对象被垃圾回收的引用。弱引用不会保持它所引用的对象存活。弱引用在垃圾回收中不被视为引用。这将使用内存更加有效。

# 136：什么是对象克隆（object cloning）？

**答案：**

这是一个复制对象的过程，使得两个相同的对象同时存在内存中。

# 137：什么是对象池？

**答案：**

创建大量相同的短生命周期对象被称为对象池。这有助于减少对垃圾回收的需求，并使内存使用更高效。

# 138：什么是垃圾回收？

**答案：**

垃圾回收是释放未引用对象所用内存的过程。它让程序员从手动释放对象使用的内存的过程中解放出来。

# 139：垃圾回收的缺点是什么？

**答案：**

它会增加影响性能的开销。

此外，无法保证对象一定会被垃圾回收。

# 140：什么是 JAR 文件？

**答案：**

JAR 代表 Java Archive（Java 归档）。这是一种允许将多个文件封装到一个归档文件中的格式。JAR 文件在 `META-INF` 文件夹中包含一个 `manifest.mf` 文件，用于描述 JAR 文件的版本和其他特性。

# 141：什么是静态初始化块？它有什么用？

**答案：**

静态初始化块是一个使用 `static` 关键字声明的代码块。它通常包含在类加载时必须执行的代码。静态初始化块仅在类加载时执行一次。

# 142：什么是标记接口？请举一些例子。

**答案：**

标记接口不包含任何方法。它仅用于标记支持某些能力的 Java 类。

例如：`Serializable`、`Cloneable`、`SingleThreadModel` 等。

# 143：什么是标签接口（Tag interfaces）？

**答案：**

标签接口是标记接口的另一种名称。

# 144：静态方法有哪些限制？

**答案：**

我们不能重写静态方法。我们不能在静态方法内部访问任何对象变量。此外，静态方法中无法使用 `this` 引用。

# 145：什么是 JVM？

**答案：**

JVM 代表 Java Virtual Machine（Java 虚拟机）。它是 Java 程序的运行时。所有 Java 程序都运行在这个 JVM 内部。它将 Java 字节码转换为特定于操作系统的指令。除了管理应用程序字节码的执行外，虚拟机还处理相关任务，如管理系统内存、提供针对恶意代码的安全以及管理程序执行的多个线程。

# 146：什么是 JIT？

**答案：**

JIT 代表 Just In Time compiler（即时编译器）。它将 Java 字节码编译为原生代码。

# 147：什么是方法重载？

**答案：**

方法重载是创建一个具有相同名称但不同签名的新方法的过程。

# 148：什么是方法重写？

**答案：**

方法重写是在子类中为现有方法提供新定义的过程。

# 149：`finalize()` 是什么？

**答案：**

`finalize()` 是 Java 中的一个保护方法。当垃圾回收器执行时，它会首先调用 `finalize()`，并在下一次垃圾回收时回收对象的内存。因此，`finalize()` 为你提供了在垃圾回收时执行某些清理操作的机会。

# 150：什么是多线程？

**答案：**

多线程是指多个线程同时运行的场景。

# 151：什么是死锁？

**答案：**

死锁是指两个线程等待对方释放资源的情况。每个线程都在等待另一个等待线程所持有的资源。

# 152：`Iterator`（迭代器）和 `Enumeration`（枚举）之间的区别是什么？

**答案：**

`Enumeration` 的速度是 `Iterator` 的两倍，且使用的内存非常少。`Enumeration` 非常基础，适合基本需求，但与 `Enumeration` 相比，`Iterator` 安全得多，因为它会检测其他线程修改集合对象的情况。每当第二个线程尝试这样做时，`Iterator` 都会抛出 `ConcurrentModificationException`。具有这种机制的迭代器被称为“快速失败”（fail-fast）迭代器，因为它们会快速且干净地失败。

`Enumeration` 用于遍历给定的集合（通常是未知大小的）。`Enumeration` 不允许对集合进行修改，而修改可以通过 `Iterator` 实现。

`Iterator` 的 `remove()` 方法从底层集合中删除由迭代器返回的最后一个元素。该方法在每次调用 `Iterator` 的 `next()` 方法后，只能被调用一次。

# 153：什么是国际化？

**答案：**

国际化是设计应用程序的过程，使其能够在不更改代码的情况下适应各种语言和地区。

# 154：`URL` 和 `URLConnection` 之间的区别是什么？

**答案：**

`URL` 代表资源的位置，而 `URLConnection` 代表访问或与该位置的资源进行通信的链接。

# 155：有哪两个重要的 TCP Socket 类？

**答案：**

- a) `ServerSocket`
- b) `Socket`

`ServerSocket` 有用于双向 socket 通信。

`Socket` 类帮助我们通过 socket 进行读写操作。

`getInputStream()` 和 `getOutputStream()` 是 `Socket` 类中提供的两个方法。

# 人力资源问题（HR Questions）

回顾这些典型的面试问题并思考你将如何回答。阅读列出的答案；你将找到最佳答案以及策略和建议。

本页特意留白。

## 1：请介绍一下你自己？

**答案：**

最常被问的问题。你需要脑中准备一段简短的陈述。将其限制在一到两分钟内。注意听起来不要像背出来的。从最远的过去开始，一直讲到现在。

## 2：你为什么要离开上一份工作？

**答案：**

无论情况如何，都要保持积极。永远不要提到管理层的问题，也不要贬低主管或同事。

## 3：你在这一领域有什么经验？

**答案：**

谈论与你申请的职位相关的具体内容。如果你没有特定经验，尽可能贴近。

## 4：你认为自己是成功的吗？

**答案：**

你应该总是回答是，并简要解释原因。一个很好的解释是你设定了目标，并且实现了一些，并且正在朝着其他目标努力。

## 5：同事如何评价你？

**答案：**

准备好一或两个来自同事的评价。无论是具体的陈述还是转述都可以。Clarke 公司的同事 Bill Smith 一直说我是见过的最努力的人。

## 6：你对这个机构了解多少？

**答案：**

这个问题是你在面试前对机构进行研究的原因之一。研究公司的产品、规模、声誉、形象、目标、问题、管理风格、技能、历史和哲学。保持了解并感兴趣。了解他们过去在哪里，未来将走向哪里。目前有哪些问题，主要参与者是谁？

## 7：去年你是如何提高知识的？

**答案：**

尽量包括与工作相关的改进活动。可以提到各种类型的活动作为积极的自我提升。准备一些好的例子可以提到。

## 8：你在申请其他工作吗？

**答案：**

要诚实，但不要在这个上花费太多时间。将重点集中在这份工作以及你能为这个机构做什么上。其他任何事情都是干扰。

## 9：你为什么想在这个机构工作？

**答案：**

这可能需要一些思考，并且显然应该基于你对机构的研究。诚意在这里极其重要，并且很容易被察觉。将其与你的长期职业目标联系起来。永远不要谈论你；先谈论他们的需求。你想加入一家充满活力、向前发展的公司。你可以为特定公司做出明确的贡献。

目标。

## 10：你认识任何在我们公司工作的人吗？

**答案：**

请注意关于亲属在机构工作的政策。即使他们问及的是朋友而非亲属，这也会影响你的回答。只有当某个朋友评价很高时，才谨慎提到。

## 11：你需要什么样的薪水？

**答案：**

一个陷阱题！如果你先回答，很可能会输掉这场卑劣的游戏。所以，不要回答它。相反，可以说类似：“这是一个很难的问题。您能告诉我这个职位的薪资范围吗？”在大多数情况下，面试官会措手不及，会告诉你。如果没有，就说这取决于工作的细节。然后给出一个宽泛的范围。

## 12：你有团队合作精神吗？

**答案：**

你当然有团队合作精神。务必准备好例子。具体的细节，展示你经常为了团队利益而非个人利益表现，这是你团队态度的良好证明。不要吹嘘；用平实的语气陈述即可。这是一个关键点。

## 13：如果被录用，你预计在我们这里工作多久？

**答案：**

在这里给出具体的细节并不好。这样回答应该可以：“我希望是很长时间，”或者“只要我们都觉得我工作得很好。”

## 14：你曾经不得不辞雇过任何人吗？你对此感觉如何？

**答案：**

这很严肃。不要轻视它，也不要以任何方式表现出你喜欢开除人。同时，在认为这样做是必要的时候你会这样做。当涉及到组织与制造有害局面的个人之间时，你会保护组织。记住，辞雇不等同于裁员或人员缩减。

## 15：你的工作哲学是什么？

**答案：**

面试官在这里并不是在寻找长篇或华丽的论文。你是否对完成工作有强烈的信念？是的。这种类型的回答在这里效果最好。保持简洁和积极，展示对机构的益处。

## 16：如果现在有足够的钱退休，你会这么做吗？

**答案：**

如果你愿意，就回答愿意。但由于你需要工作，这是你偏好的工作类型。如果不是真心话，不要说是。

## 17：你曾经被要求离开某个职位吗？

**答案：**

如果没有过，就说没有。如果有过，要诚实、简洁，并避免对涉及的人员或机构说负面话。

## 18：解释你将如何成为这个机构的财富。

**答案：**

你应该对这个问题充满期待。它给了你一个机会来突出你与所讨论职位相关的最佳优势。对这种关系做些提前思考。

## 19：为什么我们应该聘用你？

**答案：**

指出你的优势如何满足机构的需求。还应提到你的知识、经验、能力和技能。永远不要为了比较而提到任何其他候选人。

## 20：告诉我一个你提过的建议。

**答案：**

准备一个好的例子。务必使用一个被采纳并随后被认为是成功的建议。与所申请的工作类型相关的将是极大的加分项。

## 21：同事有什么事让你感到烦恼？

**答案：**

这是一个陷阱题。努力思考，但要想不出任何让你烦恼的事情。简短地陈述你和大家相处得很好，这样非常好。

## 22：你最大的优势是什么？

**答案：**

很多答案都是好的，只要保持积极即可。几个好的例子：

- 你的任务优先排序的能力
- 你的解决问题能力
- 你在压力下工作的能力
- 你专注于项目的能力
- 你的专业知识
- 你的领导能力
- 你的积极态度

## 23：告诉我你的理想工作是什么，或者你在工作中寻找什么？

**答案：**

避开具体的职位。你是赢不了的。如果你说你正在竞争的这个职位就是理想工作，就会损害信誉。如果你说另一个职位才是理想工作，你就会种下你入职后会对这个职位不满的怀疑。最好的办法是保持泛泛并说类似的话：“一份热爱工作、喜欢那里的人、可以做出贡献并迫不及待开始工作的工作。”

## 24：为什么你认为你在这个工作中会表现良好？

**答案：**

给出几个理由，包括技能、经验和兴趣。

## 25：你觉得这个职位最吸引你的地方是什么？（最不吸引的是？）

**答案：**

- a) 列出几个吸引因素，例如该职位提供的责任，以及与具有创新和创造力声誉的经验团队合作的机会。
- b) 说在对任何不吸引人的方面做出判断之前，你需要更多信息和时间。

## 26：你拒绝与什么样的人共事？

**答案：**

不要太琐碎。只有对组织不忠诚、暴力或违法才会让你产生反对。微小的反对会将你贴上抱怨者的标签。

## 27：对你来说，什么更重要：金钱还是工作？

**答案：**

金钱总是重要的，但工作是最重要的。没有更好的答案了。

## 28：你之前的上司会说你最强的一点是什么？

**答案：**

有许多可能性：

- 忠诚
- 精力
- 积极态度
- 领导力
- 团队合作精神
- 专家知识
- 耐心
- 勤奋
- 创造力

## 29：告诉我你与上司发生的一个问题。

**答案：**

这是一个陷阱题！这是为了测试你是否会诋毁老板。



## 30：工作中什么让你感到失望？

### 回答

不要变得负面。安全的领域很少：

- a) 挑战性不足
- b) 你被裁员了，那本可以给你更多责任。

## 31：告诉我你在压力下工作的能力。

### 回答

你可以说你在某些类型的压力下表现出色。给出一个与申请的工作类型相关的例子。

## 32：你的技能与这个职位匹配得吗？

### 回答

可能吧。不要助长你可能更想要其他工作的怀疑。

## 33：是什么激励你在工作中尽尽全力？

### 回答

这是一个只有你能说的个人特质，但好的例子有：

- 挑战
- 成就
- 认可

## 34：你愿意加班吗？晚上？周末？

### 回答

这取决于你。要完全诚实。

## 35：你如何知道在这个工作中是成功的？

### 回答

几种方式都是好的：

- 你对自己设定了高标准并达到了它们。
- 你的结果是成功的。
- 你的老板告诉你你是成功的，做得非常好。

## 36：如果需要，你愿意搬迁吗？

### 回答

如果你认为这有可能，你应该在面试前就和家人明确这一点。如果真实答案是否，不要为了得到工作而说是。这会在你职业生涯后期产生很多问题。在这一点上要诚实。这将为你避免未来的痛苦。

## 37：你愿意将机构的利益放在个人利益之前吗？

### 回答

这是一个关于忠诚和奉献的问题。不要担心深层的伦理和哲学含义。直接说愿意。

## 38：描述你的管理风格。

### 回答

尽量避免标签。一些更常见的标签，如进步型、销售型或共识型，根据你听哪个管理专家的，可能有多种含义或描述。情境风格是安全的，因为它表示你会根据情况进行管理，而不是一刀切。

## 39：你从工作中的错误中学了什么？

### 回答

在这里你必须想出点什么，否则会损害信誉。让一个小小的、意良好的错误，并获得一个积极的教训。例子可以是，在项目中比同事进展得早，从而影响了协调。

陷阱题！如果你已经了解了盲点，那么它们就不再是盲点了。在这里不要透露任何你个人关注的领域。让他们自己去发现你的缺点。不要把主动权交给他们。

## 41：如果你正在为这份工作招聘人员，你会寻找什么？

### 回答

注意提到所需的特质以及你所具备的特质。

### 回答

### 回答

## 47：描述你的工作准则。

### 回答

始终要准备一些问题。准备那些能让你成为组织资产的问题是好的。我多久可以开始发挥作用？我能协助哪些项目？
